# Файловые промты AI-пайплайна

Это единственная инструкция, которая нужна для наполнения/правки промт-текстов v2 — читай её
целиком перед первой правкой, остальной код пайплайна трогать не нужно.

## Расположение файлов — два корня (D32)

Кросс-документные группы (`document_type: any` — годятся для ЛЮБОГО типа документа) живут здесь,
в `resources/ai/prompts/`: `global`, `prompt-critic`, `screening-global`, `screening-classify`.

Группы типа-владельца лежат в СВОЁМ доменном корне `resources/<домен>/ai/prompts/`. Сегодня один
домен — смета: `resources/estimates/ai/prompts/` несёт `extraction-global`, `extraction-discovery`,
`extraction-passport`, `extraction-rows`, `extraction-totals` (`document_type: estimate`).

Оба корня обнаруживает `App\Services\Llm\PromptCanonReader` двумя глобами: `ai/prompts/*/*.md`
(ядро) и `*/ai/prompts/*/*.md` (доменные корни). Владелец файла — `document_type` из front-matter,
не имя папки; несоответствие («сметный» файл в корне ядра или наоборот) роняет чтение канона.
Новый тип документа добавляет СВОЙ каталог `resources/<домен>/ai/prompts/**` — сидер и применитель
патчей правки не требуют.

## Что здесь

Каждый файл — один промт для одного шага `PromptStep` (`App\Enums\Llm\PromptStep` — интерфейс,
реализуют `CorePromptStep` + типовые enum'ы анализаторов, `app/Enums/Llm/CorePromptStep.php`,
9 значений). Композиция системной инструкции для реального LLM-вызова (`PromptComposer`,
`app/Services/Llm/PromptComposer.php`) склеивает НЕСКОЛЬКО промтов по порядку:

`global` → `<step>-global` (если есть у группы шага) → `<step>` → [блок JSON Schema, генерируется
из PHP Data-классов, не файл]

Пример для `extraction:rows`: `global` + `extraction:global` + `extraction:rows` — три файла
подряд, потом схема. Порядок ВНУТРИ одной группы задаёт `priority` (меньше — раньше).

## Структура файла

```
---
key: extraction:rows
step: extraction:rows
version: 1
priority: 0
is_active: true
---

Текст промта на русском, markdown разрешён.
```

- `key` — уникальный идентификатор промта (вместе с `version`). Для базового промта шага обычно
  совпадает со `step`; для ДОПОЛНИТЕЛЬНОГО промта того же шага (второй файл, другой `priority`) —
  придумай отдельный `key`, `step` может повторяться.
- `step` — ОБЯЗАН быть значением, допустимым для `document_type` файла — реестр
  (`DocumentAnalyzerRegistry::promptStepFor()`) проверяет пару «тип + шаг» на записи, сидер падает
  на опечатке.
- `version` — целое число, начинай с `1`.
- `priority` — порядок внутри шага, меньше = раньше в промте (совпадающие значения — порядок не
  гарантирован, разводи явно).
- `is_active` — `true`/`false`. Обычно всегда `true` — файл, которого больше нет в репозитории,
  сидер деактивирует сам (см. ниже), руками гасить активность файла не нужно.

Держи файл компактным (счёт на строки, не на страницы) — одна ответственность на файл. Семантика
полей ответа уже едет исходником PHP Data-класса (`app/Dto/Procurement/Ai/Estimate/**`, P2.2/P2.3),
промт её НЕ дублирует — только правила поведения, которые в схеме не выразить (что делать с
неполными строками, приоритет ошибок, безопасность и т. п.).

## Цикл правки

1. Правишь `.md`-файл (текст промта) или добавляешь новый файл (для `key`, которого раньше не
   было — независимая правка одного шага, не трогая остальные).
2. Применяешь в БД одним из двух способов:
   - `docker compose exec app php artisan db:seed --class=Database\\Seeders\\PromptSeeder`
   - `docker compose exec app php artisan ai:prompts:sync` (то же самое, отдельная команда)
3. Гоняешь `docker compose exec app php artisan estimate:eval:run` на папке эталонных смет
   (`estimate:dataset:import`, P7.4) — метрики (precision/recall/F1 по полям, `EvalMetrics`) показывают,
   стало лучше или хуже.
4. Повторяешь 1–3, пока метрики не устроят.

`ai:prompts:sync --check` (без записи) — CI-проверка: файлы совпадают с БД байт-в-байт? Используй
её, если нужно убедиться, что кто-то не забыл прогнать `db:seed` после правки файла.

## Как поднимать version

Меняешь СМЫСЛ промта (не опечатку) — подними `version` в front-matter (`1` → `2`). Сидер создаёт
НОВУЮ строку в БД, а предыдущую версию того же `key` помечает `is_active=false` (историю версий не
удаляет — она остаётся в БД для сравнения/отката). Просто правка текста без изменения версии тоже
допустима (`content` файла — источник истины, БД обновляется тем же `key`+`version`), но если
хочешь сохранить старый текст «на память» для сравнения — подними version вместо перезаписи.

## Что значит protected

Промты из этой папки сидер всегда пишет с `is_protected=true` — в админке (Filament, P8.2) такие
записи read-only: их нельзя отредактировать или удалить из UI, только через файл + `db:seed`/
`ai:prompts:sync`. Операторы могут создавать СВОИ промты прямо в админке (`is_protected=false`,
корректирующие/дополняющие правила) — они участвуют в композиции наравне с файловыми (порядок
задаёт `priority` в пределах того же `step`), но живут только в БД, сидер их не трогает и не видит.
