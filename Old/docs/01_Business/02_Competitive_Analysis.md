# Конкурентный анализ — Agelto

## Ландшафт (2026)

Рынок тендерных сервисов РФ — системы **первого поколения** (атрибутивный поиск):

| Игрок | Суть | Слабость |
|:---|:---|:---|
| **Seldon** | Крупнейший агрегатор ЕИС | Поиск по названию контракта/ИНН, нет парсинга смет |
| **Тендерплан** | Уведомления о тендерах | То же, атрибутивный поиск, нет AI |
| **Контур.Закупки** | Экосистема Контур | Широкий охват, но нет глубокой декомпозиции смет |
| **Bicotender** | Мониторинг закупок | Базовый поиск, нет семантики |
| **РТС-тендер** | Электронная торговая площадка | Площадка, не аналитик |

**Незанятая ниша:** никто не делает глубокий AI-парсинг смет + семантический матчинг с каталогом поставщика.

## Дифференциация Agelto

**Agelto — система второго поколения (Deep AI Parsing):**

```
Конкуренты: находят ТЕНДЕР → поставщик сам читает смету (часы/дни)
Agelto:     находит СТРОКУ В СМЕТЕ → матчит с прайсом → доставляет в CRM (секунды)
```

| Параметр | Конкуренты (1 поколение) | Agelto (2 поколение) |
|:---|:---|:---|
| Точность поиска | 40–50% (ключевые слова) | >92% (векторный поиск) |
| Глубина анализа | Заголовок тендера | Каждая строка сметы |
| Форматы | Только метаданные ЕИС | PDF, Excel, Word (OCR+AI) |
| Интеграция | Нет / email | API → CRM (Bitrix24, amoCRM) |
| Языковой комплаенс | Нет | Авто-кириллизация брендов |
| Матчинг с прайсом | Нет | pgvector (косинусное сходство) |

## Барьеры входа (защита от копирования)

> [!note] Смена барьера после переноса каталога в [[TcenZor]]
> Решением [[ADR-001_Catalog_From_TcenZor|ADR-001]] эталонный каталог/MDM ведётся
> в каталоге-хабе [[TcenZor]], а не внутри Agelto. Барьер входа Agelto смещается с
> «владения каталогом» на **сметный матчинг + накопленный golden dataset
> вердиктов** (что само по себе сильнее: каталог копируем, а размеченные вердикты
> по реальным сметам — нет).

1. **Технологический** — конвейер парсинга неструктурированных смет ЕИС (LayoutLM + OCR + NLP + pgvector) требует 1.5–2 года разработки и CAPEX, сопоставимый с нашим бюджетом R&D
2. **Данных** — **golden dataset размеченных вердиктов** по реальным сметам (цель: 50 000+ строк, F-MDM-3) накапливается с каждой верификацией. Эталонный каталог общий (из [[TcenZor]]), но качество матчинга «смета → эталон» обучается только на наших данных
3. **Доменная экспертиза** — обученные модели на специфических коллекциях (ЖБИ, кабель, металл) и понимание сметной традиции нельзя просто купить

## SWOT

### Сильные стороны
- ИИ-стек с точностью матчинга >92% vs 40–50% у конкурентов
- Глубокая нишевая экспертиза (сметы строительства)
- Низкий порог безубыточности (< 0.1% SAM)
- Соответствие государственному вектору импортозамещения

### Слабые стороны
- Высокий CAPEX на R&D (GPU, Senior AI-инженеры)
- Зависимость от качества PDF в ЕИС
- Низкая узнаваемость бренда на старте

### Возможности
- Государственный заказ на цифровизацию строительства
- Интеграция с ГосТех — стать официальным AI-модулем для госзаказчиков
- Экспансия в BIM — связь цифровой модели здания с рынком материалов
- Функция антикоррупционного аудита смет (проверка цен vs ФГИС ЦС)

### Угрозы
- Крупные игроки (Seldon) могут скопировать упрощенную AI-версию
- ЕИС может изменить политику доступа к документам для парсинга
- Кадровый дефицит NLP-специалистов
