# Обнаруженные проблемы

Статусы: подтверждено кодом / подтверждено воспроизведением / подтверждено живым ответом.
Исправления не смешивать с чистыми инструкциями запуска: после исправления обновлять статус
проблемы и добавлять доказательство; исходный сценарий сохранять.

## EIS-001 — многострочный CSV может терять строки

Статус: подтверждено воспроизведением, `evidence/csv-parser-proof.json`.
`CsvSourceMethod::parseCsv()` делит CSV на физические строки до `str_getcsv` и молча пропускает
строки с другим числом полей. Переводы строк в quoted field способны потерять закупку и уменьшить
`rowsTotal` ниже 500, вследствие чего сканер преждевременно завершит интервал.
Фактический результат на PHP 8.5.8: потоковый CSV-parser читает 500 записей, текущий — 499.
На первых 23 живых ответах расхождения с потоковым parser не обнаружены; это не отменяет дефект.

## EIS-002 — ошибка источника может стать пустой выдачей

Статус: подтверждено кодом, живое проявление не установлено.
`collectListing()` парсит конечный HTTP-ответ без обязательной проверки статуса/CSV-заголовка.
HTML 200/403/503 либо повторный пустой 200 могут стать нулём записей и продвижением курсора.
Парсер на синтетических HTML и пустом теле вернул 0 без исключения. Живые ответы первых
23 запросов — CSV с корректным заголовком, включая header-only в праздничные/выходные дни.

## EIS-003 — пропуск строки без обязательных полей

Статус: подтверждено кодом.
`EisCsvRowMapper` возвращает null при отсутствии номера/дат, ingestion учитывает skipped.
Нужно различать допустимый пропуск и повреждённый ответ, иначе полнота не доказана.

## EIS-004 — нет общего переключателя первого этапа

Статус: подтверждено кодом.
Отключение screening/extraction не отключает scheduler `crawler:fetch-details`, подготовку,
revalidation и pipeline backlog. В текущей репетиции изоляция обеспечивается отдельным worker
архивной очереди и остановленным scheduler/Horizon. Для штатного полного scheduler нужен
явный режим разрешённых стадий и проверка всех прямых/плановых dispatch.

## EIS-005 — охват и верхняя цена ограничены

Статус: подтверждено живыми независимыми счётчиками.
Базовый архив — только завершённые 44-ФЗ, ОКПД2 43; стандартный потолок цены 1 млрд рублей.
Первый completed проход дал 2515 номеров, все 31 дневное окно, без raw-потерь. SSR totalCount
для этого профиля с той же ценой =2515, без ценовой границы =2516. Поэтому штатный Completed
не доказывает полноту месяца даже при корректном CSV. Evidence: `source-count.json`,
`source-count-without-price.json`, `snapshot-run-1-completed.json`.

Новый audit seed задаёт цену до 1 трлн для повторного прохода; глобальный предел не изменён.
Повтор должен получить недостающую запись и сохранить по одной ревизии остальных закупок.
Отдельно сравнить totalCount нового профиля с выдачей без ценовых ограничений.
Называть такой предметный охват всеми госзакупками месяца нельзя.

## ENV-001 — остановленные контейнеры ссылаются на удалённую сеть

Статус: подтверждено запуском; обход устранён.
Первый compose up завершился `network ... not found`; ограниченный `--force-recreate`
для app/postgres/redis/minio восстановил сеть без удаления томов.

## EIS-006 — typed options не проходят собственный round trip

Статус: подтверждено выполнением при подготовке сида.
Присваивание `$target->options = $source->options` сериализует `recordsPerPage`, который
`CrawlerRuntimeOptions::validateAndCreate()` отвергает: allowlist содержит `records_per_page`.
Новый audit seed копирует исходные сохранённые options, не вводя собственную схему колонок.
Нужна отдельная проверка совместимости входных/выходных ключей DTO.

## EIS-007 — долгие повторы не наблюдаемы по попыткам и задерживают паузу

Статус: подтверждено живым прогоном и кодом.
Fetch #20 (20 января): 104398 ms, wait_ms=9651, конечный HTTP 200, 140 записей.
Точное число/типы промежуточных ошибок восстановить нельзя: отдельного журнала попыток нет.
У proxy #1 зафиксированы network_timeout в агрегированном health, но это не полная история.
На 10:34:17 UTC запрос паузы от 10:33:09 ещё ожидал завершения блока за 24 января.
`requestWithRetries` не проверяет стоп-сигнал между попытками; deadline и heartbeat внутри
listing retry loop отсутствуют. Не путать молча ожидающий worker с доказанным зависанием.

Рекомендуемые изменения после этого аудита: отдельный безопасный журнал попыток с run/crawler,
request hash, day/from/price, attempt/max, proxy_id, start/end, HTTP либо enum причины,
budget/throttle/retry sleep и решением о повторе. Проверять stop/deadline между попытками
и дробить длительные ожидания; не записывать authenticated URL и сырые ошибки.

## ENV-002 — сброс БД оставляет задачи в Redis

Статус: подтверждено запуском; остаток очищен.
После migrate:fresh в `redis_prepare/doc_prepare` сохранились 10 ready jobs старого окружения,
при этом БД документов пуста. Исполнителей этой очереди не запускали. Выполнена адресная
`queue:clear redis_prepare --queue=doc_prepare`, удалено 10 задач. Сброс БД и сброс очередей —
разные операции; перед новым worker обязательно проверять ready/reserved/delayed.

## ENV-003 — настроенный Playwright нельзя считать RU без проверки

Статус: подтверждено живой проверкой.
Первый запрос текущего Playwright MCP к ipinfo показал SG. Отдельный host Chromium с proxy из
env подтвердил RU. SSR выдача января в этом браузере не ответила за 30 секунд, поэтому
именно браузерная проверка totalCount не подтверждена (`evidence/browser-check.json`).
Независимый totalCount позже получен HTTP-клиентом через штатный resolver/TLS/budget:
2515 со старым потолком цены и 2516 без цены/с новым потолком.

## EIS-008 — исчерпание сетевых попыток требует операторского продолжения

Статус: подтверждено живым прогоном #2.
CSV за 20 января после пяти network_timeout завершил run как failed в 10:44:47 UTC.
Global breaker прокси открылся на 30 минут, до 11:14:47 UTC. Сохранённый курсор остался
на 20 января, но `startOrResume` автоматически подбирает только paused, не failed.
`crawler:recover-stale` тоже не возобновляет failed. Поэтому после окончания cooldown
нужен новый ограниченный старт с незавершённого дня, а не SQL-смена статуса.

Для текущей репетиции поставлен один delayed operator command на 11:15:02 UTC,
с окном 20–31 января; он использует обычную команду и StartCrawlerRunAction. Это не исправление
production recovery policy. Нужны отдельное решение о bounded recovery сетевых ошибок,
сохранение execution context/курсора, различение отказов цели и узла, и наблюдаемые попытки.
Breaker не сбрасывался. `failed_jobs=1` сохранён, следующий этап не запускался.

## Проверки вспомогательных инструментов

При проверке новых audit helpers исправлены: ложный успех raw-check для отсутствующего/пустого
run, поиск сохранённых номеров без registry scope, повторная pause уже paused run, выбор
неактуального paused run при resume и возможность ручного старта поверх delayed очереди.
Проверка несуществующего run теперь завершается exit 1; повторные start/defer при delayed=1
отклоняются без создания задач. Эти изменения относятся к инструментам этого аудита,
а не к исправлению исходных EIS-001/002/003/007/008 в production-коде.

## Ремонт 2026-10-18 — исходные сценарии выше сохранены

- EIS-001: строгие потоковые записи сохраняют CR/LF, `;`, escaped quotes; width/quoting errors
  отклоняют ответ. 500-record proof больше не принимает потерю записи.
- EIS-002: финальный неуспешный HTTP, HTML, пустое тело, invalid/duplicate/missing header
  отклоняются до Drained. Header-only остаётся валидным. Rejected batch сохраняет raw/fetch
  под lease; health probe даёт not_enough_data, bounded CLI фиксирует response_error.
- EIS-003: обязательные номер/даты и невозможная календарная дата дают parse errors.
  Archive transaction откатывает неполный блок и курсор; raw object сохраняется.
- EIS-004: `CRAWLER_DOWNSTREAM_ENABLED=false` останавливает direct/batch/manual dispatch,
  retry/recovery/revalidation и уже queued detail/PipelineJob до чтения/lease/HTTP. Default true;
  env executor не менял. Audit start/resume/preflight/defer отказывают при включённых downstream/AI.
- EIS-005: run3 завершён 11:21:01 UTC: накоплено 2516 закупок и 2516 ревизий, 0 downstream.
  Approved profile priceTo=1трлн, global price ceiling=1млрд сохранены. См. STATUS и run3 evidence.
- EIS-006: options принимают snake/camel legacy ключ, сериализуют snake, отклоняют конфликт
  и unknown keys; сид сохраняет исходную форму raw options ради точной совместимости
  с прежними артефактами. Typed DTO roundtrip проверяется отдельным regression test.
- EIS-007: attempt log через существующий application logger: request hash/run/crawler,
  attempt/max, proxy ID, timestamps/duration, HTTP/enum reason, budget wait, retry decision.
  Retry/budget/throttle waits имеют секундный checkpoint; lease и stop проверяются между
  HTTP attempts. Deadline одного slice ограничивает HTTP и даёт Checkpointed без продвижения дня.
  Уже идущий HTTP не прерывается немедленно. Transport exception санитизирована.

### EIS-008 — оценка совместимости, политика остаётся открытой

Конкретное evidence: run2 failed 10:44:47, cursor.day=2025-01-20, proxy global cooldown до
11:14:47; один operator retry создал run3 с новым ограниченным окном 20–31 января и завершился.
`CrawlerRunManager::startOrResume` выбирает Paused, `RecoverStaleRuns` — stale recovery,
ни один не выбирает Failed. Queue retry contract запрещает job retry knobs. Возобновить Failed
автоматически означало бы добавить новую политику eligibility, max restarts/total deadline,
ожидания global/target cooldown и переноса неизменяемого execution context. Эти лимиты не
утверждены. Поэтому Failed остаётся terminal для автоматического recovery; ни статус SQL,
ни breaker не сбрасываются, self-restart не добавлен. Решение нужно отдельному владельцу
production recovery; оно не блокирует разрешённый SPEC ремонт и операторский rerun.
