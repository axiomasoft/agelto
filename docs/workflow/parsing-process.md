# Бизнес-процесс: Многостадийный парсинг данных

Этот документ перенесён из `docs/business-processes/parsing-process.md`.

Процесс разделен на 4 стадии, чтобы минимизировать затраты на вычислительные ресурсы и API токены, отсеивая нерелевантные данные на ранних этапах.

## Стадия 1: Сбор ссылок (Collector)

**Цель:** получение списка новых извещений из ЕИС.

- **Вход:** ссылка на результаты расширенного поиска ЕИС (с настроенными фильтрами)
- **Действие:** обход страниц поиска, сбор номеров извещений (`reg_number`), ссылок на карточки и трех ключевых дат (публикация, обновление, окончание подачи)
- **Результат:** записи в таблице `platform_parser_map_urls`

## Стадия 2: Индексация документов (Document Indexer)

**Цель:** получение списка всех вложенных файлов закупки.

- **Вход:** карточка закупки
- **Действие:** переход в раздел «Документы», сбор прямых ссылок на скачивание файлов и их названий
- **Фильтрация:** предварительная фильтрация по именам файлов (поиск ключевых слов «смета», «лср», «локальный»)
- **Результат:** записи в таблице `platform_parser_map_documents`

## Стадия 3: ИИ-скрининг (AI Screening)

**Цель:** быстрая проверка: является ли файл сметой. Самый важный этап экономии ресурсов.

- **Действие:**
  - для **Excel**: отправка первых 50–100 строк (в формате HTML) в Gemini
  - для **PDF/сканов**: отправка только первой страницы документа
- **Запрос к ИИ:** «Является ли этот документ сметой СМР? Какова итоговая сумма?»
- **Результат:** обновление статуса в `ai_analysis_report`. Если `is_smeta = true`, закупка переходит на следующую стадию

## Стадия 4: Глубокий парсинг (Full Data Extraction)

**Цель:** полное извлечение всех позиций сметы и создание записей в БД.

- **Действие:**
  - чанковая обработка всего файла (по 80 строк)
  - распознавание обоснований, наименований работ, единиц измерения, объемов и стоимостей
  - сопоставление данных с разделами сметы
- **Результат:** заполнение таблиц `orders` и `order_lots`, создание детализированного списка позиций сметы для анализа пользователем
