# СПГЗ early-lead-scoring: упреждающая аналитика будущих закупок

## Обзор

Конкуренты скорят тендер **на входе** — когда извещение уже опубликовано.
Agelto скорит заказчика **за 6–12 мес до тендера** — из планов-графиков (СПГЗ).

Лид = не человек, а связка **«заказчик + направление закупки + временной
интервал»**. Из плана-графика заранее видны: предмет, объём, сроки,
ориентировочная НМЦК, иногда контакты заказчика.

Pipeline:

1. **Сбор**: планы-графики 44-ФЗ (год + 3 плановых) и планы 223-ФЗ (1–7 лет) из
   ЕИС. Исторические тендеры заказчиков за 2–3 года.
2. **Нормализация**: заказчики по ИНН/КПП/ОГРН (+связка с дочками); маппинг
   позиций СПГЗ ↔ итоговых закупок; таймлайн: внесение в план → публикация
   извещения → контракт.
3. **Feature engineering**: частота/стабильность закупок по сегменту, доля
   отменённых, средняя конкуренция и снижение цены, портрет победителей;
   срок до закупки, регулярность позиции, история правок НМЦК; рост ОКПД2 по
   региону, плотность конкурентов.
4. **Scoring-модель**: P(закупка состоится в окне) × P(рентабельна) × P(победа).
   Target — из историки: какие связки конвертировались в маржинальные договоры.
5. **Использование**: лид-лист на 6–12 мес, отсортированный по дате будущей
   закупки и марже → отдел продаж готовит ТКП/пилот/доверие **до** тендера.

Это превращает Agelto из «находим вашу позицию в смете» в «говорим, какой
заказчик купит вашу позицию через полгода — готовьтесь заранее».

## Рыночное подтверждение

> Источник: perplexity-web (2026-06-22).

- **Источник данных существует и обязателен**: по 44-ФЗ все заказчики публикуют
  планы-графики на год + 3 плановых; без позиции в плане закупку проводить
  нельзя. По 223-ФЗ — план минимум на 1 год, по инновационной продукции 5–7 лет.
  В планах видны предмет, объём, сроки, ориентировочная НМЦК. Источник: saby.ru.
- **Ниша подсвечена, но не закрыта конкурентами**: Seldon (раздел
  «планы-графики»), Контур.Закупки, TenderPlan (нейросеть: прогноз конкуренции,
  целесообразности, вероятности победы), TenderGuru (базы победителей, прогноз
  цен). **НО** у всех scoring «на входе в тендер» — когда извещение опубликовано
  / план уже с понятным сроком. **Lead scoring заказчиков на горизонте 6–12 мес
  как отдельный B2B-продукт для продажников — отсутствует.** Источники: saby.ru,
  toolfox.ru (TenderPlan), tenderguru.ru, vc.ru (Контур.Закупки).
- **Value-prop белого пятна**: «не ещё один поиск тендеров, а система раннего
  прогноза спроса госзаказчиков на 1–3 года + очередь лидов для отдела продаж».
- **Стек подтверждён**: PostgreSQL/JSONB (или ClickHouse для тяжёлой аналитики) +
  ML-слой Python (XGBoost/CatBoost) + интеграции в CRM по вебхукам — ровно как
  делают TenderPlan/Контур. Источники: companies.rbc.ru, vc.ru.

> Сильный сигнал: явное белое пятно (нет horizon-6–12mo lead-scoring как
> продукта), а не «давка» в нише. Подтверждает приоритет high.

## Связь с проектами

- [[PickStat]] — **ключевая синергия**: PickStat = аналитика/статистика, может
  быть источником исторических данных и feature store для scoring-модели (тренды
  ОКПД2, плотность конкурентов, портреты заказчиков). Скоринг ездит на данных
  PickStat.
- [[Agelto]] — модуль Eis уже парсит ЕИС; добавить сбор планов-графиков. Scoring
  дополняет существующий «матчинг позиции в смете» upstream-сигналом.
- [[TcenZor]] — каталог нормализует ОКПД2/категории для feature engineering.

## Риски

- **Качество историки**: маппинг СПГЗ ↔ реальные закупки — грязный (позиции
  правятся, отменяются). Нужна валидация conversion-rate плана в контракт.
- **Холодный старт модели**: без 2–3 лет размеченной историки scoring слабый;
  на старте — rule-based взвешенный скоринг, ML позже.
- **Конкуренты могут «дотянуться»**: Seldon уже показывает планы-графики —
  барьер не данные, а качество предиктов. Defensibility = модель + данные
  [[PickStat]], а не доступ к ЕИС.

## Следующий шаг

Promote-критерий: на исторической выборке (50–100 заказчиков, 2–3 года)
проверить базовую гипотезу — **доля позиций плана-графика, конвертирующихся в
реальную закупку в окне 12 мес**. Если conversion предсказуем (rule-based AUC
заметно выше случайного) → `/vault:architecture` на data-pipeline СПГЗ +
feature store на [[PickStat]].
