# Обзор продукта

Agelto собирает данные о государственных и корпоративных закупках (ЕИС и другие площадки),
скачивает приложенные к ним документы и — там, где документ содержит смету — извлекает её в
структурированные строки: разделы, позиции, единицы измерения, количества, цены, суммы. Итог —
не «ещё один архив PDF», а таблица, по которой можно считать, сравнивать и анализировать сметы
без ручного перепечатывания.

## Проблема, которую решает EST-AI

Документы закупок — сотни тысяч файлов в разных форматах (PDF-сканы, Excel, архивы), без единой
структуры. Смета внутри документа может быть на десятки и сотни строк, разбита между несколькими
файлами или, наоборот, несколько смет лежат в одном файле. Ручная выгрузка такого объёма
нереалистична; универсальный «разбор по шаблону» не работает — форматы слишком разные.

EST-AI — слой AI-анализа поверх уже собранных документов (краулинг — отдельный, более ранний
этап конвейера, см. `workflow/crawling-and-discovery.md`). Он решает три последовательные
задачи:

1. **Подготовка** — приводит скачанный файл к виду, пригодному для анализа (архив разворачивается,
   Excel конвертируется, огромные файлы проверяются на предмет «слишком большой для разбора»).
2. **Первичный анализ (скрининг)** — дёшево и быстро определяет, что за документ: смета, что-то
   другое или непонятно. Только кандидаты идут дальше.
3. **Извлечение** — за счёт AI-модели (сейчас — Gemini) построчно вытаскивает содержимое сметы:
   паспорт (шапка), строки, итоги — с проверкой полноты и арифметики на бэкенде, не только «как
   сказала модель».

## Для кого

- **Владелец/менеджмент** (этот раздел, `business/`) — что за продукт и куда он движется
  (`roadmap.md`).
- **Операторы** (`operators/`) — используют админку: проверяют результат разбора, ревизуют
  сомнительные сметы, управляют промтами.
- **Разработчики и AI-агенты** (`dev/`) — технические внутренности пайплайна, база данных,
  LLM-слой, деплой.
- **Менеджерская часть процессов** (`workflow/`) — как устроены стадии бизнес-языком, без кода.

## Границы системы

- EST-AI НЕ занимается сбором документов — это краулинг (более ранняя стадия, уже работает
  независимо от этого плана).
- EST-AI НЕ гарантирует разбор 100% документов: часть файлов принципиально нечитаема (защищённый
  паролем PDF, битый скан) или превышает лимиты AI-провайдера на один запрос — такие документы
  получают явный терминальный статус «не смогли обработать» (`unprocessable`), а не тихо теряются
  или зависают (см. `operators/reference/statuses.md`).
- Автоматическое извлечение — не замена финального контроля: сомнительные сметы (расхождение сумм,
  подозрение на пропуски) остаются видимыми оператору для ревью, а не автоматически принимаются
  как истина.
- Другие типы документов (не сметы) система пока не разбирает полно — только классифицирует
  (скрининг); архитектурный шов для второго типа документа заложен, но не реализован.
- Публичного API сейчас нет: продукт предназначен для внутренних операторов и накопления данных,
  из которых позднее может обучаться локальная модель.
- Реальная стоимость обработки, лимиты аккаунта провайдера и глубокая промт-инженерия описаны в
  технической документации и зеркалятся в Brain по решению владельца D89.
