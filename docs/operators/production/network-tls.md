# Подготовка сети и TLS

`docker/host/nginx/agelto.conf` — отслеживаемый шаблон. Он завершает TLS и проксирует только на
loopback-адрес приложения `127.0.0.1:8080`; контейнеры не становятся публичными upstream.
Замените три заглушки `__AGELTO_*__` во временном файле и выполните `nginx -t` до установки или
перечитывания конфигурации. Локальный контракт выполняет эту проверку синтаксиса с временным
сертификатом.

`8080` — значение по умолчанию, а не требование: на общем хосте выберите свободный
loopback-порт и замените upstream одновременно с `APP_PORT`. На `agelto.ru` используется `8082`.
Не устанавливайте TLS-шаблон до получения настоящего сертификата: сначала отдельный vhost только
для HTTP-challenge. NGINX 1.28: `listen 443 ssl;`, `listen [::]:443 ssl;`, `http2 on;` вместо
устаревшего `listen ... http2`. Сохраните собственную резервную копию, проверьте `nginx -t`, затем
выполните reload. Не меняйте чужие sites, default и сертификаты. Полные команды:
[ручная настройка TLS](manual-deployment.md#6-dns-nginx-и-tls).
Проверяйте `/up`, HTTPS-ссылки на assets и запросы Livewire. Если приложение видит подключение
хостового NGINX с адреса Docker-шлюза, задайте этот точный адрес в `TRUSTED_PROXIES`.
По умолчанию Laravel доверяет loopback. Внешний NGINX публикует HSTS для HTTPS и принимает
запросы размером до 200 MiB с таймаутом чтения прокси 300 секунд.

Все внешние действия выполняются в ходе репетиции оператора в таком порядке:

1. убедиться, что нужные записи A/AAAA указывают на утверждённый хост;
2. установить конфигурацию только для HTTP-challenge и пройти `nginx -t`;
3. выпустить сертификат через Certbot из официального пакета Ubuntu;
4. подставить точные пути к сертификату и ключу, снова пройти `nginx -t` и перечитать NGINX;
5. проверить HTTPS, редиректы, forwarded-заголовки и WebSocket upgrade через публичное имя хоста;
6. выполнить `certbot renew --dry-run` и сохранить только обезличенные данные об идентичности и
   сроке действия сертификата.

Не используйте `--no-check-certificate`, публичный upstream-контейнер, reload без проверки и
сертификат, выпущенный до подтверждения владения DNS. DNS, выпуск сертификата, reload и публичные
проверки намеренно не выполняются текущим локальным планом подготовки. Канонические команды и
обязательные поля доказательств перечислены в
[текущем inventory команд](commands.md#current-command-inventory).
