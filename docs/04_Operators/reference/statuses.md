# Статусы и колонки админки

## Работа с таблицами на узком экране

На телефоне остаются видимыми основная сущность, её статус и доступные действия. Вторичные
поля (временные метки, диагностика и технические идентификаторы) доступны через настройку
колонок и на широком экране. Длинное значение в таблице показывается в несколько строк; наведите
курсор или откройте запись, чтобы увидеть его полностью. UUID и внутренние ID не удаляются, но
по умолчанию не занимают рабочую поверхность.

Raw stage mapping выбирается как platform default либо exact registry override; override имеет
приоритет. Неизвестный этап создаётся exact-registry `unknown`, не влияя на другие реестры.
Если в форме нет platform/registry capability, профиль не сохраняется: это fail-closed diagnostic,
а не причина выбирать другую площадку или global fallback.

Сверено с `app/Enums/Procurement/` — каждый кейс перечислен.

## Статус документа (`DocumentStatus`)

Колонка «Статус» в карточке документа — где документ сейчас в конвейере обработки.

| Статус | Значит |
|---|---|
| `discovered` (обнаружен) | Краулер увидел документ на площадке, ещё не скачал. |
| `downloaded` (скачан) | Файл скачан, ждёт подготовки к AI-анализу. |
| `expanded` (развёрнут) | Архив успешно разложен на дочерние документы. Сам архив терминален и не проходит скрининг; дочерние файлы обрабатываются отдельно. |
| `prepared` (подготовлен) | Приведён к разбираемому виду (архив развёрнут, Excel сконвертирован и т.п.). |
| `screened` (проверен) | Прошёл первичный анализ — определён тип документа. |
| `extracted` (извлечён) | Смета успешно извлечена в строки. |
| `ignored` (отсеян) | Не смета или тип не определён — дальше не обрабатывается. |
| `failed` (ошибка) | Временный технический сбой — система повторит попытку автоматически. |
| `unprocessable` (не смогли обработать) | Терминальный, НЕ повторяемый исход: документ принципиально не поддаётся разбору. Причина — в `UnprocessableReason` (ниже). Это не сбой, а констатация факта — см. `04_Operators/how-to/handle-unprocessable-document.md`. |

### Результат screening в карточке анализа

Карточка показывает краткое содержание, тип, confidence, число видимых смет, теги и backend
решение. `unknown` — завершённый тип, а пустой тип означает, что screening ещё не завершён.
`single`/`multiple` относятся только к типу `estimate`; это не число страниц или файлов архива.
Решения `extract`, `retain`, `review`, `ignore` и причина показываются отдельно: их вычисляет
система, не модель. Старый или неполный результат остаётся доступен как raw JSON для аудита.

### Причина `unprocessable` (`UnprocessableReason`)

| Причина | Значит |
|---|---|
| `too_large` | Файл (или таблица Excel) превышает настроенный лимит размера/строк. |
| `zip_bomb` | Архив выглядит как «zip-бомба» (подозрительно большое несоответствие размера упакованного/распакованного) — не разворачивается из соображений безопасности. |
| `unsupported_format` | Расширение не входит в закрытый список поддерживаемых форматов. |
| `format_mismatch` | Расширение известно, но MIME или сигнатура байтов ему не соответствует. |
| `unreadable_format` | Формат файла не читается (битый PDF, неподдерживаемый формат). |
| `password_protected` | PDF защищён паролем — открыть не можем. |
| `provider_limit_size` | Файл превышает лимит размера ОДНОГО запроса к AI-провайдеру (даже разбор окнами не спасает). |
| `provider_limit_pages` | Файл превышает лимит числа страниц ОДНОГО запроса к AI-провайдеру. |

## Статус прогона краулера (`RunStatus`)

Колонка «Статус» в витрине прогонов (`Краулинг → Прогоны`) — где сейчас конкретный обход площадки
по одному профилю.

| Статус | Значит |
|---|---|
| `running` (выполняется) | Job идёт на очереди Horizon прямо сейчас (либо завис — см. heartbeat). |
| `paused` (приостановлен) | Остановлен кооперативно («Остановить») или воркер упал (протухший heartbeat) — курсор сохранён, прогон можно продолжить с того же места. |
| `completed` (завершён) | Дошёл до стоп-условия (известный блок / нет новых-обновлённых строк / повтор дедуп-сигнатуры) без ошибок. |
| `failed` (ошибка) | Упал с исключением — `last_error`/`last_error_at` несут текст и время. |
| `cancelled` (отменён) | Остановлен кооперативно («Отменить») — терминальный, продолжить нельзя, только «Запустить с начала». |

### Причина остановки (`stats.stop_reason`)

Показывается в карточке прогона (секция «Итоги») и колонкой в таблице. Пишется ТОЛЬКО при
`completed`/`paused`/`cancelled` — на `running`/`failed` пусто (`—`).

| Причина | Значит |
|---|---|
| `reached_previous_run` | Fresh-прогон с политикой «только актуальные данные» дошёл до времени старта предыдущего завершённого прогона (`stop_threshold_at`). |
| `no_new_or_updated_rows` | Снятый блок не принёс ни одной новой/обновлённой строки — дальше площадка отдаёт уже известное. |
| `dedup_signature_repeat` | Блок повторяет дедуп-сигнатуру предыдущего — признак конца выдачи (`stats.cap_hit` выставляется тем же событием). |
| «Остановлено оператором (pause)» / «(cancel)» | Оператор нажал «Остановить»/«Отменить» в админке или консоли — стоп-гейт сработал на ближайшей проверке между блоками. |

### Вид запрошенной остановки (`RunStopKind`)

| Значение | Значит |
|---|---|
| `pause` (остановить) | Прогон уходит в `paused` — курсор сохранён, кнопка «Продолжить» доступна. |
| `cancel` (отменить) | Прогон уходит в `cancelled` — терминально, продолжить нельзя. |

## Статус AI-анализа (`AnalysisStatus`)

Колонка «Статус» в карточке AI-анализа (одна запись = одна попытка скрининга или извлечения).

| Статус | Значит |
|---|---|
| `pending` (ожидает) | Анализ поставлен в очередь, ещё не начался. |
| `running` (выполняется) | Модель сейчас обрабатывает документ. |
| `succeeded` (успешно) | Анализ завершён успешно — есть результат. |
| `failed` (ошибка) | Анализ провалился (временная проблема — обычно повторяется автоматически). |
| `skipped` (пропущен) | Анализ не выполнялся (например, документ отсеян раньше). |

## Полнота и достоверность извлечённой сметы (`validation_status`)

Колонка на карточке КАЖДОЙ извлечённой сметы (не документа целиком — в одном документе может быть
несколько смет с разным статусом).

| Значение | Значит |
|---|---|
| `valid` (в порядке) | Собраны все ожидаемые строки, суммы сходятся в пределах допуска. |
| `suspicious` (подозрительная) | Есть расхождения (суммы не сходятся, возможны пропуски/дубли строк), но данные сохранены целиком — стоит проверить (`how-to/review-estimate.md`). |
| `invalid` (существенная потеря данных) | Сильное расхождение между ожидаемым и извлечённым количеством строк — приоритетный кандидат на ревью, данные всё равно сохранены, не отброшены. |

## Статус операторского ревью (`review_status`)

Колонка на карточке AI-анализа — отмечал ли оператор результат.

| Значение | Значит |
|---|---|
| `unreviewed` (не проверено) | Оператор ещё не смотрел результат. |
| `approved` (проверено) | Оператор подтвердил результат верным — становится эталонным примером для обучения. |
| `rejected` (отклонено) | Оператор зафиксировал коррекцию — что именно не так (см. `how-to/review-estimate.md`). |

## Пометка неопределённости позиции

Колонка «Пометка» в витрине смет (`how-to/check-marked-positions.md`) — на КОНКРЕТНОЙ строке
сметы, не на смете целиком (одна и та же смета может быть `valid` в целом и нести одну-две
помеченных строки).

| Причина | Значит |
|---|---|
| «Не прочитано моделью» (`unreadable`) | AI не смог разобрать эту строку (или часть её полей) в
  источнике — обычно плохое качество скана. Перечислены конкретные поля, которых это касается. |
| «Арифметика раздела не сходится» (`arithmetic_mismatch`) | Проверка сметы нашла: сумма по
  разделу не сходится с суммой позиций внутри него. |
| «Нарушена нумерация строк» (`numbering_gap`) | Проверка сметы нашла разрыв в сквозной нумерации
  строк. |

Пустая колонка = строка прочитана и проверена полностью. Пометка НЕ означает «строка неверна» —
это сигнал «здесь стоит свериться с оригиналом документа», данные при этом сохранены как есть, не
отброшены.

Как всё это использовать в повседневной работе — `how-to/check-ai-analysis.md`,
`how-to/review-estimate.md` и `how-to/check-marked-positions.md`.
