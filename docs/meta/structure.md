# Каркас документации

`docs/` — единое дерево, которое зеркалится в Brain. Его стартовая точка —
[`docs/index.md`](../index.md): оттуда читатель доходит до любого файла через раздел и его
`_index.md` не более чем за два перехода.

## Разделы

| Раздел | Что в нём живёт | Чего в нём не бывает |
|---|---|---|
| `00_Ideas` | Черновики владельца и резерв места для Brain. | Рабочие регламенты и технический канон. |
| `01_Business` | Продукт, дорожная карта и риски для владельца. | Детали реализации и SOP. |
| `02_Workflow` | Доменные процессы на общем, бизнес-языке. | Дублирование internals из `03_Dev`. |
| `03_Dev` | Архитектура, кодовые контракты, пайплайны, ADR, runbooks и среда разработки. | Операторские инструкции по UI. |
| `04_Operators` | Task-based SOP и понятные статусы админки. | Исходный код и инженерные internals. |
| `meta` | Правила ведения самой документации. | Предметная или продуктовая документация. |

Новый верхнеуровневый раздел или переименование `00_Ideas`…`04_Operators` требует решения
владельца: эти имена — внешний контракт Brain-sync.

## Размещение и навигация

Каждый раздел имеет `_index.md`: это короткий маршрутизатор с блоками не более семи ссылок.
Добавляя файл, добавьте ссылку из подходящего маршрутизатора и проверьте путь от
[`docs/index.md`](../index.md). Одна тема имеет один канонический файл; остальные страницы
ссылаются на него, а не копируют текст.

## Frontmatter

Каждый markdown-файл начинается с frontmatter:

```yaml
---
audience: dev | operator | owner | shared
type: howto | reference | explanation | runbook | adr
status: draft | living
last-reviewed: YYYY-MM-DD # только для 04_Operators/how-to/**
---
```

`draft` — только настоящая заглушка с объяснением будущего содержания. Наполненный материал
имеет `living`; SOP дополнительно обновляет `last-reviewed` при содержательной правке.

## Диаграммы и Brain-sync

Mermaid пишется inline в markdown. Отдельный файл допустим лишь для большой диаграммы, которую
используют минимум два документа. Диаграмма поясняет уже описанный текст и не вводит новую
предметную истину. Всё `docs/` синхронизируется с Brain, поэтому ссылки и имена верхних разделов
должны оставаться стабильными.
