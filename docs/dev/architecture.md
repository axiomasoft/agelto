# Архитектура

Этот раздел — адаптированная версия старого `docs/architecture.md`.

## Архитектура системы сбора данных

Система построена на модульной архитектуре с четким разделением ответственности между общим ядром (Platform) и специфичными реализациями площадок (Eis, B2B и т.д.).

## Терминология

1. **Platform (Платформа)** — объект, описывающий источник данных (например, ЕИС).
2. **Crawler (Профиль/Настройка)** — модель `Platform\Models\Crawling\Crawler`. Содержит параметры поиска: фильтры, регионы, частоту обновлений.
   - Таблица: `plt_crawlers`
3. **Link (Результат обхода)** — модель `Platform\Models\Crawling\Link`. Конкретная найденная закупка/лот на первом этапе.
   - Таблица: `plt_crawler_links`
4. **Document (Документ)** — модель `Platform\Models\Parser\Document`. Файл, найденный внутри Link (смета, ТЗ, контракт).
   - Таблица: `plt_parser_documents`

## Схема работы (в общих чертах)

1. **Crawling (обход)**
   - Сервис `AbstractCrawlingService` запускается для конкретного `Crawler`.
   - Находит новые объекты на источнике.
   - Формирует `LinkDto` и сохраняет в `plt_crawler_links` со статусом `pending`.
2. **Parsing (анализ и разбор)**
   - Воркер берет ссылки из `plt_crawler_links`.
   - Собирает список документов в `plt_parser_documents`.
   - Использует AI (Gemini) для классификации: является ли документ сметой.
   - Если да — извлекает позиции сметы в структурированный вид.
