## Архитектура системы сбора данных

Система построена на модульной архитектуре с четким разделением ответственности между общим ядром (Platform) и специфичными реализациями площадок (Eis, B2B и т.д.).

## Терминология

1. **Platform (Платформа)** — объект, описывающий источник данных (например, ЕИС).
2. **Crawler (Профиль/Настройка)** — модель `App\Models\Crawler\Crawler`. Содержит параметры поиска: фильтры, регионы, частоту обновлений.
   - Таблица: `plt_crawlers`
3. **Link (Результат обхода)** — модель `App\Models\Crawler\Link`. Конкретная найденная закупка/лот на первом этапе.
   - Таблица: `plt_crawler_links`
4. **LinkAttachment (Документ-вложение)** — модель `App\Models\Crawler\LinkAttachment`. Файл, найденный внутри Link (смета, ТЗ, контракт).
   - Таблица: `plt_crawler_link_attachments`
5. **DocumentAnalysis (Сессия AI-анализа)** — модель `App\Models\DocumentAnalysis\DocumentAnalysis`. Полиморфно привязана к вложению; несёт статус AI-пайплайна (enum `AnalysisStatus`).
   - Таблица: `plt_document_analysis`

## Схема работы (в общих чертах)

1. **Crawling (обход)**
   - Сервис `AbstractCrawlingService` запускается для конкретного `Crawler`.
   - Находит новые объекты на источнике.
   - Формирует `LinkDto` и сохраняет в `plt_crawler_links` со статусом `pending`.
2. **Parsing (анализ и разбор)**
   - Воркер берет ссылки из `plt_crawler_links`.
   - Собирает список документов-вложений в `plt_crawler_link_attachments`.
   - Создаёт сессию `DocumentAnalysis` и через AI (Gemini) классифицирует: является ли документ сметой.
   - Если да — извлекает позиции сметы в `plt_document_analysis_responses` (нормализация в `ord_*` — Стадия 5, не подключена).
