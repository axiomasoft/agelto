# ProcurementSucceeded v1.0.0

## Событие

`App\Events\Procurement\ProcurementSucceeded` сообщает, что закупка впервые достигла
положительного исхода: её канонический статус — положительный терминальный либо существует
award с `winner_org_id`.

## Нагрузка

| Поле | Тип | Значение |
|:--|:--|:--|
| `procurementId` | int | Первичный ключ закупки. |
| `registryId` | int | Первичный ключ реестра. |
| `registryNumber` | string | Реестровый номер из head закупки. |
| `canonicalStatus` | string | Канонический статус в момент отправки. |
| `reason` | `status`\|`award` | Факт, который первым выполнил правило исхода. |
| `succeededAt` | Carbon | Момент атомарного захвата исхода. |
| `hasEstimate` | bool | Были ли распознанные сметы в момент отправки. |
| `estimatesCount` | int | Число распознанных смет в момент отправки. |
| `winnerOrgId` | int\|null | Определённый победитель, если известен. |
| `awardId` | int\|null | Award, давший победителя, если применимо. |

## Гарантии и ограничения

- `succeeded_at` захватывается атомарно, поэтому событие отправляется не более одного раза на закупку.
- Dispatch происходит только после фиксации окружающей транзакции БД; при откате ничего не отправляется.
- Поля смет — снимок, а не обещание полноты: сметы могут быть распознаны позже.
- Контракт не объявляет слушателей. Уведомление поставщиков — задача будущего плана.
