# Экономика AI-пайплайна EST-AI

> Реальные цены и лимиты аккаунта провайдера зеркалятся в Brain по решению владельца D89. Публичная
> версия ("как считается стоимость", без чисел) — `docs/03_Dev/llm-providers.md` §Учёт стоимости.

## 1. Тарифы активных маршрутов (config/ai.php, июль 2026)

Цены Gemini Standard tier, $/1M токенов; `cached_per_1m` — implicit/explicit cache-hit; лимиты —
на ОДИН запрос (D29, действуют даже через Files API):

| Модель | Роль в пайплайне | in | out | cached | max MB/запрос | max стр./запрос | EOL |
|---|---|---:|---:|---:|---:|---:|---|
| `gemini-2.5-flash-lite` | скрининг, discovery оконного пути | 0.10 | 0.40 | 0.01 | 50 | 1000 | 2026-10-16 → `gemini-3.1-flash-lite` |
| `gemini-2.5-flash` | извлечение (паспорт/строки/итоги) | 0.30 | 2.50 | 0.03 | 50 | 1000 | 2026-10-16 → `gemini-3.5-flash` |
| `gemini-2.5-pro` | эскалация при сложности/провале валидации | 1.25 | 10.00 | 0.125 | 50 | 1000 | 2026-10-16 → `gemini-3.1-pro-preview` |

Преемники (закомментированы в `AiRoutingSeeder` до решения владельца о дате переключения):
`gemini-3.1-flash-lite` 0.25/1.50/0.025; `gemini-3.5-flash` 1.50/9.00/0.15;
`gemini-3.1-pro-preview` 2.00/12.00/0.20 (≤200k контекста; >200k у `gemini-2.5-pro` дороже:
2.50/15.00). Источник — `plans/EST-AI/research/E-gemini-research.md` §4, сверить актуальность
цен перед любым бюджетным расчётом (провайдер меняет тарифы).

## 2. Порядок величины стоимости одного документа

- Страница PDF (нативный текст ИЛИ скан — цена одинаковая) = 258 токенов фиксированно (Files API).
- Скрининг: первые 4 страницы (`config('ai.screening.pages')`) × 258 ≈ 1000 input-токенов на
  `flash-lite` ≈ $0.0001/документ — пренебрежимо дёшево, отсеивает большинство нецелевых
  документов до дорогого извлечения.
- Извлечение (row-range путь, документ целиком в кэше): input оплачивается один раз почти
  полностью по полной цене (первый запрос сессии), последующие построчные запросы читают ТОТ ЖЕ
  контекст по цене `cached_per_1m` (implicit caching, ~10% от полной цены при префиксе
  ≥2048 токенов) — экономический смысл row-range пути vs postraничного перечитывания.
- Explicit context cache (не подключён к боевому пути на дату этой сессии — Open risk) добавил бы
  storage-стоимость $1.00/1M ток./час (Flash) / $4.50 (Pro) сверху — не начислялась.
- Batch API (−50%, до 24ч turnaround) — НЕ используется (D7), рычаг зафиксирован на будущее.

## 3. Как посмотреть фактический расход

`ai:cost-report {--days=7}` — таблица по `(provider, model, purpose)` из `prc_ai_llm_calls`:
calls/prompt_tokens/cached_tokens/completion_tokens/cost (в $ и ₽ по курсу
`config('ai.cost_report.rub_per_usd')`, env `AI_COST_REPORT_RUB_PER_USD`, дефолт 90.0 — **курс
статический, не live-котировка**, см. Open question в handoff) + отдельная строка «экономия
кэша» (`cached_tokens × (input_per_1m − cached_per_1m)`).

## 4. Лимиты аккаунта провайдера

Реальная квота запросов в минуту/токенов в минуту (RPM/TPM) на используемом Gemini-аккаунте — НЕ
откалибрована против фактического троттлинга (открытый риск, см. `plans/EST-AI/handoff.md`).
Files API: файл до 2 ГБ на загрузку, квота хранилища 20 ГБ на аккаунт, файл живёт 48 часов после
загрузки (достаточно для цикла скрининг→извлечение одного документа, недостаточно для
долгоиграющих pending-документов — переиспользование `file_uri` ограничено этим окном).

## 5. Что не учтено в текущих расчётах

- Явная стоимость исходящего прокси для доступа к Gemini из РФ (открытый вопрос владельца).
- Реальная просадка/наценка при частой эскалации на `gemini-2.5-pro` (borderline-скрининг, D36) —
  не измерялась на боевом трафике.
- Windowed-путь (D30) для гигантских документов делает МНОГОКРАТНО больше запросов на один
  документ (discovery + per-сегмент паспорт/строки/итоги) — суммарная стоимость такого документа
  выше, чем row-range пути пропорционально; точный множитель не откалиброван (зависит от числа
  смет и страниц внутри документа).
