# ADR 0004: результат AI-извлечения не-смет — jsonb, не отдельная таблица

- Status: Accepted
- Date: 2026-07-07
- Источник: `plans/archive/2026.07.07-EST-AI/plan.md` §5 Decision Log, D13; аудит F ось 4

## Context

Сегодня пайплайн извлекает только сметы (`prc_estimates`/`prc_estimate_items`). Требование
универсальности плана EST-AI (D-заголовок Context, пятая итерация) предполагает расширяемость на
другие типы документов в будущем — второй экстрактор с иным результатом (не сметой).

## Decision

Результат AI-извлечения НЕ-сметы хранится как `jsonb` в `prc_ai_analyses.result` (то же поле, где
уже живёт сырой вывод screening/extraction). Generic-таблица под нормализованную витрину результатов
(`ai_extractions` или аналог) НЕ создаётся заранее.

## Consequences

- Плюс: вход/роутинг (`llm_routes`, `LlmRouteResolver`) уже параметризован строкой
  `document_type` — второй экстрактор стартует с этого же шва, без миграции схемы под гипотетическую
  структуру.
- Плюс: избегает преждевременной абстракции (YAGNI) — нормализованная витрина «на все типы
  документов» дорога, пока есть только один тип.
- Минус (принят осознанно): когда появится второй экстрактор, потребуется решение о его собственной
  нормализованной витрине (по аналогии с `prc_estimates`/`prc_estimate_items`) — `jsonb` в `result`
  остаётся источником правды до этого момента, не заменяет её.
