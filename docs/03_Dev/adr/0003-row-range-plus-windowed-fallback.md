# ADR 0003: row-range основной путь извлечения + windowed fallback

- Status: Accepted
- Date: 2026-07-07 (уточнено D30/D40/D42, 2026-07-07/09)
- Источник: `plans/archive/2026.07.07-EST-AI/plan.md` §5 Decision Log, D3, D30, D40, D42

## Context

Извлечение позиций сметы из документа сталкивается с двумя ограничениями: (1) LLM плохо справляется
с длинными таблицами «в один присест» («lost in the middle», разрывы таблиц на границах чанков —
research/E §5); (2) документ может физически не влезать в лимиты провайдера НА ЗАПРОС (Gemini: 50
МБ / 1000 стр. даже через Files API до 2 ГБ, research/L finding 16) и содержать несколько
перемешанных смет.

## Decision

Основной путь — **row-range по кэшированному целому документу**: документ грузится в Files API +
context cache один раз, построчные диапазоны запрашиваются адресуемо (`ChunkSource`/
`RowRangeChunkSource`). У этого пути вообще нет проблемы разрыва страниц (весь документ уже в
контексте) и он дешевле (cached input ~10% от полной цены).

Fallback — **windowed** (сверх лимита провайдера, решает `ExtractionPreflight` preflight ДО upload,
D29): собственный трёхстадийный алгоритм — (1) discovery-проход дешёвой моделью по страничным окнам
находит маркеры границ смет, бэкенд детерминированно (без LLM) склеивает сегменты; (2) per-estimate
извлечение rows-окнами с overlap 1 внутри сегмента; (3) totals по хвосту сегмента.
`WindowedChunkSource` НЕ реализует интерфейс `ChunkSource` (D42) — постраничная адресация discovery
структурно другая, чем row-index-адресация row-range пути; общий 3-методный интерфейс потребовал бы
резинового 4-го метода не по форме данных.

## Consequences

- Плюс: подавляющее большинство документов (укладывающихся в лимит провайдера) идёт по дешёвому и
  структурно простому пути без разрыва страниц.
- Плюс: гигантские мульти-сметные документы (сотни страниц сканов) обрабатываемы — не падают в
  generic `Failed` без объяснения.
- Минус (принят осознанно): два независимых контракта чанкинга (`ChunkSource` и
  `WindowedChunkSource`) вместо одного универсального — `ExtractionOrchestrator` получил второй
  top-level метод `runWindowed()` параллельно `runWholeDocument()` (D43) с собственной
  progress-схемой checkpoint'а.
