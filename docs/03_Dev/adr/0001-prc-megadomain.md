# ADR 0001: таксономия `prc_`-мегадомена

- Status: Accepted
- Date: 2026-07-07
- Источник: `plans/EST-AI/plan.md` §5 Decision Log, D11 (аудит F, вариант b)

## Context

Раннее ТЗ (01 §0.1) описывало 9-префиксную схему таблиц по типу сущности. К моменту аудита схемы БД
(research/F) в коде уже закреплён единый `prc_`-мегадомен (все закупочные сущности: заказы,
документы, сметы, AI-пайплайн, crawling-инфраструктура, площадки, логи — под одним префиксом),
осознанно принятый прошлой сессией и закреплённый канонами `CLAUDE.md`/`.ai/guidelines/glossary.md`.
Аудит нашёл диссонанс: часть raw-индексов/FK ссылалась на имена таблиц из 9-префиксной схемы,
которых физически не существует.

## Decision

Закрепить `prc_`-мегадомен как таксономию таблиц; 9-префиксную схему НЕ возвращать. Исправить только
имена raw-индексов/FK под фактические таблицы + обновить ТЗ §0.1/§0.37. Имена таблиц, включая
`prc_estimate_items`, не переименовывать.

## Consequences

- Плюс: диссонанс «индекс ссылается на несуществующую таблицу» устранён дёшево, пока данных в БД
  нет (`migrate:fresh` ещё дешёвый инструмент на этой стадии проекта).
- Плюс: не сломана уже перенесённая Filament-фаза и вся написанная документация/доки, которые уже
  ссылаются на `prc_`-имена.
- Минус (принят осознанно): один мегадомен без внутренней типизации таблиц по подсхемам —
  навигация компенсируется структурой каталогов (`app/Filament/Resources/Procurement/{Ai,Crawler,
  Platform,Procurements}`) и `database.md`.

## Смежное

- `../database.md` — карта таблиц AI-пайплайна.
- `../architecture.md` — три домена (`Procurement`/`Reference`/`Organization`).
