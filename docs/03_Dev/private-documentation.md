# Закрытая production-документация

Этот документ фиксирует production contract для внутренней документации Agelto. Он определяет
границу до реализации P4.2–P4.5: source `docs/` и generated bytes не являются public-статикой,
а удобство VitePress не создаёт второй, неавторизованный путь чтения.

## Threat model

Основные угрозы — публичный URL или volume с artifact bytes, HTML под авторизацией при открытых
JS/CSS/fonts, traversal/symlink escape, MIME sniffing, кэш после logout или отзыва права, и drift
между image tag и собранной документацией. Контролы должны быть общими для корневой страницы,
вложенной HTML-страницы и каждого manifest asset.

## Build и immutable artifact

- Generator — exact stable VitePress `1.6.4` на frozen pnpm carrier; `@next`, `@latest`, plugins,
  analytics, remote fonts и service worker запрещены.
- Base — `/admin/documentation/`; source — committed `docs/`; production host не запускает build.
- Проверенный output располагается в application image в
  `var/private-documentation/site`, вне `public`, writable `storage` и Compose volumes.
- Build сначала проверяет complete tree, затем публикует только отсортированный manifest
  `{path, mime, sha256}` и соответствующие ему bytes. Symlink, unsafe path, неизвестное
  расширение и remote executable resource отвергаются.
- Проверка выполняется `make documentation:check`: она доказывает два byte-identical build,
  hostile fixtures и placement read-only artifact в application image. Изменение `docs/` — это
  frontend/image input; `prod:deploy:code` для него не является допустимым carrier.

Изменение source documentation требует нового image artifact. Runtime image не содержит Node или
pnpm как production-serving dependency.

## Serving и authorization

Один именованный Laravel GET/HEAD wildcard route владеет HTML, nested pages, CSS, JavaScript, JSON,
SVG/images и fonts. Он требует authenticated user и enum-aware AzGuard permission
`DocumentationPermission::View` для panel `admin` до обращения к filesystem. Controller остаётся
HTTP-only: authorization, locator, `response()->file()` и headers; normalisation, manifest, MIME и
containment принадлежат locator service.

P4.3 регистрирует этот единственный route уже сейчас, но до P4.4 controller возвращает fail-closed
`403` до locator: ни HTML, ни assets не получают временного allow-all окна. P4.4 заменяет заглушку
на enum-aware `DocumentationPermission::View` в явном panel scope `admin` и проверяет final
guest/denial/allow matrix. Route использует canonical web auth и направляет guest к штатному admin
Filament login; контроллер затем вызывает `hasPermission()` с тем же enum для каждого GET/HEAD
artifact до обращения к locator.

Initial role path — только SuperAdmin wildcard. AnalystRole, OperatorRole и roleless authenticated
user не получают bytes. Filament navigation использует ту же permission, но скрытая навигация не
заменяет проверку direct URL. Guest получает стандартный admin login flow, authenticated denial —
403, отсутствующий или unsafe manifest path — 404.

## Path, MIME и browser policy

Locator принимает только manifest member с ASCII known-good path grammar. Он отклоняет percent,
backslash, NUL, empty/dot/dot-dot segments и расширение вне closed MIME map; после `realpath` путь
должен оставаться под configured root. Unknown content не служится как
`application/octet-stream` inline.

Каждый успешный ответ, включая assets, задаёт exact manifest MIME, `Cache-Control: private, no-store`,
`X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` и
`Cross-Origin-Resource-Policy: same-origin`. Нет `public`, `s-maxage`, `immutable` или ETag branch.
HTML дополнительно получает restrictive CSP, блокирующий remote default/connect/object/frame/form/base
surfaces. Public/static/Nginx aliases, signed URLs, `X-Accel-Redirect` и alternate asset middleware
не являются допустимыми serving paths.

VitePress 1.6.4 build содержит inline bootstrap scripts и style attributes, поэтому текущая CSP
разрешает inline script/style только при `default-src 'self'`; remote origins остаются закрытыми.
Изменение этого allowance требует повторной проверки against generated artifact.

## Владельцы и доказательства

| Owner | Ответственность | Required proof |
|:--|:--|:--|
| P4.2 | build, verifier, manifest и image boundary | deterministic tree/manifest, no public or writable runtime artifact |
| P4.3 | locator, route и response policy | traversal/containment/MIME/404 corpus и header parity |
| P4.4 | permission enum и Filament discovery | SuperAdmin allowed; Analyst/Operator/roleless/direct URL denied as specified |
| P4.5 | adversarial acceptance | guest/403/404 body-leak checks, browser assets, no-store and image inspection |
| P12 | release rehearsal | clean-host build/deploy/recovery proves image-contained docs without host generation |

## P4 acceptance carrier

`make documentation:acceptance` runs the item-owned carrier: focused Pest access/traversal/MIME
datasets, deterministic documentation build and image checks, then the isolated Chromium
clean-install flow. It requires `E2E_ADMIN_EMAIL` and `E2E_ADMIN_PASSWORD_FILE`; the runner is
started from a clean committed candidate so it never reuses an operator's Compose project, database,
volumes, cookies or browser cache. Browser evidence covers root/nested artifact loading, direct
representative MIME requests, every observed documentation response's `private, no-store` header,
no console/page/CSP failures and the post-logout direct reload denial.

The release contract is D7, D17, D18, D26, D27 and APP-07–APP-10 of
`plans/2026.08.09-RELEASE-READINESS/root/contracts/release-readiness-v1.md`. Any change to the
generator, storage, authorization, MIME/cache or browser policy requires evidence and a superseding
decision; it is not an implementation convenience.
