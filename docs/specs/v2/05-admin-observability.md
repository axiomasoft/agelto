# ТЗ v2 · 05 — Админка и наблюдаемость

> Стек админки — Filament (по канону проекта). Схема — `01-database.md`. Настройки провайдеров/матрицы — `04-llm-providers.md`.

## 1. Роль

Внутренний инструмент операторов: управление краулерами, промптами и LLM-роутингом; контроль пайплайна; ревизия закупок/смет; сбор датасета. Публичного контура нет; доступ — только авторизованные операторы с ролями.

## 2. Filament-ресурсы

### 2.1 Краулинг
- **Платформы / реестры**: справочники, шаблоны URL карточек, лимиты выдачи.
- **Краулеры (профили)**: режим (fresh/archive), метод + fallback, фильтр, расписание, опции колонок; действия — «запустить»/«пауза».
- **Прогоны (runs)**: статус, курсор, heartbeat, статистика по стадиям; таймлайн заборов (`prc_fetches`) со ссылками на сырые CSV; ручное возобновление/сброс курсора.
- **Прокси**: пул, статус, счётчик ошибок, журнал проверок (креды — маскированы).
- **Ignore-правила**: справочник фильтров отсева.

### 2.2 Закупки
- **Реестр закупок**: таблица с фильтрами (реестр, статус, даты, НМЦК, ОКПД2, заказчик, регион); полнотекстовый поиск (`prc_search`); ссылка на карточку источника.
- **Карточка закупки**: текущее состояние + **таймлайн событий** (`prc_events`) + список редакций (`prc_revisions`) со снапшотом на дату и диффом; вкладки детального слоя — позиции (`prc_items`), финансирование по годам (`prc_financing`), роли/участники (`org_procurement_parties`), протоколы (`prc_protocols`), результаты/победитель (`prc_awards`/`prc_bids`), разъяснения (`prc_clarifications`), отмены (`prc_cancellations`).
- **Документы закупки**: версии (хэш, размер, дата), дерево дочерних (архивы), статусы пайплайна, ссылки на оригинал/подготовленный файл.
- **Организации** (`org_organizations`): реестр по ИНН/ОГРН, все закупки организации по ролям (`org_procurement_parties`).
- **Классификаторы** (`ref_okpd2`/`ref_ktru`/`ref_okved2`/`ref_kbk`): просмотр справочников, статус загрузки версий.

### 2.3 AI-анализ и сметы
- **Анализы**: скрининг/извлечение по версии документа — статус, тип, результат, провайдер/модель, ошибки; ручной перезапуск стадии.
- **Сметы**: паспорт + дерево разделов/позиций/ресурсов/итогов; индикатор полноты (`rows_expected/extracted`, `validation_status`); сырой ответ LLM; отметка «проверено оператором» (правка → в датасет).
- **Промпты**: редактор `prc_ai_prompts` (ключ, шаг, версия, приоритет, активность).
- **LLM-роутинг**: матрица `prc_ai_routes` (тип × шаг → провайдер+модель), флаг shadow; провайдеры (`prc_ai_providers`).
- **Датасет / eval**: golden-примеры, запуски eval с метриками, сравнение провайдеров (в т.ч. shadow).

### 2.4 Настройки (spatie-settings)
Рантайм-настройки без деплоя: активный провайдер по умолчанию, лимиты троттлинга, пороги дробления краулинга, ретеншн сырых артефактов.

## 3. Метрики

- **Краулинг**: заборов/мин, найдено/новых/обновлено, ошибок; глубина очередей; детект «тихого cap» (повтор блока); отставание fresh-скана.
- **Документы**: скачано/подготовлено/заскринено/разобрано; доля `failed` по стадиям; доля `unknown` в скрининге.
- **LLM**: вызовы, токены (prompt/completion/cached), стоимость по провайдеру/модели/цели; доля cache-hit; латентность; полнота извлечения (`rows_expected/extracted`).
- **Прогоны**: длительность, возобновления, recovery оборванных.

Хранение метрик — из партиционированных `prc_fetches` / `prc_ai_llm_calls` + агрегаты (аналог v1 `crawler_analytics` по суткам/стадиям); дэшборды в Filament-виджетах.

## 4. Алерты

- Очередь стадии выше порога — замедлить диспатч.
- Подряд N пустых/повторных блоков — вероятный cap/блок источника, переключить прокси/остановить.
- Всплеск `failed`/`unknown` на стадии — дрейф классификатора или редизайн источника (смена набора колонок CSV).
- Расхождение полноты сметы выше допуска — на ручную ревизию.
- Рост стоимости LLM выше бюджета — уведомление.
- Прогон без heartbeat дольше порога — recovery.

## 5. Журналы

- **Доменный журнал** (`prc_events`) — источник истины истории закупок; не смешивать с операционным.
- **Операционный журнал** (аналог v1 `sys_logs`): вехи прогонов, стадии документов, ошибки с trace, полиморфная привязка к сущности.
- **Аудит операторов** (опц. spatie/activitylog) — кто из операторов что поменял в админке; отдельно от доменной истории.

## 6. Наблюдаемость инфраструктуры

- Horizon — очереди, throughput, failed-jobs, supervisor'ы.
- Health-checks (spatie/laravel-health): БД, Redis, object storage, доступность браузерного сервиса (`/v1/health`), heartbeat планировщика.
- Smoke-контроль актуальности источника (02 §6.2) — отдельная проверка с алертом.
