# Глоссарий

Единственный источник канона имён и терминов домена — `03_Dev/**` ссылается сюда, не копирует.
Технический канон для кода — `.ai/guidelines/glossary.md`; здесь те же термины объяснены
бизнес-языком.

## Основные сущности

| Термин | Что это |
|---|---|
| **Platform** (площадка) | Источник закупок — портал, с которого система собирает данные (ЕИС и другие). |
| **Crawler** (краулер) | Настроенный профиль обхода одной площадки — что и как собирать. |
| **CrawlerRun** (прогон) | Один запуск краулера: началось, идёт, завершилось (успешно/с ошибкой). |
| **Procurement** (закупка) | Извещение о закупке — карточка на площадке со всеми своими данными: лоты, участники, документы. |
| **Document** (документ) | Файл, приложенный к закупке (извещение, документация, смета, протокол и т.п.). |
| **DocumentVersion** (версия документа) | Конкретный скачанный файл документа — если файл на площадке заменили, версия новая, документ тот же. |
| **Ai\Analysis** (AI-анализ) | Одна сессия работы AI над версией документа — скрининг ИЛИ извлечение. |
| **Estimate** (смета) | Распознанная и структурированная смета: паспорт (шапка), строки, итоги. Один документ может содержать несколько смет. |
| **Lot / PurchaseItem** (лот / позиция закупки) | Не путать со сметой: это позиции самого объекта закупки (что закупается), а не строки сметы. |
| **ProcurementRevision** (редакция) | Снапшот состояния закупки на момент обнаружения изменения — фиксирует историю редакций извещения. |
| **ProcurementEvent** (событие) | Неизменяемая запись в журнале закупки: что именно изменилось и когда. |

В речи и в интерфейсе допустим бытовой язык («извещение», «вложение», «смета»); эта таблица —
канон для точных формулировок и для сверки со статусами (`04_Operators/reference/statuses.md`).

## Изменения терминов

Продукт разрабатывался дважды (v1 → v2, текущая версия). Часть терминов сменилась при переходе;
если встречается старое название в архивных материалах — вот соответствие:

| v1 (устарело) | v2 (текущий канон) |
|---|---|
| Link | Procurement (закупка) |
| LinkAttachment | Document (документ) |
| DocumentAnalysis | Ai\Analysis (AI-анализ) |
| Profile | Crawler (краулер) |
| Run | CrawlerRun (прогон) |
| «Смета» / Smeta (как идентификатор в коде) | Estimate — в идентификаторах «Smeta» не используется, только в бизнес-тексте |

## OCDS-термины и оспариваемые поля

Термины из внешнего аудита по отраслевому стандарту OCDS (Open Contracting Data Standard) и поля,
чьё назначение не всегда очевидно из названия.

- **Projection** (свёртка) — `Procurement` хранит текущее состояние закупки; история редакций и
  событий (`ProcurementRevision`/`ProcurementEvent`) — источник, из которого это состояние
  складывается (см. `03_Dev/adr/0007-ocds-as-exchange-layer.md`).
- **Provenance** (происхождение данных) — где и когда родилась запись: какой прогон краулера,
  какой файл-источник, с какими параметрами прошёл AI-вызов. Хранится отдельными колонками по
  оспариваемым полям, не отдельной подсистемой на все факты (см.
  `03_Dev/adr/0008-thin-provenance-slice.md`).
- **quality flag** (флаг качества) — автоматическая оценка полноты и корректности извлечённой
  сметы (`Valid`/`Suspicious`/`Invalid`), которую выставляет пайплайн ДО того, как смету увидит
  оператор. Не путать с операторским ревью AI-анализа (`review_status`) — это два разных статуса о
  разных вещах.
- **Notice** (извещение) — не отдельная сущность, а синоним `Procurement` в терминологии 44-ФЗ и
  OCDS.
- **Registry number** (реестровый номер) — номер извещения о закупке в реестре ЕИС по 44-ФЗ.
- **ETP number** (номер ЭТП) — второй номер закупки на электронной торговой площадке по 223-ФЗ;
  поле в схеме уже есть, но источник данных для него пока не подключён.
