# Онбординг клиента — Agelto

> [!note] Назначение
> Путь клиента от регистрации до первого лида (Time-to-Value). Главная митигация churn-риска ([[Risk_Register (Agelto)]] R-3). Требования — [[BRD (Agelto)]] §4.3, §7.

---

## Целевая метрика

**TTV (Time-to-Value): ≤ 3 рабочих дня** от регистрации до первого верифицированного лида в кабинете. Дольше — растёт риск отвала до оплаты.

---

## Процесс

| Шаг | Действие | Кто | SLA |
|:---|:---|:---|:---|
| 1. Регистрация | Аккаунт + 2FA, выбор тарифа (или пилот) | Клиент | — |
| 2. Загрузка Коллекции | Импорт прайс-листа (Excel/CSV) → валидация (F-MATCH-1) → отчёт об ошибках | Клиент (Commercial Director) | — |
| 3. Чистка данных | Исправление невалидных строк по отчёту; при Setup Service — делает Agelto | Клиент / Agelto | 1 день |
| 4. Индексация | Embeddings строятся в фоне, статус «Коллекция обновляется» | Система | часы |
| 5. Настройка фильтров | Регионы, ОКПД2, ценовой диапазон, порог Score | Клиент + Agelto | 1 день |
| 6. Первые матчи | Прогон по свежим тендерам, премодерация ([[Lead_Verification]]) | Система + Analyst | 1 день |
| 7. CRM-подключение | Bitrix24/amoCRM webhook (после пилота — F-CRM-1) | Agelto | — |
| 8. Обучение | Демо кабинета менеджерам клиента | Customer Success | 1 сессия |

## Setup Service (платный, F-MON-4)

Шаги 2–8 «под ключ»: чистка прайс-листа, настройка фильтров, CRM-интеграция, обучение персонала. Для Enterprise — обязательная рекомендация.

## Не реализовано / открыто

- Self-service onboarding UI — после пилотной фазы (на пилоте шаги ведёт команда вручную)
- Кто выполняет роль Analyst на шаге 6 — [[Открытые вопросы (Agelto)]] P6
