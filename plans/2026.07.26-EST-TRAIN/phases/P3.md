# P3 — Фабрика представлений документа (gsfx, LibreOffice, архивы, OCR)

## Phase Context

Сегодня подготовка понимает только zip, `xls/xlsx`→PDF (PhpSpreadsheet+Mpdf) и картинки как есть,
а результат подготовки несёт ОДНА колонка `prc_document_versions.prepared_storage_path` — одно
представление на версию, без метаданных о происхождении. Реальный корпус приносит `.gsfx`,
`.doc/.docx` и сканы (D7), а бенчмарк P6 обязан сравнивать НЕСКОЛЬКО представлений одного
документа. Поэтому фаза сначала меняет НОСИТЕЛЬ (таблица `prc_document_representations`, D25:
kind + путь + измеримые признаки + `meta`), а потом наполняет фабрику конвертерами: ГрандСмета,
LibreOffice, компактная текстовая сетка, архивы 7z/RAR, OCR сканов.

Два класса лимитов разведены явно (D26): лимит ИНСТРУМЕНТА подготовки живёт в
`config('ai.prepare.*')` и означает «эта стратегия не годится, пробуем следующую», лимит
ПОТРЕБИТЕЛЯ живёт в `config('ai.capabilities.<model>')` и означает «это представление не влезает
в этот маршрут». `unprocessable` наступает, только когда ни одна стратегия не произвела ни одного
представления. Числа существующих порогов фаза НЕ меняет.

Ключевая ценность фазы — `.gsfx`: ZIP с `Data.xml` ГрандСметы даёт структурную модель без единого
LLM-вызова и бесплатный gold (D2). Системные бинари ставятся в ЕДИНЫЙ образ `docker/php/Dockerfile`
(D23) одним item'ом с гейтом версий. Фаза завершена, когда каждый формат корпуса имеет хотя бы
одно валидное представление, отсутствие представления даёт честный `unprocessable` с причиной, а
потолок локального OCR зафиксирован числом, а не мнением.

Фаза исполняется В КОНТЕЙНЕРАХ (как P2): `php artisan`, Postgres `agelto_test`, пересборка образа.
Новых composer-зависимостей не вводится; новые системные пакеты — только в P3.2.

**Scope Included:** таблица `prc_document_representations` + enum `RepresentationKind` + репозиторий
+ резолвер представления + удаление `prepared_storage_path`; превращение `DocumentPreparer` в
цепочку стратегий (D28); новые причины `UnprocessableReason` (D27); системные бинари в
`docker/php/Dockerfile` + команда-доктор (D23/D24); стратегии `GsfxStrategy`, LibreOffice-конвертер
(`doc/docx`→PDF и fidelity `xls(x)`→PDF), компактная текстовая сетка `text_grid`, 7z/RAR в
`ArchiveStrategy`, OCR-представление сканов; замер потолка OCR на скан-эталонах; правка
`docs/specs/v2/03-document-pipeline.md` §3.3 под новый контракт; Pest-тесты на всё перечисленное.

**Scope Excluded:** ВЫБОР представления для отправки в LLM и правило по типу источника (P6, D3) —
здесь только «умеем произвести» и дефолтная политика резолвера, повторяющая сегодняшнее поведение;
построение gold и парсинг структурной модели ГрандСметы В ЭТАЛОНЫ (P5 — P3 только производит
представление); ЛЮБАЯ правка `prc_estimate*` и решений по схеме смет (P4, D10); изменение чисел
существующих порогов `ai.prepare.*` и лимитов `ai.capabilities.*` (D26); маршрутизация моделей и

`storeOrUpdate(DocumentVersion $version, RepresentationKind $kind, array $attributes):
DocumentRepresentation` (`updateOrCreate` по паре версия+kind — идемпотентность повторной
генерации), `find(DocumentVersion $version, RepresentationKind $kind): ?DocumentRepresentation`,
`allFor(DocumentVersion $version): Collection`. `RepresentationResolver::forLlm(DocumentVersion
$version): array{storagePath: string, disk: string, extension: string, mime: string}` — ДЕФОЛТНАЯ
политика повторяет сегодняшнее поведение байт-в-байт: есть представление `pdf` → отдать его как
`pdf`/`application/pdf`, иначе оригинал версии; порядок политики выносится в именованную константу
`DEFAULT_PRIORITY` с комментарием «правило выбора по типу источника и модели — P6, D3». Контракт
`PreparationStrategy::process()` меняет возвращаемый тип с `void` на `bool` — «произвела ли
стратегия представление»; докблок интерфейса фиксирует смысл: `false` = «эта стратегия не годится,
цепочка идёт дальше», терминальный `unprocessable` стратегия ставит САМА только когда исход
терминален по существу (zip-бомба, пароль). `DocumentPreparer::prepare()` идёт по
`config('ai.prepare.strategies')` и вызывает КАЖДУЮ подошедшую по `canProcess()`, пока одна не
вернёт `true` или пока документ не стал терминальным; ни одна не вернула `true` и документ не
терминален → `unprocessable(conversion_failed)` с перечислением испробованных стратегий в
`last_error`. `PassthroughStrategy` остаётся последней и возвращает `true` (оригинал — валидный
вход). Существующий xlsx size-gate `SpreadsheetStrategy` при превышении теперь возвращает `false`
