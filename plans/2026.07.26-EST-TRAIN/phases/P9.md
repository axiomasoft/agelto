### P9.1 — Экспорт под локальную LLM: реальный вход, отбор по доверию, splits, DPO по `analysis_id`

**Status:** ⛔ Skipped by decision
**Intent:** Довести `ai:dataset:export` до датасета, который training-раннер берёт БЕЗ ручной
доработки: (а) миграция nullable `analysis_id` в `prc_ai_dataset_examples` + его запись
`GoldExampleRecorder`'ом; (б) сервис `DatasetInputBuilder` — ЕДИНЫЙ строитель входа для обоих
форматов, кладущий в `user`-турн ФАКТИЧЕСКИЙ текст представления документа
(`prc_document_representations`), а не ссылку на него; (в) отбор записей по явному основанию
доверия (`source='deterministic'` ИЛИ непустой `verified_at`); (г) маркировка каждой строки
`split` из `estimates/eval-splits.json`; (д) DPO-пара, резолвящая предшественника через
сохранённый `analysis_id`, с тем же входом и переключателем формы `--dpo-schema`; (е) манифест
прогона со счётчиками, причинами пропусков, `prompt_version_set` и `rules_hash`.
**Why:** Сегодняшний экспорт непригоден для обучения по двум независимым причинам, обе
зафиксированы в докблоке самой команды. Первая: `user`-турн несёт ССЫЛКУ на документ
(`document_version_id=…, storage_path=…`) и примечание «текст не подставлен — распознавание ещё не
реализовано», RAG:— (repo-grounded: `app/Console/Commands/Ai/DatasetExportCommand.php:192-204`);
после P3 распознавание РЕАЛИЗОВАНО и его результат лежит в `prc_document_representations` — долг,
записанный EST-AI как deferred, здесь и закрывается, иначе датасет учит модель предсказывать JSON
из строки с идентификатором. Вторая: DPO-пара ищет предшественника через АКТИВНЫЙ анализ версии
документа, потому что `analysis_id` не хранится, и при нескольких gold-версиях одной версии
документа резолвит один и тот же анализ для каждой — прямая констатация докблока (там же, строки
36–44), а несколько версий gold на документ в этом плане — норма, а не экзотика (HITL P8.3 создаёт
новую версию на каждую правку). Дальше — отбор: без явного основания доверия в экспорт уедет
`source='llm'`-запись, которую человек не подтверждал, и «эталон» станет догадкой модели о себе
самой (то же возражение, что D2/D43). Маркировка `split` нужна потому, что holdout уже
детерминированно определён для тюнинга промтов (D63), и обучающийся на нём локальной моделью
holdout перестаёт быть holdout'ом. Имена полей обоих форматов менять не нужно — они уже совпадают
с каноном TRL/Axolotl/Unsloth, RAG:✅ 2026-07-27 (`findings/rag-P9-export-2026-07-27.md`).

**Implementation Rules:** **Сигнатура:** `ai:dataset:export {--format=sft : sft|dpo}
{--task=extraction} {--split=all : all|tune|holdout} {--source=* : ограничить значениями source}
{--dpo-schema=conversational : conversational|standard} {--disk=} {--path=}`; существующие
`--disk`/`--path`/`--task` и дефолтный путь не меняются. **Основание доверия (D76):** запись
экспортируема ⟺ `source === 'deterministic'` ИЛИ `verified_at !== null`. Всё остальное
ПРОПУСКАЕТСЯ и считается по причине `not_trusted`; молчаливого включения нет. **Отбор:** SFT —
ПОСЛЕДНЯЯ по `version` экспортируемая запись на пару (`document_version_id`, `task`) (старые версии
несут противоречащий эталон и в обучение не идут); DPO — каждая экспортируемая запись с
`source='corrected'` и непустым `analysis_id`. **Вход (`DatasetInputBuilder`) — ОДИН носитель для
обоих форматов:** `ComposedPrompt` считается ОДИН раз на прогон
(`PromptComposer::compose(PromptStep::ExtractionRows, [RowsChunkResponse::class])`);
`user`-содержимое = строка задачи (какую именно смету извлечь: `ordinal` и `estimate_number`, если
он есть) + разделитель + ТЕКСТ представления. Представление выбирается по
`config('ai.dataset_export.representation_priority')` (дефолт `['text_grid', 'text']`) — первое
существующее для версии документа, у которого `mime` начинается на `text/`; `structured_xml`
исключён ЯВНО (в проде `.gsfx` вообще не уходит в LLM — это вход детерминированного парсера, и
обучение на нём учит неиспользуемому навыку), бинарные kind'ы (`pdf`, `pdf_alt`, `pdf_ocr`)
исключены по построению фильтра `text/`. Нет подходящего представления → пропуск с причиной
`no_textual_representation`. Текст длиннее `config('ai.dataset_export.max_input_chars')` (дефолт
**300000**, число задано ТЗ ДО данных) → пропуск с причиной `input_too_large`. **DPO:** `rejected`
— `estimates[]` из `result` анализа `analysis->parent_analysis_id` записи; нет `analysis_id`, нет
родителя или у родителя пустой `result` → пропуск с соответствующей причиной. Резолв через
АКТИВНЫЙ анализ версии документа ЗАПРЕЩЁН — это и есть чинимый дефект. `--dpo-schema=conversational`
(дефолт): `prompt` — список сообщений (`system` + `user` из того же строителя), `chosen`/`rejected`
— списки из одного `assistant`-сообщения; `--dpo-schema=standard`: те же три поля плоскими
строками (`prompt` = `systemPart` + разделитель + `user`-часть). **Строка SFT** — форма не
меняется: `{"messages":[system,user,assistant]}`, `assistant` — `{rows, incomplete_items}` того же
контракта `RowsChunkResponse` (§3.2). **Маркировка:** каждая строка несёт ключ `meta` с
`fixture_code` (если запись связана с эталоном), `split` (`tune`/`holdout`/`none` — по коду из
`estimates/eval-splits.json`; файла нет → `none` у всех + предупреждение в сводке), `source`,
`trust` (`deterministic`|`human`), `representation_kind`, `document_version_id`, `example_version`.
**Фильтр `--split`** отбрасывает строки с другим значением и считает их отдельно. **Манифест**
(`<путь>.manifest.json`) дополняется: `schema` (`sft-messages` либо `dpo-conversational`/
`dpo-standard`), `exporter_version` (константа команды, поднимается при любой смене формы строки),
`examples`, `skipped` (карта причина→счётчик), `by_source`, `by_split`, `by_representation_kind`,
`prompt_version_set`, `rules_hash`, `plan` (`2026.07.26-EST-TRAIN`, `D76`/`D77`), `task`,
`generated_at`, `sha256`. **Порядок строк** — `document_version_id ASC, version ASC`, чтение
`cursor()` с `with()` (N+1 запрещён). **Сводка в консоль** — экспортировано N · пропущено по
причинам построчно · путь файла и манифеста; `SUCCESS` даже при пропусках (пропуск — это норма
корпуса, а не сбой), `FAILURE` — только на неизвестном `--format`/`--dpo-schema`/`--split`.
**Code Guidance:** Chat-template целевой модели (`<|im_start|>` Qwen3 и любая другая разметка
токенизатора) в экспорт НЕ попадает — его применяет training-раннер, RAG:✅ 2026-07-27
(`findings/rag-P9-export-2026-07-27.md` §3 п.4); вшитая разметка протухнет при первой смене модели

DPO разъедется с SFT при первой правке — ровно тот дрейф, против которого написан
`plan-protocol` §3. Резолв предшественника DPO через `Analysis::active()` — запрещён: это дефект,
