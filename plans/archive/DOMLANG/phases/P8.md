# P8 — Lifecycle-map и state machines единым документом

## Phase Context

Закрывает валидную находку аудита: слова `status`/`stage`/`state`/`step` живут на нескольких осях
одновременно, а сводного документа нет. Рефакторинг **не нужен** — оси уже разделены в коде; не
хватает одного канонического справочника. Фаза **docs-only**: правка любого `app/`/`database/`/
`tests/` = дефект.

Пять осей состояния (`verified:✅ 2026-07-10`, `findings/P8-status-writers.md`) — и они **НЕ
однородны**, в этом суть дизайна: `ProcurementStatus` (**7** кейсов после удаления `Announced` в
P2.1/D16) — **не guarded-FSM**, статус целиком задаёт `StatusMappingService::resolve()` по этапу
ЕИС, внутренних transition-гардов нет (D35); `DocumentStatus` (8) — guarded pipeline-FSM, **уже
нарисован** в Д1 (`document-pipeline.md:16-33`), дублировать запрещено (D34); `AnalysisStatus` (5)
+ ортогональный `AnalysisStep` (2) — guarded FSM, диаграммы нет; `RunStatus` (5) — guarded FSM
(единственный писатель `CrawlerRunManager`), диаграммы нет; `PipelineStage` (3) — стадия-маршрут,
не статус. Ни у одного enum'а нет `allowedTransitions()` — рёбра берутся из код-сайтов присваивания,
не из воображения.

Второй Deliverable — `entity-lifecycle-map`: кто создаёт сущность впервые, кто мутирует, кто только
дописывает дочерние, что есть **повтор** vs **новая ревизия** (`prc_revisions`, дедуп `snapshot_hash`)
vs **новая версия документа** (`prc_document_versions.content_hash`). Путаница revision ⇄ document
version — реальный риск (Phase Context аудита), обе оси дедупликации независимы (§5 findings).

**Завершение фазы:** создан `docs/03_Dev/state-machines.md` (5 осей, из них 3 новые диаграммы +
ссылка на Д1 + раздел «это не FSM») и `docs/03_Dev/entity-lifecycle-map.md`; каждое ребро/факт
анкорено на процитированный код; частичные диаграммы (Д1/Д2/Д4) не продублированы, а связаны
ссылкой; `mermaid` парсится (нотация `Class.method()`, не `Class::method()`).

**Ловушка:** `mermaid stateDiagram-v2` трактует `:` как разделитель метки состояния — `Class::method()`
ломает парсер. Использовать `Class.method()` (прецедент — единственная существующая stateDiagram Д1
уже так делает, `verified:✅`; workaround зафиксирован в `plans/archive/2026.07.07-EST-AI/handoff.md`).

**Scope Included:** `docs/03_Dev/state-machines.md` + `docs/03_Dev/entity-lifecycle-map.md`.
**Scope Excluded:** изменение enum'ов/кода/тестов/миграций; дублирование Д1/Д2/Д4; введение
transition-методов в enum'ы; рисование не-анкорённых рёбер.
