# RAG — лимиты Gemini для документов (2026-07-26)

> Слой 1 (`plan-protocol` §16): внешняя фактура, проверенная в ходе авторинга плана.

## Запрос

Можно ли загрузить крупный PDF (сотни МБ) через Files API один раз и затем в запросах
анализировать только его отдельные страницы/куски — то есть существует ли параметр диапазона
страниц у document understanding?

## Ответ (Perplexity → ai.google.dev/gemini-api/docs/document-processing, проверено 2026-07-26)

| Факт | Значение |
|:--|:--|
| Files API: размер файла | до 2 ГБ на файл, 20 ГБ на проект, хранение 48 ч |
| PDF на ЗАПРОС | до 50 МБ **или** 1000 страниц — предел применяется и к inline-данным, и к `fileUri` из Files API |
| Параметр диапазона страниц (`start_page`/`end_page` и аналоги) | **не документирован — отсутствует** |
| Модель поведения | документ анализируется целиком в контексте запроса (текст, изображения, таблицы) |
| Официальный обходной путь | разрезать PDF на меньший файл с нужными страницами, загрузить производный файл и промптить по нему |
| Несколько PDF в одном запросе | допустимо, если суммарно влезает в контекстное окно и каждый PDF в своих лимитах |

## Что из этого следует для плана

1. **Реплика владельца «грузим 500 МБ и анализируем куски» технически невыполнима.** Загрузка
   пройдёт (2 ГБ лимит хранения), но любой запрос по такому `fileUri` упрётся в 50 МБ / 1000
   страниц — и нет способа попросить только страницы 300–350.
2. **Нарезка на нашей стороне обязательна** — ровно то, что уже зафиксировано в EST-AI (D28:
   `qpdf` вместо FPDI; D29: preflight против capability-матрицы ДО первого upload; D30: оконный
   путь с discovery-паспортом). Эта разведка подтверждает решение, а не отменяет его.
3. **«Дёшево по кускам» достигается кэшем**, а не частичной загрузкой: документ, влезающий в
   один запрос, кладётся в context cache, и построчные диапазоны (row-range, EST-AI D3)
   запрашиваются по кэшированному префиксу со скидкой на cached input. Документ, не влезающий,
   идёт оконным путём по физически нарезанным окнам.
4. **Практический вывод для корпуса:** `Смета картинками.pdf` (132 МБ) — заведомо оконный путь,
   и именно он должен быть в эталонах как крайний случай (см. `corpus-recon-2026-07-26.md`).

## Ограничение достоверности

Проверка сделана 2026-07-26 против текущей документации провайдера. Линейка Gemini 2.5 имеет
EOL 2026-10-16 (EST-AI D27) — лимиты нужно перепроверить при переходе на 3.x, до фиксации
финального ADR по формату входа (фаза P6).
