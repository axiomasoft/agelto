## 4. Кандидаты сценариев сортировки/фильтрации (вход теста б3, утверждение — P5.3)

- **GAP-2** — сортировка/фильтр позиций по доле категории прямых затрат (ОТ/ЭМ/МАТ) — НОВАЯ
  величина.
- **GAP-8** — фильтр смет по редакции/дате нормативной базы (устарела ли смета относительно
  текущего приказа) — НОВАЯ величина.
- **Класс P5.2** (уже в схеме, не пишется — фикс записи, НЕ новое поле): сортировка по
  `unit_price_base`/`total_price_base` (сравнение базис/текущий уровень); фильтр по применённому
  `index_code` (SR-03); натуральная сортировка по `source_position_number` (номер позиции по
  смете — 100%-я потеря, см. §1); фильтр по `work_type_id` (вид работ, SR-08/09); группировка
  `prc_estimate_totals` по `chapter_number`/`rate` (глава сводного расчёта, SR-11).
- **НЕ кандидат (без названного потребителя)** — сортировка/фильтр по «итогу раздела»: величина
  нигде не хранится и не пересчитывается (см. §3); появление такого сценария потребует либо
  хранимого агрегата, либо вычисляемого представления — решение вне этого item'а (P5.3/долг).

## 5. Подтверждённый состав items P5.2/P5.5

существующей схемы, оба writer-пути) закрывает найденные классы A-run/A-code (18 колонок) и

требующих новой D-записи по D20, не найдено — состав items остаётся как есть.
