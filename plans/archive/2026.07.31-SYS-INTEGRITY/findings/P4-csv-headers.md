# P4-csv-headers — живая проба CSV-выгрузки ЕИС (P4.9)

Слой 1: только факты снятой пробы, без проектных выводов. Полная машинная выжимка —
`artifacts/eis-csv-headers.json`.

## 1. Проба

- **Снято:** 2026-08-05 03:54 UTC (серверная дата ЕИС в имени файла — `05.08.2026`).
- **Канал:** RU-прокси `prc_proxies` id=1 (`185.218.0.130`) — тот же узел, что P4.1; egress
  проверен ДО первого запроса к ЕИС (`ipinfo.io/json` → `185.218.0.130`/`RU`), D3 соблюдён.
- **Инструмент:** MCP Playwright, `browser_run_code_unsafe`, новый browser context с
  `ignoreHTTPSErrors: true` (ЕИС отдаёт цепочку российского УЦ — тот же обход, что P4.1,
  `phases/P4.md` P4.1 Known Deviations), запрос — `context.request.get()`.
- **URL:** боевой, собран РЕАЛЬНЫМ `EisCsvUrlBuilder::buildQueryParams()` на засеянном архивном
  профиле P4.5 (`ЕИС 44-ФЗ — архив 2025 (завершённые)`, `crawler:run-archive`), `options.columns`
  подменён В ПАМЯТИ (не сохранялось в БД) на полный набор 25 флагов колонок раздела 5
  `research/05` — полная строка заголовков, а не только 12 колонок боевого профиля. Полный URL —
  `artifacts/eis-csv-headers.json` → `url`.
- **Ответ:** `200`, `application/download;charset=windows-1251`,
  `attachment; filename="OrderSearch(1-500)_05.08.2026.csv"`, 243192 байт, 500 строк данных.

## 4. Дополнительные находки за пределами четырёх констант

Проба вскрыла три факта, которых `research/05` §3.2 не называл (результат пробы старше
документа, Implementation Rules P4.9 п. 1) — все три поимённо в
`artifacts/eis-csv-headers.json` → `дополнительные_находки`:

1. **Префикс «№» (U+2116) перед реестровым номером** — 500/500 строк блока. Уже виден в сырой
   фактуре P4.1 (`findings/P4-eis-recon.md` §1 факт 8, значение `№0322300059126000708`), но не
   был назван дефектом маппера ни там, ни в `research/05` §3.2/§8. Прямо блокирует резолв
   карточки: `EisCardUrlBuilder::buildUrl()` подставляет `registry_number` в query-параметр
   `regNumber`, а образцы `artifacts/eis-registry-settings.json` `_observed` несут номер БЕЗ
   префикса — необрезанный номер дал бы URL, не совпадающий ни с одной реальной карточкой.
   Тот же класс тихого отказа, что и четыре названных дефекта («резолв карточки» — предмет
   Scope Included этого item'а, не только П-8) → **исправлено в этом item'е**
   (`EisCsvRowMapper::stripRegistryNumberPrefix()`).
2. **`Классификация по ОКПД2`/`ОКПД`/`ОКДП`/`Код позиции` пусты у ВСЕХ 500 строк блока** —
   архивный профиль (завершённые закупки 44-ФЗ) не несёт классификации на уровне листинга
   вообще ни у одной записи в этом срезе. Заголовок колонки подтверждён (раздел 3 выше) — это
   НЕ дефект маппера, а характеристика источника/среза данных. Прямое следствие: real-fixture
   тест `EisCsvRowMapperTest` не может честно утверждать `okpd2_code` непустым на РЕАЛЬНЫХ
   строках этого блока (Known Deviations item'а).
3. **`Идентификационный код закупки` — заголовок БЕЗ суффикса `(ИКЗ)`** (константа `IKZ_COLUMN`
   несёт `Идентификационный код закупки (ИКЗ)`). Вне четырёх констант П-6 — не правится этим
   item'ом, назван в Pending Work.
