Внешние факты собраны отдельно: §7 (Filament v5 — приём файла и динамическое правило, RAG:✅

## 1. Контракт `DocumentAnalyzer` — ровно пять методов, валидации профиля нет

## 3. Механизм, которым дыра закрывается без расфриза §1.2–§1.4

`root/document-analyzer-contract.md` §1.5 (дополнение 2026-07-30, D106) уже ввёл форму для ровно
такого случая: **опциональные capability-интерфейсы типа РЯДОМ с `DocumentAnalyzer`** — ядро
спрашивает `instanceof`, тип без реализации не реализует ничего. Инвариант 4 §1.5: новый
capability-интерфейс заводится ТОЛЬКО с call-site'ом и ТОЛЬКО D-записью.

Первый и пока единственный представитель — `App\Services\Procurement\Contracts\SupportsResultComparison`
(реализован `app/Services/Procurement/Analyzers/Estimate/EstimateAnalyzer.php`, объявление `:31`).
Идиома взята из транспортного домена: `App\Services\Llm\Contracts\{LlmProvider, SupportsFileUpload,
SupportsContextCaching}`.

## 7. Filament v5: как форма принимает файл и как валидируется поле, зависящее от другого

Внешний факт — проверен RAG в день заходa, не по памяти.

- **Запрос:** «Filament v5 — FileUpload без постоянного сохранения (temporary uploaded file);
  динамическое правило валидации, читающее состояние другого поля».
- **Источник:** `mcp__laravel-boost__search-docs` (документация версии, установленной в проекте) →
  `filament/filament@5.x`, `packages/forms/docs/09-file-upload.md` (раздел «Preventing files from
  being stored permanently») и `packages/forms/docs/01-overview.md` (разделы «Validating fields»,
  «Conditionally making a field required», «Field utility injection»).
  URL: <https://github.com/filamentphp/filament/blob/5.x/packages/forms/docs/09-file-upload.md>,
  <https://github.com/filamentphp/filament/blob/5.x/packages/forms/docs/01-overview.md>.
- **Дата проверки:** 2026-07-30. **Вердикт:** оба механизма штатные и версионно-актуальные.
  RAG:✅ 2026-07-30.

1. `FileUpload::make('…')->storeFiles(false)` — «When the form is submitted, a temporary file upload
   object will be returned instead of a permanently stored file path». Ровно то, что нужно: файл не
   ложится вторым путём мимо `Fixture::storagePathFor()`, сервис получает временный файл и сам
   решает, куда и под каким именем его положить.
2. Правила валидации принимают ЗАМЫКАНИЕ с утилитой `Filament\Schemas\Components\Utilities\Get`
   (`required(fn (Get $get): bool => …)`), и документация прямо обобщает: «Using a function is able
   to make any other validation rule dynamic in a similar way». Поле-источник обязано быть `->live()`
   (то же условие, что у зависимого `Select` —
   `findings/filament-dependant-select-2026-07-30.md`), иначе замыкание увидит состояние первого
   рендера.
