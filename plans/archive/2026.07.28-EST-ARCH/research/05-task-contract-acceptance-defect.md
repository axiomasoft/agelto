**Дата:** 2026-07-30 · **Заход:** `plan-design 2026.07.28-EST-ARCH P4.5` (снятие эскалации) ·
**Слой:** 2 (авторский синтез) · **Стоит на:** `phases/P4.md` → P4.5 Completion Notes (разбор
исполнителя), код плагина `swissknifeman/task@0.9.0` (прочитан напрямую, см. §1).

## 1. Механика до корня (перепроверено чтением кода, не по описанию)

Путь `plugin: ~/.claude/plugins/cache/swissknifeman/task/0.9.0/lib/task/`. Три факта, каждый —
строка кода:

1. **`Validation` режется ТОЛЬКО по `·`.** `task_contract.py:87` —
   `_INPUTS_SPLIT_RE = re.compile(r"\s*·\s*")`; она же применяется к полю `Validation` в
   `task_contract.py:387` (`_split_nonempty(validation_text, _INPUTS_SPLIT_RE)`). Нумерованные
   строки `1.`/`2.`/… разделителем НЕ считаются, поэтому все восемь проверок P4.5 схлопываются в
   ОДНУ клаузу `A1`. Проверено: `build()` вернул `clauses=1`.
   RAG:— (repo-grounded: `task_contract.py:87,387`).
2. **Публичность клаузы определяется наличием «внешнего» path-токена в ЕЁ тексте.**
   `task_contract.py:392–393`: `path_tokens = plan_lint.PORTABILITY_PATH_RE.findall(clause)`;
   `scope = "internal" if any(is_external_path(tok) for tok in path_tokens) else "public"`.
   RAG:— (repo-grounded: `task_contract.py:392-393`).
3. **«Внешний» = начинается со `/`, `~`, `../`, `tmp/`.** `task_contract.py:71` —
   `_EXTERNAL_PREFIXES = ("/", "~", "../", "tmp/")`; регексп пути (`plan_lint.py:285-286`) —
   `(?:~/|\.\./|\./|/)?[A-Za-z0-9_.][A-Za-z0-9_.-]*(?:/[A-Za-z0-9_.][A-Za-z0-9_.-]*)+`.
   Класс символов сегмента — `[A-Za-z0-9_.-]`: угловая скобка, фигурная скобка и кириллица в него
   НЕ входят. RAG:— (repo-grounded: `task_contract.py:71`, `plan_lint.py:285-286`).

**Сцепка.** В Validation 4 стояла цитата пути второго корня канона промтов с плейсхолдером домена
в угловых скобках. Совпадение регекспа обрывается на открывающей скобке, не может продолжиться
через кириллицу и **стартует заново с подстроки `/ai/prompts`** — а она начинается со `/` и потому
классифицируется `is_external_path()` как внешний путь. Единственная клауза становится `internal`,
`pre_final` на первом же предикате возвращает `ACCEPTANCE_NOT_PUBLIC`
(`task_contract.py:741-743`: `if not any(entry["scope"] == "public" …)`).

Воспроизведение (на дереве `9ff9527`):

```python
from task import task_contract as tc; from task import plan_lint
c = tc.build(plan_dir=Path('plans/2026.07.28-EST-ARCH'), item_id='P4.5')
tc.pre_final(c)                      # → 'ACCEPTANCE_NOT_PUBLIC'
len(c['done']['public_acceptance'])  # → 1   (восемь проверок — одна клауза)
[t for t in plan_lint.PORTABILITY_PATH_RE.findall(c['done']['public_acceptance'][0]['check'])
   if tc.is_external_path(t)]        # → ['/ai/prompts']
```

**Класс дефекта.** Два независимых дефекта компилятора, наложившиеся друг на друга:

- **(D-1) сплиттер не знает нумерованной формы** — поэтому ОДИН плохой токен обнуляет публичность
  ВСЕХ проверок item'а, а не своей строки. Без этого дефекта блок бы не возник: семь остальных
  строк дали бы `public`, и `any(public)` прошёл бы.
- **(D-2) строковый тест «внешности» применяется к произвольному тексту клаузы**, а не к пути,
  роль которого уже установлена. Докстринг `is_external_path` сам оговаривает это ограничение
  («over a path ALREADY known to be an execution input»), но в §`public_acceptance` он вызывается
  на токенах, вырезанных регекспом из свободной прозы.

Владелец обоих — пакет `swissknifeman/task`, не этот план (`plan-protocol` §11 + скилл
`package-contribution-protocol`: правка vendor-копии из потребителя запрещена). Заведено в
`open-questions.md` → «Незакрытое вне этого плана» как реопен-кандидат туда.

## 2. Предложенный в `Pending Work` фикс НЕ работает (проверено)

`Pending Work` P4.5 и `handoff.md` предлагали заменить угловые скобки на фигурные либо на
заглавный плейсхолдер. Обе формы проверены прямым прогоном регекспа и **обе оставляют блок**:
дело не в скобках как символах, а в том, что ЛЮБОЙ символ вне класса `[A-Za-z0-9_.-]` закрывает
сегмент, и совпадение начинается заново со слеша перед `ai` — то есть с абсолютного пути.

| Кандидат (форма цитаты пути в Validation) | Внешние токены | Годен |
|:--|:--|:--|
| исходная, плейсхолдер в угловых скобках | `['/ai/prompts']` | ✗ (это и есть блок) |
| плейсхолдер в фигурных скобках (предложение `Pending Work`) | `['/ai/prompts']` | ✗ |
| заглавный плейсхолдер в угловых скобках (предложение `Pending Work`) | `['/ai/prompts']` | ✗ |
| точка-мост вместо скобок (`.домен.` в ERE) | `[]` | ✓, но шаблон нечитаем |
| **`-cF` по фрагменту без второго слеша (`домен>/ai`)** | `[]` | **✓ выбрано** |
| **`-cF` по формулировке («обоих корней»)** | `[]` | **✓ выбрано** |

Практический вывод для будущих заходов: **предсказывать вердикт компилятора «на глаз» нельзя** —
форма проверяется одной командой (§4), и только она является доводом.

Отдельная ловушка, найденная при подборе: `grep -cF 'обоих корней канона'` даёт **0** на уже
исправленном дереве — фраза разорвана переводом строки между строками 34 и 35
`docs/03_Dev/admin-panel.md`, а `grep` построчный. Поэтому в гейт ушёл фрагмент без переноса
(`обоих корней`), проверенный на обоих деревьях.

## 3. Что именно измеряет новая форма Validation 4

Требование к переформулировке было жёстким: **не ослабить гейт** (иначе это подгонка под
результат, прецедент D89 и класс F1 этого плана). Сверка «до / после»:

| | Исходная форма | Новая форма |
|:--|:--|:--|
| Что утверждает | в файле есть либо фраза «оба корня», либо цитата пути второго корня | в файле есть И фрагмент цитаты второго корня, И формулировка «обоих корней» |
| Ветка «оба корня» | **никогда не срабатывала** — в файле стоит «обоих корней» (склонение), а `grep` буквален | покрыта фрагментом `обоих корней` |
| Исход на `<base>` = `5d8b4f3` | красный (пусто) | красный (`0` и `0` — проверено) |
| Исход на item-коммите `eeb519d` | зелёный | зелёный (`1` и `1` — проверено) |
| Логика | дизъюнкция (достаточно одной ветки) | конъюнкция (нужны обе) |

То есть новая форма **строго сильнее**: две обязательные проверки вместо одной достаточной, и
мёртвая ветка исходного шаблона заменена живой. Ослабления нет ни по одному измерению — это и
есть основание закрывать item против ОБНОВЛЁННОГО ТЗ (`plan-protocol` §6: дефект спеки — не
отклонение исполнителя; правка спеки под D# → `🟢` + запись `Known Deviations`).

Команды-якоря (воспроизводимы на `9ff9527`; `<base>`-дерево получено
`git show 5d8b4f3:docs/03_Dev/admin-panel.md`):

```
grep -cF 'домен>/ai'   docs/03_Dev/admin-panel.md   → 1   (на <base> → 0)
grep -cF 'обоих корней' docs/03_Dev/admin-panel.md   → 1   (на <base> → 0)
```

## 4. Свип по всем 40 items: задет ровно один

Открытый риск, унаследованный из `handoff.md` («тот же класс вероятен на будущих Validation-строках
с угловыми плейсхолдерами»), **снят измерением, а не обещанием**. Прогон `pre_final` по каждому
item'у всех семи фаз:

```python
for item in <все ### Pn.m семи phase-файлов>:
    c = tc.build(plan_dir=Path('plans/2026.07.28-EST-ARCH'), item_id=item)
    print(item, tc.pre_final(c))
```

Результат (на дереве `9ff9527`, до правки этого захода): **40/40 items построены без ошибок; ровно
один — `P4.5` — дал `ACCEPTANCE_NOT_PUBLIC`; остальные 39 — `None` (allow), внешних токенов ноль.**
Побочно видно, что у **37** items `Validation` схлопывается в одну клаузу (дефект D-1 присутствует
везде, но безвреден, пока в тексте нет токена, похожего на абсолютный путь), а у **трёх**
(`P2.2` и `P2.5` — по 4 клаузы, `P5.2` — 3) режется по `·`.

Следствия:

- **ремедиации других items не требуется** — периметр этого захода закрыт двумя строками;
- но дефект D-1 делает КАЖДЫЙ item одноточечно уязвимым: одна цитата абсолютного пути в любой
  строке `Validation` обнулит публичность всей приёмки. Поэтому правило формы вынесено в §2
  Execution Rules плана (D121) со ПРОВЕРЯЮЩЕЙ командой, а не как «помни об этом».

## 5. Отвергнутые варианты (провенанс для D-лога)

1. **Закрыть `🟠` с объяснением в Completion Notes, приняв незелёную границу.** Отвергнуто:
   `plan-protocol` §13 — гейт бинарен, `n/a`/`block` зелёным не считается; прецедент F1 ЭТОГО плана
   (реопен P1.5–P1.8, D97/D98) — ровно этот шорткат уже стоил реопена четырёх items. Цена отказа:
   один заход дизайна вместо нуля.
2. **Переформатировать `Validation` в `·`-разделённые клаузы** (тогда 7 из 8 останутся `public`, и
   `any(public)` пройдёт). Отвергнуто: клауза с цитатой пути остаётся ложно `internal` — искажение
   не устраняется, а перекрывается голосованием; плюс форма ломает нумерацию, на которую по номеру
   ссылаются D89, Completion Notes и `handoff.md`, и которую несут все 40 items. Годится как
   аварийный обход, если правило формы окажется несовместимым с каким-то будущим гейтом.
3. **Починить компилятор в `swissknifeman/task`.** Отвергнуто как предмет ЭТОГО захода (чужой
   пакет, `plan-protocol` §11), но не как задача: заведено в `open-questions.md`. Правильный фикс
   там — резать `Validation` и по нумерованной форме (D-1), и вызывать строковый тест внешности
   только на путях с установленной ролью (D-2).
4. **Оставить Validation как есть и вписать исключение в `journal-exceptions.jsonl`.** Отвергнуто:
   sidecar предназначен для schema-INVALID журнальных строк, а не для несогласия с вердиктом
   Task Contract; применение не по назначению обесценило бы механизм.
