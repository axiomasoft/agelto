# P3.1 return evidence — P2 Redis ACL permission denial

P3.1's carrier correctly refuses to start until `app`, `postgres`, `redis` and `minio` are
healthy. On the development Compose topology, Redis restarts before the application is created:

```text
Aborting Redis startup because of ACL errors: Error loading ACLs, opening file
'/run/secrets/redis_acl': Permission denied
```

The host ACL secret is present with mode `0600`; the rendered Compose contract mounts it at
`/run/secrets/redis_acl`, and Redis is configured to load exactly that file. Changing the secret
mode, Redis user, or Compose secret handling is P2 secret/runtime work and is outside P3.1.

The Livewire HTML → asset URL → Nginx → Laravel route runtime trace therefore has no valid
PROVED/REFUTED verdict. The exact continuation is
`$ task:plan-design 2026.08.09-RELEASE-READINESS P2` to add an owner-approved P2 remediation
item, restore a dependency-ready dev topology, then resume P3.1.
