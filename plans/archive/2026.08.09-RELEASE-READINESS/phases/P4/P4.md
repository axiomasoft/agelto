# P4 — Закрытая production-документация вне public

## Phase Context

Фаза превращает committed `docs/` в один закрытый production artifact set: exact stable VitePress
build находится внутри immutable image вне `public`/writable volumes, а HTML, CSS, JS, JSON,
images и fonts выдаёт только Laravel после одного AzGuard permission. Vintera используется как
измеренный anti-pattern/reference: его public asset bypass, VitePress alpha и dist volume не
переносятся. RAG:— (repo-grounded: `findings/P4-private-documentation-recon-2026-08-09.md`,
D26/D27).

P0.4/P0.6/P1.5/P3.5 ещё не терминальны: P4.1 до mutation сверяет их fresh states и named products
с D26/D27. Расхождение возвращает фазу в plan-design; исполнитель не подменяет generator,
storage, permission или response policy. P4.2–P4.5 образуют строгую build→serve→authorize→prove
цепочку. RAG:— (repo-grounded: `research/06-P4-execution-design.md`).

> **Контракт фазы (contract-first).** Потребляет: terminal P0.4/P0.6/P1.5/P3.5, `root/contracts/release-readiness-v1.md`, D7/D17/D18/D24–D27/D72, P4 repo/reference/official findings и current docs/AzGuard/Filament carriers · Производит: reconciled threat model, stable private docs build+manifest inside immutable image, one authorized Laravel serving path, Filament discovery link, rejected active-SVG surface and committed GREEN adversarial HTTP/browser/deploy proof · Границы: не публикует docs/assets в public, не добавляет default grant Analyst/Operator, не оптимизирует через Nginx/X-Accel/signed URLs, P9 владеет full Filament UX, P11 — CI, P12 — final production rehearsal

## Scope Included

1. Reconcile/freeze P0/P1/P3 outputs, threat register, generator/storage/serving alternatives and
   durable project contract.
2. Exact VitePress 1.6.4, frozen pnpm build, deterministic manifest and immutable image integration.
3. One manifest-backed locator/controller/route with path containment, closed MIME and no-store
   response/browser policy for every artifact.
4. AzGuard `DocumentationPermission::View`, SuperAdmin initial access, future grant seam and
   permission-aware Filament navigation.
5. Guest/non-admin/admin/grant, direct URL, traversal, MIME/cache/CSP, reproducible build, image and
   isolated Playwright acceptance.
6. Audit remediation F1–F8: reject active SVG, self-contained clean vendor/image build, literal
   browser/hash/header/logout/revoke proof and append-only commit/write-site/status reconciliation.

## Scope Excluded

- Public docs/static alias, separate unauthenticated asset route, signed bearer URL, Nginx auth
  subrequest/X-Accel optimization or production-host generator.
- Default docs access for AnalystRole/OperatorRole, final business role matrix or a second RBAC
  system; future roles consume the single enum permission.
- Rewriting documentation content beyond the config/index links needed for a valid build; full
  Filament localization/navigation overhaul P9 and CI topology P11.
- Ubuntu/reverse-proxy/TLS/rollback/final rehearsal P12, domain pipeline behavior and secrets.

### Находки

**F1 · Blocker · high · issue · P4.3/P4.5 · `scripts/documentation/verify-dist.mjs:17`,
`scripts/documentation/verify-dist.mjs:96`, `app/Services/Documentation/PrivateDocumentationAsset.php:30`,
`tests/Feature/Documentation/PrivateDocumentationResponseTest.php:64`**

Verifier разрешает произвольный `.svg` и проверяет executable content только у HTML/CSS/JS;
response policy добавляет CSP только для HTML, а focused test прямо требует отсутствие CSP у SVG.
Прямой authenticated route отдаёт такой SVG как `image/svg+xml` с admin-origin. *Failure scenario:*
скомпрометированный committed docs SVG, открытый direct URL пользователем с docs permission,
исполняет active content в origin админки и получает same-origin поверхность сессии. Это ломает
security/browser-policy Deliverable самой P4, поэтому finding красит фазу RED.
