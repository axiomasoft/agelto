**Implementation Rules:** P2.4 terminal is a hard gate. `BaseSeeder` owns the explicit production-required list and every member is idempotent; `DemoSeeder` refuses outside local/testing and never overwrites existing users/passwords. Console commands delegate short transactional mutations to Actions. Create requires nonblank normalized email, refuses ambiguous existing user and assigns the canonical SuperAdmin role atomically. Noninteractive create/reset accepts only a readable password-file path; interactive input is hidden. Password value never appears in argv/output/log/assertion. Bootstrap appends base seed and optional admin-create stages, never reset. RAG:— (repo-grounded: architecture/glossary, D9/D20).
**Code Guidance:** Final Actions use constructor dependencies/named arguments and one transaction; tests use factories and `test('<русский intent>', fn)`. Do not call `migrate:fresh`, hard-code demo password, reuse Seeder as mutable service, accept `--password=`, auto-promote an existing account or weaken authz for tests. Анти-подгонка: production refusal/demo and existing-user/admin-role cases stay explicit tests; a green rerun that duplicates rows is failure.
