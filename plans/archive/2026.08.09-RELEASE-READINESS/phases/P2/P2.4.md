### P2.4 — Автоматизировать clone-to-running bootstrap без скрытых ручных шагов

**Intent:** Собрать resumable staged bootstrap, который из clean Agelto clone вызывает vendor sync, create-only secrets, preflight и P1 build/runtime targets, достигая healthy dev stack или verified production images без скрытых команд. RAG:— (repo-grounded: D6/D17/D19/D20).
**Why:** Отдельно корректные vendor/secrets/preflight targets не образуют воспроизводимый порядок, а текущие setup/deploy recipes смешивают host Composer/yarn, destructive cleanup и production mutation. RAG:— (repo-grounded: `composer.json` scripts and current Make/deploy docs).
**Scope Included:** Named bootstrap stages/progress marker · `MODE=dev|prod-build` · vendor/secrets/preflight integration · P1 image/runtime commands · retry/resume/failure report · fresh/second-run contract tests · command/getting-started docs.
**Scope Excluded:** Base/demo seed/admin stages until P2.5 · Livewire/assets until P3 · production host provisioning/deploy/migrate/rollback/backup until P12 · automatic secret rotation · destructive recovery.
**Inputs:** `research/04-P2-execution-design.md` · `phases/P1/P1.5.state.md` · `phases/P2/P2.3.state.md` · D6 · D17 · D19 · D20 · `docker/Makefile` · `docker/php/Dockerfile`
**Files:** `docker/scripts/bootstrap.sh` · `docker/tests/bootstrap-contract.sh` · `docker/Makefile` · `composer.json` · `docs/03_Dev/getting-started.md` · `docs/03_Dev/commands.md` · `docs/03_Dev/docker/development.md` · `docs/03_Dev/docker/production.md`
**Required Reads:** 1) `plans/2026.08.09-RELEASE-READINESS/research/04-P2-execution-design.md` 2) `plans/2026.08.09-RELEASE-READINESS/phases/P2/P2.3.state.md` 3) `D6` 4) `D17` 5) `D19` 6) `D20` 7) `docker/Makefile` 8) `composer.json` 9) `docs/03_Dev/getting-started.md` 10) `docs/03_Dev/process/deploy.md`
**Implementation Rules:** P2.3 terminal and a green preflight are hard gates. Stage order is vendor → secrets → preflight → dependencies/image → dev up+health or prod image contracts; P2.5 later appends base/admin. Progress stores only stage/status/source SHA, never secrets, and advances only after deterministic validation. Rerun preserves secret bytes, vendor pin and persistent volumes; it never uses `down --volumes`, `migrate:fresh`, reset/clean or production-host build. Failure exits nonzero with failed stage and exact resume command, leaving prior valid state intact. RAG:— (repo-grounded: D17/D19/D20).
**Code Guidance:** Thin Make target calls one script; script calls canonical P1/P2 targets rather than duplicating Docker/Composer commands. No implicit `git pull`, interactive credential prompt in agent mode, hidden host PHP/Node fallback or success-on-partial-stage. Анти-самообман: second run must prove byte-stable secrets/ref and no extra destructive actions; a warmed developer tree is not clean-clone evidence.
**Validation:** `bash docker/tests/bootstrap-contract.sh` — item-owned carrier обязан включать shell syntax, fake-tool stage/failure/resume/forbidden-command cases, fresh temporary clone dev bootstrap to healthy liveness, idempotent rerun preserving secret/vendor/volume identities, prod-build without production mutation, redacted stage output and clean diff; upstream producer не исполняет этот ещё не созданный carrier.
**Deliverables:** One staged/resumable bootstrap carrier, dev and prod-build modes, progress/failure contract, fresh+rereun tests and exact operator docs; separate item commit.
