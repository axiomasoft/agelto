### P2.2 — Сделать безопасный генератор .env и .env.docker secrets

**Intent:** Создать create-only generator и единый file-secret contract для dev/prod Compose, чтобы internal credentials появлялись до bootstrap, но не попадали в Git, env/config output, image, argv или logs. RAG:— (repo-grounded: D20 and owner brief).
**Why:** Текущий prod carrier смешивает external Swarm secrets с env fallback, app entrypoint не читает объявленный AWS secret key, а examples содержат placeholder password; это fail-open до первого deploy. RAG:— (repo-grounded: P2 recon).
**Scope Included:** Secret contract manifest · ignored `local/secrets/` root · dev/prod env materialization · APP/DB/Redis/MinIO/admin secret generation · Redis hashed ACL · per-service Compose grants and `_FILE` wiring · atomic create/staged rotation · leakage/permission/idempotency tests · docs.
**Scope Excluded:** Генерация external Gemini/Telegram/mail/Sentry credentials · automatic rotation/apply · external vault/KMS · production backup policy · вывод secret values.

**Implementation Rules:** P2.1 terminal is a hard gate. Generator sets `umask 077`, uses cryptographic randomness, validates shape before atomic rename and preserves every existing value by default. Internal set is APP_KEY, DB_PASSWORD, REDIS_PASSWORD + hashed Redis ACL, MINIO_ROOT_PASSWORD and ADMIN_INITIAL_PASSWORD; external tokens remain explicit operator inputs. Production env files contain no secret values. Compose file secrets grant minimum services; PostgreSQL/MinIO use supported `_FILE`, Redis reads ACL file without plaintext argv, app entrypoint maps each `_FILE` exactly once and unsets file variables. Rotation writes staged `.next` only. RAG:✅ 2026-08-09 official Docker/PostgreSQL/Redis/MinIO docs recorded in findings.
**Code Guidance:** Не source произвольный env/contract file; parse a closed key set and reject duplicates, newline/control chars and symlinks. No `echo $SECRET`, `set -x`, process substitution carrying values, default `change-me`, predictable test RNG in production path or permissive chmod. Tests use temporary roots/sentinel values and assert values absent from stdout/stderr/rendered config/history. Анти-самообман: green shape/permission test without Compose grant/leakage assertions is insufficient.
**Validation:** `bash docker/tests/secrets-contract.sh` — item-owned carrier обязан включать shell syntax, create-only/rerun byte stability, 0600/atomic failure/staged rotation/redaction fixtures, tracked/ignored boundary, quiet dev/prod render, exact grants and _FILE paths, absence secret literals from environment/build/history and clean diff; fake secret success or отдельные преждевременные compose checks запрещены.
**Deliverables:** Versioned secret schema, create-only generator, ignored file-secret root, aligned Compose/entrypoint carriers, hashed Redis ACL, leakage tests and synchronized docs; separate item commit.
