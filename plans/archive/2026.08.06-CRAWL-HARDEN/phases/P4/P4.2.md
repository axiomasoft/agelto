### P4.2 — Привязка прокси к профилю и легальный прямой режим

**Intent:** Дать профилю ЯВНЫЙ набор прокси («пул из 10 — эти относятся к этому профилю»), сделать
выбор узла случайным внутри этого набора и легализовать работу без прокси на ВСЕХ трёх точках
исхода, включая детальную карточку и скачивание документа.
**Why:** Прямое требование владельца: «для каждого профиля мы можем выбирать, какие из этих прокси
относятся к данному профилю, и уже из них делать рандом… нельзя брать те, что явно не указали —
иначе там могут быть иностранные, и мы тут же спалимся» (`brief/01-refinements.md` блок P4 п. 2–3,
D37/D38). Сегодня профиль сужает пул только страной, набора нет вовсе
(`RAG:— (repo-grounded: app/Dto/Procurement/Proxy/ProxyRequirements.php — единственное поле country;
database/migrations/2026_07_31_100063_add_proxy_routing_to_prc_crawlers_table.php)`). Второй, более
острый факт: детальная карточка и скачивание документа зовут резолвер БЕЗУСЛОВНО — ветки прямого
запроса, которая есть у листинга, у них нет, поэтому пустой пул валит снятие карточки и загрузку
файла `NoProxyAvailableException`, а сид при этом ставит обоим профилям `use_proxy => true` при
нулевом числе прокси в БД
(`RAG:— (repo-grounded: CsvSourceMethod::collectTab() против CsvSourceMethod::listingLease();
DocumentDownloader::fetch(); ProxyResolver.php:44-47; CrawlerProfileSeeder.php:123-124,146-147)`).
Бриф требует обратного прямым текстом: «по умолчанию проксей нет — работаем в том же потоке».
**Scope Included:** (1) миграция: pivot `prc_crawler_proxy` (`crawler_id`, `proxy_id`, unique-пара,
`cascadeOnDelete`), обратимый `down()`; (2) связь `Crawler::proxies(): BelongsToMany` и обратная
`Proxy::crawlers()`; (3) `ProxyRequirements` += `?array $proxyIds` — резолвер добавляет
`whereIn('prc_proxies.id')` ПОСЛЕ гео-гейта, не вместо него; (4) сервис
`App\Services\Procurement\Proxy\ProxyBindingResolver` — отвечает на вопрос «какой набор узлов
разрешён этой точке исхода»: для листинга — набор профиля; для стадий БЕЗ профиля (вкладки
карточки, скачивание документа) — ОБЪЕДИНЕНИЕ наборов активных профилей реестра закупки; (5) гейт
`Crawler::saving()`: `use_proxy = true` требует непустого набора — сохранить профиль-«с прокси, но
без прокси» нельзя; (6) прямой режим как легальный исход всех трёх точек: набор пуст ПО
КОНФИГУРАЦИИ → `ProxyLease::direct()` с явной записью в лог (канон «тихого прямого запроса не
существует» соблюдён); набор непуст, но весь закрыт breaker'ом → прежний
`NoProxyAvailableException`; (7) сид: оба профиля переводятся на `use_proxy => false` (прокси в БД
не сидируются, бриф называет режим без прокси дефолтным); (8) Filament: в форме профиля —
мультиселект прокси (подпись называет условие «набор + флаг»), в таблице профилей — колонка числа
привязанных узлов; (9) `CrawlerFactory` по умолчанию создаёт валидный direct-профиль
(`use_proxy = false`), а явный state `withProxies(Proxy ...$proxies)` прикрепляет прокси ДО
включения `use_proxy`; (10) тесты: резолвер не выдаёт узел вне набора профиля; стадия без профиля
получает объединение по реестру; профиль с `use_proxy = true` и пустым набором не сохраняется;
пустой по конфигурации набор даёт direct-лизу и запись в лог на ВСЕХ трёх точках; закрытый
breaker'ом непустой набор по-прежнему даёт отказ; сид даёт профили без прокси; существующий тест
динамических proxy-настроек создаёт допустимое начальное состояние через factory-state.
**Scope Excluded:** алгоритм выбора узла, веса score, пороги breaker'а (D37 — не переписываются);
авто-дизейбл и витрина здоровья — P4.3; скоуп `llm` и `PoolOutboundProxy` (другая политика, чужой
домен); бюджет запросов — P4.4; массовый импорт прокси и их проверка (`prc_proxy_checks` — вне
скоупа фазы).

**Implementation Rules:** 1) Привязка СУЖАЕТ, а не заменяет: гео-политика скоупа и требование
страны профиля продолжают действовать поверх набора — узел из набора, не прошедший гео-гейт, не
выдаётся. Иначе привязка станет способом обойти запрет иностранного узла, то есть ровно тем, чего
владелец боится. 2) «Пусто по конфигурации» и «всё закрыто breaker'ом» — РАЗНЫЕ исходы и разные
ветки кода: первый даёт прямой запрос, второй — отказ. Смешать их значит молча перевести обход на
наш собственный IP в момент массового бана прокси. 3) Прямой режим ВСЕГДА логируется явно
(`ProxyLease::direct()` уже это делает) — тихого прямого запроса не существует. 4) Объединение
наборов для стадий без профиля берётся по АКТИВНЫМ профилям реестра закупки; профиль с
`use_proxy = false` в объединение не входит (он сознательно ходит напрямую). 5) Гейт
`Crawler::saving()` дополняется, а не переписывается — там уже живут резолв фильтра (P2) и политика
остановки (P3.3). 6) **Номер миграции — следующий свободный В МОМЕНТ исполнения** (D35). 7) Сид
переводится на `use_proxy => false` ТЕМ ЖЕ коммитом, что и гейт: иначе `db:seed` начнёт падать на
собственном гейте. 8) Фабрика меняет default на `use_proxy = false`; state
`withProxies(Proxy ...$proxies)` обязан присоединить непустой набор и лишь затем сохранить
`use_proxy = true`. Нельзя сделать тестовый default «с прокси» скрытой фабрикой: это скрывает
главный продуктовый default и размазывает привязку по фикстурам. 9) Тесты прокси не ходят в сеть:
лиза проверяется по возвращённому объекту и логу, а HTTP-выходы — через `Http::fake()`.
**Code Guidance:** Стиль — `final readonly`, promotion, именованные аргументы. `ProxyBindingResolver`
— один вопрос и один ответ: «какие id узлов разрешены этой точке исхода»; выбор узла остаётся у
`ProxyResolver`, состояние здоровья — у репозитория. Докблок обязан объяснить, почему стадии без
профиля берут объединение по реестру (у закупки нет профиля, а второй носитель привязки заводить
нельзя) — иначе следующая сессия заведёт третью таблицу. Тесты — только
`test('<интент по-русски>', fn)`, персистентные модели через фабрики. **Factory contract:**
обычный `Crawler::factory()->create()` обязан сохраняться как direct-профиль; тесту, которому
нужен `use_proxy = true`, запрещено присваивать флаг без `withProxies(...)` либо эквивалентного
явного attach ДО сохранения. **Test locality:** direct-регрессии живут в трёх уже существующих
тестах соответствующих HTTP-выходов; `EisSeedersTest` — единственный носитель сида профилей.
