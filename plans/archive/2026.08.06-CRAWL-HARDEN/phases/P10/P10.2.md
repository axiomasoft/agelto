### P10.2 — Сохранить cap-detector state через checkpoints и исправить precedence stop-веток

**Intent:** Реальный exact-repeat cap ЕИС и archive max-block cap должны срабатывать одинаково в
одном job и после любого числа continuations.

**Why:** Generic no-change branch сейчас скрывает exact repeat, а detector state живёт в локальных
переменных и исчезает на checkpoint (`RAG:— (repo-grounded: F3/F4 audit, D133)`).

**Scope Included:** (1) `ListingCursor.lastDedupSignature` и `blocksInInterval` с backward-compatible
defaults; (2) fresh сохраняет signature перед checkpoint и проверяет exact repeat после ingest,
но до reached-known/no-change; (3) archive восстанавливает signature/count из cursor, сохраняет их
после каждого блока/checkpoint и сбрасывает только вместе с текущим interval; (4) exact same-row
fixtures и one-request-per-continuation regressions; (5) UI cursor decode, если новые поля
показываются оператору.

**Scope Excluded:** изменение EIS block size/5000 cap · новая стратегия price splitting · run
ownership (P10.1) · treating any unchanged block as cap without matching signature.

**Implementation Rules:** 1) Existing cursor JSON without new keys loads as null/0. 2) Signature is
the actual `ListingBatch::dedupSignature`; do not derive a second hash. 3) Exact-repeat comparison
occurs after ingest evidence is recorded and before generic no-change/reachedKnown completion.
4) Cursor written at a platform-budget checkpoint includes the last completed block's detector
state. 5) Archive count increments once per full block in the same interval and survives
continuation; it resets only on partial drain, split/drop or interval pop. 6) Tests use identical
registry rows and identical signature, not merely equal signature over different data. 7) One
regression forces checkpoint between first and repeated blocks; another allows one request per
continuation until `max_blocks_per_window` is reached.

**Code Guidance:** Preserve `ListingCursor` as the only resumable state carrier; avoid parallel
stats keys. A small immutable cursor-copy helper is acceptable if it reduces missed fields across
constructors. Запрещённые shortcuts: moving the generic no-change branch before ingest;
hard-coding block 5001; raising `max_blocks_per_window`; retaining detector state in a singleton.
Анти-самообман: two queued batches in one method call prove branch order but not persistence;
both single-call and continuation tests are required. Анти-подгонка: do not set `rowsNew>0` on
the repeated fixture to force the cap branch.
