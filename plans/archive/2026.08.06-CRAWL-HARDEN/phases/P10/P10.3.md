### P10.3 — Сериализовать procurement ingest и логическую нумерацию ревизий

**Intent:** Любые concurrent observations одной `(registry_id, registry_number)` образуют одну
монотонную revision history и детерминированный procurement head.

**Why:** Current find/latest/revision_count reads are unlocked and crawler jobs can overlap by
procurement identity (`RAG:— (repo-grounded: F5 audit, D134)`).

**Scope Included:** (1) transaction-scoped PostgreSQL advisory lock key from registry id + exact
registry number; (2) lock acquired before first find/create and held through revision/events/head;
(3) post-lock reread of procurement/latest revision; (4) deterministic handling of identical and
different concurrent snapshots; (5) real two-connection tests using P10.1 helper; (6) explicit
error propagation/row logging assertion so a concurrency violation cannot be counted as a healthy
unchanged row.

**Scope Excluded:** global registry lock · schema redesign of partitions · weakening revision
unique index · cross-registry deduplication · changing snapshot hash semantics · broad rewrite of
`CsvBlockIngestor` (parse counters belong to P10.5).

**Implementation Rules:** 1) Lock key is deterministic for the full domain identity; document
collision handling of its 64-bit representation. 2) Use `pg_advisory_xact_lock`, never session
lock; transaction end releases it. 3) No query that can create/read the procurement occurs before
the lock inside the transaction. 4) After waiting, discard detached pre-lock model state and
requery. 5) Identical snapshots create at most one new revision; different snapshots receive
distinct increasing `revision_number`, and head/hash/revision_count point to the final committed
revision. 6) Concurrency test uses two PostgreSQL sessions and deterministic barriers; transaction
rollback in test harness must not make both writes invisible to one another. 7) Do not add an
illusory unique index PostgreSQL cannot enforce across the partition key.

**Code Guidance:** Prefer a tiny Postgres-specific advisory-lock adapter with named arguments if
raw SQL would otherwise spread. Keep business comparison in the processor after the lock. Ensure
deadlock/retry errors remain visible to queue retry policy. Запрещённые shortcuts: Redis/cache
lock as the only correctness guard; `lockForUpdate()` only after an unlocked missing-row check;
catch-and-log unique violations as unchanged; serializing the entire registry. Анти-самообман:
two calls in one transaction/connection are not concurrent. Анти-подгонка: do not assert only
row count; assert revision numbers, hashes, head id and final event set.

**Validation:** current code first fails the new concurrency regression · two identical snapshots
commit one logical revision · two different snapshots commit monotonic unique revision numbers
and correct head · focused `ProcurementIngest|CsvBlockIngestor` tests green · `migrate:fresh --seed`
green · Pint/PHPStan · no new full-suite delta.

**Deliverables:** per-procurement PostgreSQL serialization · post-lock reread contract · real
concurrency regression for identical/different snapshots · application/test item commit plus
separate bookkeeping commit.
