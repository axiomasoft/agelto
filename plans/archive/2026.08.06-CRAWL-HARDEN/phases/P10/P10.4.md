### P10.4 — Исправить initial/terminal timeline и наблюдённую длительность

**Intent:** Timeline и Filament должны показывать фактически наблюдённый первый статус и честно
распознавать procurement, который уже terminal при discovery.

**Why:** Initial ingest stores `Discovered`, но mapped initial status не создаёт status event;
builder начинает только с `StatusChanged` и выводит `идёт` для completed procurement
(`RAG:— (repo-grounded: F6 audit, D135)`).

**Scope Included:** (1) canonical initial-status event at discovery for every source status;
(2) отсутствие duplicate event для unknown status; (3) builder starts first interval at discovery,
detects terminal initial status and reports observed total duration 0; (4) transitions continue to
accumulate by status; (5) UI copy distinguishes observed duration from source lifetime; (6) tests
go through actual ingest, not direct synthetic events only.

**Scope Excluded:** реконструкция времени до первого observation · изменение status mapping canon ·
редактирование historical events · изменение semantics `ProcurementSucceeded` · новый UI экран.

**Implementation Rules:** 1) Initial status is represented once, with `old_status=null`,
`new_status=<resolved status>` and occurrence at discovery. 2) Unknown mapping uses the same
canonical event path; do not emit a second status event. 3) Builder remains backward-compatible
with existing historical data that may have only `Discovered`: it may use discovery payload/model
status only when this cannot invent an intermediate transition; document the fallback. 4) A
terminal initial event closes the first interval at the same timestamp: terminal status set, total
observed duration 0, by-status entry 0. 5) Non-terminal current interval keeps total duration null
and UI ongoing semantics. 6) Test Bidding → Evaluation → Completed with controlled timestamps,
Completed-at-discovery, Unknown-at-discovery and legacy discovered-only history.

**Code Guidance:** Prefer one helper that writes initial status through the same event schema as
later changes. Keep `ProcurementDurations` units in seconds. UI labels should say «наблюдаемая
длительность» rather than implying the procurement started when Agelto first saw it.
Запрещённые shortcuts: using `procurement.status` as terminal for every legacy history without
temporal evidence; replacing null ongoing duration with zero; creating a special terminal-only
event type. Анти-самообман: direct event factories do not prove ingest emits the event.
Анти-подгонка: do not change evaluator success semantics to make the timeline test pass.

**Validation:** focused `Discovery|StatusMapping|ProcurementTimeline|ProcurementSucceeded` tests
green · rollback probe returns terminal `completed`, total 0 and no `идёт` placeholder · transition
test preserves exact by-status durations · initial unknown emits one status event · Pint/PHPStan ·
no new full-suite delta.

**Deliverables:** canonical initial status event · backward-compatible truthful timeline · updated
Filament copy · ingest-path regressions · application/test item commit plus separate bookkeeping
commit.
