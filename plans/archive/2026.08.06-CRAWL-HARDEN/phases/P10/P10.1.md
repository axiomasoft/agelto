### P10.1 — Изолировать ownership crawler run и починить PostgreSQL race recovery

**Intent:** Сделать run resumable только своим purpose/subject и устранить запрос внутри aborted
PostgreSQL transaction при unique race.

**Why:** Сейчас delta/backlog получают любой running archive run, а catch после unique violation
выполняет SELECT в уже aborted transaction (`RAG:— (repo-grounded: F1/F2 audit, D132)`). Цена
ошибки — чужой cursor/completion и потерянная фоновая работа.

**Scope Included:** (1) enum `RunPurpose` со значениями `profile`, `delta`, `backlog`; (2) baseline
columns `purpose` и `subject_key` в `prc_crawler_runs`, casts/factory/UI readout; (3)
`CrawlerRunManager::startOrResume()` принимает purpose/subject, блокирует crawler row и возвращает
только exact owner; mismatched running owner даёт typed busy exception/outcome; (4) вложенный
SAVEPOINT для create + safe unique recovery; (5) все callers передают owner; delta/backlog при busy
завершают текущий вызов без мутации чужого run и без acknowledgement; (6) общий минимальный helper
для двух PostgreSQL sessions и concurrency tests.

**Scope Excluded:** второй параллельный running run на crawler · advisory lock procurement ingest
(P10.3) · cap state (P10.2) · retry loop, который ждёт освобождения crawler внутри scheduler job ·
изменение schedule cadence.

**Implementation Rules:** 1) Exact owner tuple is explicit at every call; no default that maps
background work back to profile. 2) Profile subject is `null`; delta key is
`fresh-crawler:<id>`; backlog key is `fresh-run:<id>`. 3) Locked crawler is re-read inside the
transaction before running/paused lookup. 4) A paused run resumes only for exact owner. 5) Create
occurs inside a nested `DB::transaction()`; catch surrounds that nested call, then queries winner.
6) Busy delta returns `null`; busy backlog returns false and leaves `backlog_rescanned_at` null.
7) Concurrency proof uses PostgreSQL, two physical connections/processes and a deterministic
barrier; sleeps without a barrier are forbidden. 8) Baseline migration is edited in place because
the project has no production schema; no follow-up migration.

**Code Guidance:** Keep purpose resolution at orchestration boundaries; scanner remains ignorant of
who owns the run. The concurrency helper is test-only and exposes synchronization, not crawler
domain policy. Prefer a small typed busy exception over `?Run` ambiguity inside the manager.
Запрещённые shortcuts: returning the existing mismatched run; deleting the partial unique
index; swallowing unique violations; retrying a SELECT in the aborted transaction; serializing all
crawlers through one global lock. Анти-самообман: a test that calls `startOrResume()` twice
sequentially does not prove the PostgreSQL race. Анти-подгонка: do not special-case test process
IDs or lower isolation only in tests.
