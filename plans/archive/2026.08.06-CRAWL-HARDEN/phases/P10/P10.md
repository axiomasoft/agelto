# P10 — Adversarial remediation: correctness, concurrency and truthful health

## Phase Context

> **Контракт фазы (contract-first).** Потребляет: terminal worktree после P9 · восемь
> воспроизведённых code findings F1–F8 из `findings/P10-code-adversarial-audit-2026-08-09.md` ·
> PostgreSQL-only data layer и штатный `migrate:fresh` · Производит: изолированное владение
> crawler runs, durable cap detection, serial procurement revisions, честную timeline, раздельные
> parse/change health-сигналы, lossless proxy breaker updates и adversarial regression suite ·
> Границы: application code/tests и связанные живые docs; закрытые P1–P9 ТЗ, Swissknifeman,
> Layout migration, historical delivery commits и generated projection defects не меняются.

P10 добавлена прямым решением владельца после финального code audit. Причина не в красных
существующих тестах: targeted и full suite зелёные, но rollback probes доказали восемь сценариев,
которые текущая suite не выражает. Четыре из них могут смешать run ownership, потерять ревизию или
скрыть реальный cap; остальные врут оператору/healthcheck либо задерживают circuit breaker.

RAG:— (repo-grounded: `findings/P10-code-adversarial-audit-2026-08-09.md`, D131–D137).

## Scope Included

1. Typed ownership и PostgreSQL-safe start/resume для profile/delta/backlog runs.
2. Полное сохранение cap-detector state через job checkpoints и правильный порядок stop branches.
3. Transaction-scoped advisory serialization procurement ingest по доменной identity.
4. Initial/terminal status semantics и «наблюдённая длительность» в timeline/UI.
5. Fetch parse/error telemetry, которая не смешивает unchanged rows с parser failure.
6. Serialized proxy/target breaker и EWMA persistence после завершившегося HTTP.
7. Реальные PostgreSQL concurrency regressions, exact EIS repeat probes, полный validation и
   актуализация живой документации.

## Scope Excluded

- Любые `task:*` команды и v1-carriers; Layout-v2 rollout остаётся за Swissknifeman.
- Переписывание закрытых P1–P9 item specifications или generated `.state.md` вручную.
- Ремедиация missing item commits / P3 projection contradictions из старого delivery audit.
- Изменение one-running-per-crawler product policy: background work ждёт/пропускает, а не идёт
  параллельно вторым running run.
- Ослабление partitioned indexes, health thresholds, test guards, TLS/proxy boundaries либо
  замена реальной PostgreSQL concurrency моками.
