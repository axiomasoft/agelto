### P7.1 — Витрина содержимого золотой сметы в карточке эталона

**Intent:** Показать в админке, ЧТО лежит в золотой смете: паспорт, итоги, разделы, позиции и их
подэлементы — вкладкой карточки эталона, read-only, читая файл на лету, без импорта золота в БД.
**Why:** Дословное требование владельца: «Золотые сметы — основа, хранятся в файловой системе. В
админке мы тоже должны понимать, что в них лежит» (`brief/00-brief.md` блок 1); гэп G12. Сегодня
слово `gold_dir`/`gold.json` не встречается в `app/Filament/**` ни разу — единственный контакт
панели с файловым корпусом — бейдж `in_manifest`
(`RAG:— (repo-grounded: app/Filament/Resources/Procurement/Ai/Fixtures/Tables/FixturesTable.php:56-70)`).
Место витрины выбрано владельцем 2026-08-06: вкладка карточки эталона, а не отдельный пункт меню
(D73) — золото есть артефакт эталона, и второй сущности в навигации не появляется. Импорт в БД не
нужен: Filament 5 несёт штатную таблицу поверх произвольных данных
(`RAG:✅ 2026-08-06 — filament/filament@5.x, packages/tables/docs/09-custom-data.md, метод
->records()`, выжимка — `findings/P7-rag-filament-2026-08-06.md` §1), поэтому файл остаётся
единственным источником истины.
**Scope Included:** (1) читатель витрины `app/Services/Procurement/Gold/GoldDocumentReader.php`:
принимает `Fixture`, возвращает разобранный документ либо «золота нет» (без исключения), **разбор
— существующими контрактными DTO** `PassportResponse`/`EstimateRow`, как это делает
`GoldValidator`; (2) гейт пути: код эталона проверяется на допустимые символы, итоговый путь
сверяется с `config('ai.fixtures.gold_dir')` — выход за каталог = отказ чтения; (3) тонкий
контейнер документа `app/Dto/Procurement/Gold/GoldDocumentView.php` (список смет: паспорт, итоги,
строки) — только контейнер, ни строки, ни паспорта заново не описывает; (4) единый рендер
содержимого `app/Filament/Resources/Procurement/Ai/Fixtures/Schemas/GoldContentSchema.php`: паспорт
и итоги секцией, позиции таблицей (номер строки, тип строки, раздел, обоснование, наименование,
единица, количество, цены), подэлементы позиции — раскрытием строки; (5) страница ресурса
`Pages/ViewFixtureGold.php`, зарегистрированная в `FixtureResource::getPages()` и в
`getRecordSubNavigation()` рядом с просмотром эталона; (6) колонка «Золото» в списке эталонов —
признак берётся из УЖЕ читаемого манифеста, не вторым обходом диска; (7) честные пустые состояния:
«золота нет» с указанием команды сборки и «манифест обещает золото, файла нет» — раздельно; (8)
раздел в `docs/03_Dev/admin-panel.md`; (9) тесты Filament и тест гейта пути.
**Scope Excluded:** импорт золота в БД (D73 отверг); редактирование золота из админки (граница

**Implementation Rules:** 1) **Разбор золота — только существующими DTO** `PassportResponse` и
`EstimateRow`: второй парсер формы §8.2 запрещён (Л-2); контейнер документа несёт СПИСКИ этих
объектов и ничего сверх. 2) **Путь строится только после проверки кода**: код обязан состоять из
безопасного набора символов, а итоговый абсолютный путь — лежать внутри `gold_dir`; нарушение —
отказ чтения с понятным сообщением, а не пустой результат (Л-1). 3) Признак наличия золота для
СПИСКА эталонов берётся из уже прочитанного манифеста; чтение файла на строку списка запрещено
(Л-3). 4) Расхождение «манифест обещает `gold_path`, файла нет» показывается на странице явным
сообщением, а не пустой таблицей. 5) Позиции показываются таблицей поверх массива
(`->records()`), подэлементы — раскрытием строки; `json_encode` содержимого одной строкой и
`KeyValueEntry` по вложенной структуре запрещены (Л-4). 6) Страница строго read-only: ни одного
действия, меняющего файл или БД; навигационная группа — существующая «AI-анализ», новых разделов
меню не заводится. 7) Подписи колонок — по-русски, из ОДНОГО носителя подписей страницы (как
`ItemsRelationManager::FIELD_LABELS`), не россыпью литералов. 8) Чтение файла не кэшируется в
статике класса: файл в git может смениться коммитом, а страница обязана показывать текущий.
**Code Guidance:** Стиль — существующая раскладка ресурса (Resource / Pages / Schemas / Tables),
`final` + `declare(strict_types=1)`, конструкторная инъекция читателя. Бизнес-логики в схеме
рендера нет: она получает готовый разобранный документ. Тесты — только
`test('<интент по-русски>', fn)`, персистентные модели — фабрикой `Fixture::factory()`, файлы
корпуса в тестах — временный каталог + подмена `config('ai.fixtures.gold_dir')`, НЕ чтение боевого
`estimates/gold/**` (тест, зависящий от содержимого корпуса, ломается при его пополнении).
