## 2. Граф зависимостей фаз

```
P1 (разведка ЕИС)
 ├──> P2 (ОКПД2)          — форма фильтра зависит от вердикта G2
 ├──> P3 (профили)        — sortBy/sortDirection подтверждены, статусы этапов
 ├──> P5 (healthcheck)    — эталонные якоря вёрстки снимаются в P1
 ├──> P6 (статусы)        — сверка prc_status_mappings с живым ЕИС; success-карточка — вход P6.2
 └──> P8 (схема)          — инвентарь P1.5: какие поля просятся в колонки (Q16)

P2, P3 ──> P4 (надёжность конвейера)   — бюджет запросов считается по фактическим стадиям
P4 ──> P5                              — healthcheck сам ходит на площадку, обязан жить в бюджете
P6 независима от P2–P5 (кроме входа из P1)
P7 независима от P1–P6

P2, P3, P4, P5, P6 ──> P8 (схлопывание миграций)
   ЖЁСТКО: схлопывание последним среди схемных фаз, иначе squash придётся повторять
   P7 из этой стрелки ИСКЛЮЧЕНА при детализации: фаза не добавляет ни одной колонки (D75/D78)

P8 ──> P9 (документация)
   документация описывает финальную схему и финальные настройки
```

## 3. Coupling-поверхность (файлы/канон, трогаемые ≥2 фазами)

| Поверхность | Фазы | Риск расхождения |
|:--|:--|:--|
| `app/Dto/Procurement/Crawler/EisSearchFilter.php` | P2 (ОКПД2), P3 (сортировка) | оба добавляют поля в один DTO с `ALLOWED_KEYS` и `rules()` — правки обязаны сойтись, иначе гейт `Crawler::saving()` отвергнет валидный профиль |
| `app/Filament/…/Crawlers/Schemas/CrawlerForm.php` | P2 (дерево ОКПД2), P3 (настройки режима/попыток) | одна форма, две ветки полей |
| `database/migrations/…create_prc_crawlers_table.php` | P3 (новые колонки настроек), P8 (схлопывание) | P8 обязана поглотить всё, что добавила P3 |
| `config/crawler.php` | P2, P3, P4, P5 | четыре фазы дописывают секции; конфликт ключей |
| `routes/console.php` | P3 (расписание профилей), P4 (троттлинг тиков), P5 (ежедневный healthcheck) | три фазы добавляют/меняют расписания — общий бюджет тиков |
| `app/Services/Procurement/CrawlerRunManager.php` | P3 (стоп/резюм/нахлёст), P5 (сигнал поломки останавливает прогон?) | владелец состояния прогона один |
| `prc_status_mappings` + `StatusMappingSeeder` | P1 (сверка), P6 (событие) | сид и живой ЕИС обязаны сойтись |
| `resources/crawler/health/eis-baseline.json` | P5.1 (заводит вкладку `known_broken`), P6.2 (переводит на `measured`) | эталон, оставшийся на `known_broken` после починки парсера, навсегда прячет реальную поломку вкладки (D72) |
| `app/Models/Procurement/Procurement.php` | P5.2 (колонка исхода разбора), P6.3 (связи), P6.5 (колонка `succeeded_at`) | три фазы правят одну модель — `fillable`/`casts` обязаны сойтись, P8 обязана поглотить обе колонки |
| `app/Enums/Procurement/ProcurementEventType.php` | P6.5 (добавляет значение), P6.3 (читает в ленте) | новое значение без подписи в словаре витрины даёт пустой бейдж |
| `app/Services/Procurement/ProcurementIngestProcessor.php` | P6.5 (одна строка вызова оценщика) | у статуса закупки один владелец (D63); любая вторая правка здесь — кандидат в дефект |
| `tests/Fixtures/Crawler/Card/*.html` | P1.4 (снимает HTML), P5.1 (берёт якоря), P6.2 (промоутит вкладку в фикстуру) | фикстура без живого источника — фантазия о вёрстке, уже однажды уведшая парсер от площадки |
| рендер содержимого золота (`GoldContentSchema`) | P7.1 (создаёт), P7.2 (потребляет) | два рендера одной формы §8.2 разойдутся молча (D80) |
| `app/Enums/Procurement/Estimate/RowQualityReason.php` | P7.4 (новое значение) | значение без подписи в том же `label()` даёт пустой бейдж в витрине смет |
| `app/Filament/Resources/Procurement/Estimates/**` | P7.3 (ссылки между слоями), P7.4 (фильтр по причине пометки) | одна витрина, две ветки правок |
| `docs/03_Dev/admin-panel.md` | P7.1–P7.5 (каждая витрина — свой раздел), P9 (сводит) | фаза, не дописавшая раздел, оставляет P9 работу без фактуры |
| Дерево `docs/` | P9 и все фазы (PR-чеклист доков) | каждая фаза обязана дописать свой раздел, P9 сводит |
