## 1. Context

v2-краулинг доведён ровно до статуса документа `downloaded` (`app/Services/Procurement/DocumentDownloader.php`); всё после — подготовка, скрининг, извлечение смет, LLM-слой — отсутствует (есть только схема БД `prc_*`, модели без логики и enum'ы). Этот план реализует Фазы 4–6 роадмапа `docs/specs/v2/06-roadmap.md` по ТЗ `docs/specs/v2/03-document-pipeline.md` и `04-llm-providers.md`.

Вторая цель — папка `Old/` (архив v1) готовится к удалению. В ней живут незаменимые доменные знания: промт-подсистема (`Old/app/Repositories/Prompt/PromptRuleRepository.php`, приём «PHP-исходник схемы в system instruction»), контракты смет (`Old/app/Process/EstimateAnalysis/Schema/**`, `#[Alias]`-словари русских заголовков), guards идемпотентности/lease, стратегии подготовки. Тексты промтов v1 существуют ТОЛЬКО в БД v1 (`plt_prompt_rules`) и в `Old/docs/03_Dev/LLM_Strategy.md`. До удаления всё это фиксируется в спеке и переносится в код (P1); само удаление — терминальный P11.1. Колоночный диф всей v1-БД против v2 выполнен (research/I): доменных потерь нет; гейты удаления — нетрекаемый `Old/database/database.sqlite` и `locations.zip` (см. P11.1).

Черновые документы `tmp/agelto.md` и `tmp/agelto2.md` (agelto2 — надмножество agelto) дают алгоритм разрывов страниц (sliding window + orphan buffer + stitcher) и JSON-контракты; они транскрибируются в спеку и удаляются. Их `ord_*`-схема БД устарела — актуальная `prc_*` уже смигрирована.

Выжимки одиннадцати разведок (A процессы v1 · B промты v1 · C поля смет v1 · D состояние v2 · E Gemini-2026 · F аудит схемы БД · G транспорт/обучение · H структура доков · I диф v1-БД · J observability/деплой/конкурентность · K ревью плана) — в `plans/EST-AI/research/`; исполнитель обязан читать их по Required Reads, а не переоткрывать Old/ с нуля.

Вторая итерация (2026-07-07) добавила: санацию схемы БД по аудиту F (нейминг индексов, FK, onDelete, снятие unique с `prc_estimates.analysis_id`), обучающий контур (обратная связь оператора «проверено/что не так», корректирующие промты, gold-петля, экспорт SFT-датасета — фундамент локальной LLM при отключении Gemini в РФ), сиды и `is_protected` для промтов, фазу документации с диаграммами. Требование универсальности: система не завязана на Gemini (capability-based кэширование, D14), не завязана на ЕИС (шов `prc_eis_details` подтверждён аудитом), расширяема на другие типы документов (D13) и до CRM (org_* — чистый shared-слой; контакты-сущность — отложенный шов).

Пятая итерация (2026-07-07) по pre-exec аудиту с внешней верификацией (research/L) закрывает ключевую вводную владельца: **документ может быть гигантским (2–200 МБ, до сотен страниц-сканов) и содержать несколько перемешанных смет, упираясь в лимиты Files API провайдера (Gemini: 50 МБ / 1000 стр. НА ЗАПРОС даже при upload до 2 ГБ)**. Механизм разбора обязан быть максимально стабильным: preflight против capability-матрицы маршрута до загрузки (D29), окно + собственный discovery-паспорт для сегментации смет без целого документа в контексте (D30), checkpoint-requeue job'а для постепенной проработки без упора в timeout (D31), и явный терминальный исход `unprocessable` с причиной и алертом, когда обработка невозможна (D32). Плюс EOL-осознанные модели (D27), qpdf вместо ограниченного FPDI (D28), retention/бэкапы под большой объём (D33, P7.7), durability очередей (D34).

Следующий шаг владельца после плана: другая модель будет парсить папку эталонных смет и наполнять промты — P8 и P7.4 готовят для этого файловую структуру промтов и датасет-контур; P9 замыкает петлю обучения.

## 2. Execution Rules

- Один item за раз; статус обновляется В ПЛАНЕ (phase-файл + Status Board здесь) до завершения работы.
- Статусы — 6 канонических строк байт-в-байт (plan-protocol §5).
- План разошёлся с кодом → не импровизировать, эскалировать (Escalation Needed + handoff).
- После закрытия item/фазы — перезаписать `plans/EST-AI/handoff.md` целиком.
- Тесты: Pest, `test('<интент по-русски>')`, БД `agelto_test`, запуск `docker compose exec app php artisan test --filter=<Subject>`; стиль `docker compose exec app ./vendor/bin/pint --dirty --test`.
- Канон имён/слоёв — CLAUDE.md + `docs/02_Workflow/glossary.md` отсутствует → канон в `plans/EST-AI/research/D-v2-state.md` §Конвенции; сущности `$document`, `$documentVersion`, `$analysis`, `$estimate`.
- Персистентность только через `app/Repositories/Procurement/*StoreRepository`; сервисы `final readonly`, конструкторная инъекция, именованные аргументы, `declare(strict_types=1)`.
- Таблицы существуют (`prc_*`) — новые миграции создавать ТОЛЬКО там, где item явно это указывает.
- Old/ и tmp/agelto*.md — read-only справочники до P11.1; ничего в них не менять.
- LLM-вызовы в тестах — только через тестовые двойники (`tests/Support/Doubles/`), никаких реальных запросов к Gemini.
