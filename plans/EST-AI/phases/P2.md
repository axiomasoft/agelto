# P2 — Схема-как-код: DTO-контракты ответов LLM

## Phase Context

Реализует решение D2: PHP Data-классы — единственный источник контрактов LLM-ответов; из них генерируются и промт-текст (очищенный исходник — приём v1 `PromptService::getCleanSchema`), и `responseJsonSchema` для structured output. Контракты пишутся по спеке `docs/specs/v2/08-estimate-extraction.md` (P1.2) и кладутся в `app/Dto/Procurement/Ai/` — подпапки `Screening/` и `Estimate/`. Докблоки и `#[Alias]`-атрибуты — часть промта, пишутся по-русски как инструкции модели. Требуется `spatie/laravel-data` (если не установлен — `composer require spatie/laravel-data`). Фаза завершена, когда генераторы дают стабильный (байт-в-байт воспроизводимый) промт-блок и валидную JSON-схему для каждого шага, всё под тестами.

### P2.3 — Генераторы: prompt-контекст и responseJsonSchema

**Status:** ⬜ Not started

**Why:** Двойная фиксация контракта (D2): исходник передаёт семантику, JSON Schema — принуждает структуру; оба обязаны производиться из одного класса, иначе рассинхронизация вернётся.
**Scope Included:** оба генератора; функция `rulesHash(string $systemPart): string` (sha1); детерминизм вывода (стабильная сортировка файлов); юнит-тесты: снапшот промт-блока для ScreeningResult, схема для RowsChunkResponse валидна (json_decode + обязательные ключи type/properties/required), рекурсия/вложенность ограничена.
**Scope Excluded:** композиция полного промта из БД-правил (P3.3); вызовы LLM.
**Inputs:** приём v1 — `Old/app/Services/PromptService.php::getCleanSchema` (regex-очистка); ограничения responseJsonSchema — research/E §2 (плоскость, маленькие enum, рекурсивный $ref только в non-required, схема тарифицируется).
**Files:** app/Services/Llm/Schema/{PromptContextGenerator,JsonSchemaGenerator}.php · tests/Unit/Llm/{PromptContextGeneratorTest,JsonSchemaGeneratorTest}.php
**Required Reads:** 1) Old/app/Services/PromptService.php 2) app/Dto/Procurement/Ai/ (результат P2.1–P2.2) 3) plans/EST-AI/research/E-gemini-research.md §2
**Implementation Rules:** генерация схемы — ручной Reflection-маппер по Data-классам (нативной генерации JSON Schema в spatie/laravel-data НЕТ — не искать несуществующий API; TypeScript-transformer не подходит); НЕ тянуть тяжёлые сторонние json-schema пакеты без нужды; `final readonly`, без состояния.
**Code Guidance:** выход генераторов должен быть байт-в-байт стабильным между запусками (это база rules_hash и implicit-cache префикса — research/E §1); никаких timestamp/рандома в выводе; схему держать компактной: без description-дублей из докблоков (семантика уже в prompt-контексте), enum-значения — короткие; снапшот-тест обновляется осознанно (assertMatchesSnapshot или файл-фикстура в tests/fixtures/).
