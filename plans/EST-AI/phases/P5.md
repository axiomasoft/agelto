# P5 — Скрининг (первичный анализ)

## Phase Context

Фаза 4b роадмапа, ТЗ 03 §3.4: дешёвая классификация документа с минимальным ответом. Экономика (D6): скринится ТОЛЬКО первые N страниц PDF (default 4) — режем PDF на бэкенде через **qpdf** (D28: бесплатный FPDI не читает PDF ≥1.5 с compressed xref; Gemini не принимает диапазон страниц параметром); маршрут `(any, screening)` → gemini-2.5-flash-lite. Результат — `prc_ai_analyses(step=screening)` (unique по `(document_version_id, step)` уже в схеме) с `document_type`; ветвление: estimate → очередь извлечения; иной известный тип → статус `screened`, стоп; unknown → `ignored`; borderline-confidence → эскалация/пометка (D36); нечитаемый/битый файл → `unprocessable` с reason (D32). Стоит на P2 (ScreeningResult), P3 (LLM-слой), P4 (jobs-каркас). Фаза завершена: полный путь prepared→screened/ignored/unprocessable на FakeLlmProvider под тестами, включая ветвления, borderline и идемпотентность.

### P5.1 — ScreeningJob + процессор с резкой первых страниц

**Status:** ⬜ Not started
**Intent:** `ScreeningJob` (очередь ai_screening, PipelineJob-абстракт) + `app/Services/Procurement/Screening/ScreeningProcessor.php`: создать/найти `Ai\Analysis(step=screening)` (firstOrCreate по unique), взять lease, вырезать первые N страниц PDF (`PdfPageSlicer` — обёртка над **qpdf CLI**, D28), загрузить срез через LlmProvider (Files API), собрать промт (PromptComposer, шаг `screening:classify`), вызвать completeStructured со схемой ScreeningResult, прогнать валидационный каскад, записать результат в `analysis.result` + `document_type`, перевести статусы.
**Why:** Первая точка, где весь LLM-слой собирается в боевой сценарий; экономия токенов здесь определяет стоимость всего потока (каждый документ проходит скрининг).
**Scope Included:** job, процессор, `PdfPageSlicer` (применяется ТОЛЬКО к PDF: N страниц → временный PDF через qpdf; изображения после подготовки идут целиком без резки — vision-путь; прочие нечитаемые форматы, дошедшие до скрининга, — `unprocessable(reason=unreadable_format)`, D32, НЕ generic failed); запись rules_hash/finish_reason в Analysis; фиксация usage через LlmCallRecorder; тесты на FakeLlmProvider (успех, MAX_TOKENS→re-ask, фатальный→failed).
**Scope Excluded:** ветвление по типу и ignore-правила (P5.2). Enum `DocumentStatus::Unprocessable` + `UnprocessableReason` УЖЕ СОЗДАНЫ в P4.2 (D38 — P4 исполняется раньше P5); P5.1 лишь ДОПОЛНЯЕТ `UnprocessableReason` кейсами `unreadable_format`/`password_protected` (битый/зашифрованный PDF), P6.1 — `provider_limit_*` (D32).
**Inputs:** N страниц — `config('ai.screening.pages', 4)`; v1-замысел «первые 3-4 страницы» (research/B §5 — в v1 не был реализован, слался весь файл); контракт ScreeningResult (P2.1); qpdf-канон — D28, research/L finding 2.
**Files:** app/Jobs/Procurement/ScreeningJob.php · app/Services/Procurement/Screening/{ScreeningProcessor,PdfPageSlicer}.php · app/Enums/Procurement/{DocumentStatus,UnprocessableReason}.php (добавление кейсов) · docker/ (Dockerfile worker-образа — установка qpdf) · tests/Feature/Procurement/Screening/ScreeningProcessorTest.php · tests/Unit/Procurement/Screening/PdfPageSlicerTest.php · tests/fixtures/documents/{sample-multi-page.pdf,sample-pdf17-compressed-xref.pdf}
**Required Reads:** 1) docs/specs/v2/03-document-pipeline.md §3.4 2) app/Services/Llm/ (P3-результат: контракты, композер, валидатор) 3) Old/app/Process/DocumentAnalysis/PrimaryAnalysisProcessor.php (guards, порядок статусов) 4) docs/specs/v2/08-estimate-extraction.md §скрининг 5) app/Enums/Procurement/DocumentStatus.php (текущие кейсы)
**Implementation Rules:** **НЕ** `composer require setasign/fpdi` — резка через `qpdf` бинарь (`qpdf in.pdf --pages . 1-N -- out.pdf`); проверить наличие qpdf в worker-образе, при отсутствии добавить в Dockerfile (по образцу gd/zip из P4.2) + smoke-проверка `qpdf --version` в тесте окружения; страницы ≤ N — файл как есть, без резки; статус `running` у Analysis ставится в job после lease (v1-канон «в воркере, не до commit»); user-часть промта минимальна («Классифицируй документ по правилам»), вся семантика — в системной части (кэшируемый префикс).
**Code Guidance:** временный срез PDF удалять в finally; qpdf нативно читает PDF 1.5–1.7 (compressed xref/object streams) — ключевая причина отказа от бесплатного FPDI (research/L finding 2); ошибку qpdf на битом/зашифрованном PDF маппить в `unprocessable` с конкретным reason (unreadable_format/password_protected), НЕ в retryable failed; maxTokens скрининга маленький (config, default 1024); не переводить статус документа здесь (это P5.2); тест PdfPageSlicer — на фикстуре 10-стр. **Validation:** `docker compose exec app php artisan test --filter=Screening` зелёный; `docker compose exec horizon qpdf --version` работает (или проверка в тесте окружения); pint чистый.

### P5.2 — Ветвление, ignore-правила, события

**Status:** ⬜ Not started
**Intent:** Довести скрининг до терминала: маппинг ScreeningResult → статус документа (`estimate` → dispatch EstimateExtractionJob afterCommit + статус остаётся screened до извлечения; известный тип → `screened`; `unknown`/ignore-правило → `ignored`); конфигурируемые ignore-правила (по подстроке в subject/названии закупки — v1-канон «Поставка продуктов питания»); доменные события переходов.
**Why:** Ветвление — «дёшево → дорого»: именно тут отсекаются нецелевые документы и экономятся extraction-токены.
**Scope Included:** `ScreeningOutcomeHandler` в `app/Services/Procurement/Screening/`; config `ai.screening.ignore_rules`; **borderline-зона confidence** (D36): значения в `[config('ai.screening.confidence_low',0.4), config('ai.screening.confidence_high',0.6)]` НЕ уходят молча в ignored — либо эскалация скрининга на модель классом выше (следующий priority маршрута), либо пометка `needs_review=true` в analysis.result для выборочного операторского ревью (выбор поведения — config-флаг `ai.screening.borderline_action` = escalate|flag, default flag); переходы статусов через store-репозиторий + `storeEvent`; интеграционный тест сценариев ТЗ §6: «не-смета сохраняет тип без разбора», «unknown отсекается», «borderline помечается/эскалируется, не теряется», «архив со сметой внутри доходит до кандидата» (сквозной: P4.2-фикстура + FakeLlmProvider), «повтор идемпотентен».
**Scope Excluded:** сам EstimateExtractionJob (P6.1 — здесь только dispatch класса-заглушки, если P6 ещё не исполнен, диспатч за feature-flag `config('ai.extraction.enabled')`).
**Inputs:** ТЗ 03 §3.4 ветвление; v1 ignore-правила — research/C §5 (`config('platform.estimate.ignore_rules')`); borderline-канон — D36, research/L finding 6.
**Files:** app/Services/Procurement/Screening/ScreeningOutcomeHandler.php · config/ai.php · tests/Feature/Procurement/Screening/ScreeningBranchingTest.php
