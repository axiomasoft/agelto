# P5 — Скрининг (первичный анализ)

## Phase Context

Фаза 4b роадмапа, ТЗ 03 §3.4: дешёвая классификация документа с минимальным ответом. Экономика (D6): скринится ТОЛЬКО первые N страниц PDF (default 4) — режем PDF на бэкенде (Gemini не принимает диапазон страниц параметром); маршрут `(any, screening)` → gemini-2.5-flash-lite. Результат — `prc_ai_analyses(step=screening)` (unique по `(document_version_id, step)` уже в схеме) с `document_type`; ветвление: estimate → очередь извлечения; иной известный тип → статус `screened`, стоп; unknown → `ignored`. Стоит на P2 (ScreeningResult), P3 (LLM-слой), P4 (jobs-каркас). Фаза завершена: полный путь prepared→screened/ignored на FakeLlmProvider под тестами, включая ветвления и идемпотентность.

### P5.1 — ScreeningJob + процессор с резкой первых страниц

**Status:** ⬜ Not started
**Intent:** `ScreeningJob` (очередь ai_screening, PipelineJob-абстракт) + `app/Services/Procurement/Screening/ScreeningProcessor.php`: создать/найти `Ai\Analysis(step=screening)` (firstOrCreate по unique), взять lease, вырезать первые N страниц PDF (`PdfPageSlicer` на setasign/fpdi), загрузить срез через LlmProvider (Files API), собрать промт (PromptComposer, шаг `screening:classify`), вызвать completeStructured со схемой ScreeningResult, прогнать валидационный каскад, записать результат в `analysis.result` + `document_type`, перевести статусы.
**Why:** Первая точка, где весь LLM-слой собирается в боевой сценарий; экономия токенов здесь определяет стоимость всего потока (каждый документ проходит скрининг).
**Scope Included:** job, процессор, `PdfPageSlicer` (N страниц → временный PDF; для не-PDF после подготовки — эскалация в failed с понятной ошибкой); запись rules_hash/finish_reason в Analysis; фиксация usage через LlmCallRecorder; тесты на FakeLlmProvider (успех, MAX_TOKENS→re-ask, фатальный→failed).
**Scope Excluded:** ветвление по типу и ignore-правила (P5.2); vision-специфика сканов (пометка уже есть из P4.2 — скрининг картинок идёт тем же путём, файл целиком).
**Inputs:** N страниц — `config('ai.screening.pages', 4)`; v1-замысел «первые 3-4 страницы» (research/B §5 — в v1 не был реализован, слался весь файл); контракт ScreeningResult (P2.1).
**Files:** app/Jobs/Procurement/ScreeningJob.php · app/Services/Procurement/Screening/{ScreeningProcessor,PdfPageSlicer}.php · tests/Feature/Procurement/Screening/ScreeningProcessorTest.php · tests/Unit/Procurement/Screening/PdfPageSlicerTest.php · tests/fixtures/documents/sample-multi-page.pdf
**Required Reads:** 1) docs/specs/v2/03-document-pipeline.md §3.4 2) app/Services/Llm/ (P3-результат: контракты, композер, валидатор) 3) Old/app/Process/DocumentAnalysis/PrimaryAnalysisProcessor.php (guards, порядок статусов) 4) docs/specs/v2/08-estimate-extraction.md §скрининг
**Implementation Rules:** `composer require setasign/fpdi` при отсутствии; страницы ≤ N — файл как есть, без резки; статус `running` у Analysis ставится в job после lease (v1-канон «в воркере, не до commit»); user-часть промта минимальна («Классифицируй документ по правилам»), вся семантика — в системной части (кэшируемый префикс).
**Code Guidance:** временный срез PDF удалять в finally; maxTokens скрининга маленький (config, default 1024) — ответ крошечный по построению; не переводить статус документа здесь (это P5.2 — процессор возвращает результат, ветвление отдельно); тест PdfPageSlicer — на фикстуре 10-страничного PDF выходит 4-страничный.
**Validation:** `docker compose exec app php artisan test --filter=Screening` зелёный; pint чистый.
