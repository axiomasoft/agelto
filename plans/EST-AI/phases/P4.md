# P4 — Подготовка документов и мост пайплайна

## Phase Context

Фаза 4a роадмапа: довести документ от `downloaded` до `prepared` и включить реальный мост крауling→пайплайн. Сейчас `app/Services/Procurement/PipelineDispatcher.php` — заглушка (только Log::info), Jobs в проекте нет вообще, Horizon стоит без очередей пайплайна. Канон v1 переносится: lease (атомарный `UPDATE ... WHERE locked_until IS NULL OR < now()`, TTL 600с, try/finally), status-guard в начале Job, идемпотентность через unique-констрейнты, error-блок + backoff. FSM документа: `docs/specs/v2/03-document-pipeline.md` §2. Стратегии подготовки — по v1 (`Old/app/Process/DocumentPrepare/Strategies/`) с усилением из ТЗ §3.3 (zip-бомбы, vision-пометка). Структура: процессная когезия в `app/Services/Procurement/Prepare/`, Jobs — `app/Jobs/Procurement/` (D1). Фаза завершена: архив со сметой внутри порождает дочерние документы, Excel становится PDF, статусы двигаются, повтор любого job — no-op.

### P4.2 — PrepareDocumentJob и стратегии подготовки

**Status:** ⬜ Not started
**Intent:** `PrepareDocumentJob` (очередь doc_prepare) + `DocumentPreparer` в `app/Services/Procurement/Prepare/` с цепочкой стратегий (интерфейс `PreparationStrategy::canProcess/process`, выбор по расширению/сигнатуре, реестр в `config/ai.php`): `ArchiveStrategy` (zip → дочерние Document+DocumentVersion c `parent_version_id`, дети входят в пайплайн с индексации; лимиты zip-бомбы: глубина ≤2, файлов ≤200, суммарно ≤500МБ), `SpreadsheetStrategy` (xls/xlsx → PDF, landscape + fitToWidth(1)/fitToHeight(0) — v1-урок, иначе смета режется по столбцам; результат в `prepared_storage_path`), `ImageStrategy` (пометка vision-ветки, без конвертации), `PassthroughStrategy` (pdf/текст). **Scope Excluded:** RAR/7z (фиксировать Pending Work — нужен бинарный тул, отложено до появления реальных кейсов); OCR/предобработка сканов; скрининг; замена движка конверсии на LibreOffice (D35 — задокументированный рычаг, реализуется при реальных проблемных файлах, не сейчас).
