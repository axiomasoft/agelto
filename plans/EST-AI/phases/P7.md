# P7 — Экономика токенов, надёжность, eval-контур

## Phase Context

Достройка вокруг рабочего пайплайна (P4–P6): управление context-кэшами и мониторинг implicit-хитов, отчёт стоимости, перенос v1-наблюдаемости (stuck-check, алерты), и eval-контур — датасет эталонных смет + минимальный раннер. Eval-контур — прямая подготовка к следующему шагу владельца: другая модель будет парсить папку предзаготовленных смет и наполнять промты; ей нужны (а) команда импорта эталонов в `prc_ai_dataset_examples`, (б) метрики, показывающие, стало ли лучше. Схема БД готова (dataset_examples, eval_runs, eval_results). Роутинг-матрица и провайдеры сидируются здесь же.

### P7.4 — Датасет эталонов и eval-раннер

**Status:** ⬜ Not started
**Intent:** Команда `ai:dataset:import {path}` — импорт папки эталонных смет (пары: исходный файл + gold-JSON в контракте P2.2) в `prc_ai_dataset_examples` (+загрузка файла в object storage, создание Document/Version вне краулинга — source=manual); `ai:eval:run` — прогон текущего пайплайна по голдену (FakeLlm недопустим — реальный маршрут, но запускается вручную владельцем; в CI — только dry-run на 0 примеров), метрики field-level precision/recall/F1 + row coverage → `prc_ai_eval_runs/results`, консольный отчёт.
**Why:** ТЗ 04 §5; следующий шаг владельца — другая модель наполняет промты по папке предзаготовленных смет: ей нужны вход (import) и объективная обратная связь (eval), иначе «улучшение промтов» — вслепую.
**Scope Included:** обе команды; формат папки задокументировать в спеке 08 (`<name>.pdf` + `<name>.gold.json`); расчёт метрик (сравнение по (row_index, field), нестрогое сравнение строк — trim/collapse spaces); тесты импорта и расчёта метрик на фикстурах (без LLM).
**Scope Excluded:** shadow-режим и CI-гейт (Фаза 6 роадмапа целиком — после появления реального голдена); ANLS-метрики.
**Inputs:** схема dataset_examples/eval_* — research/D §Схема; метрики — ТЗ 04 §5.
**Files:** app/Console/Commands/Ai/{DatasetImportCommand,EvalRunCommand}.php · app/Services/Procurement/Extraction/EvalMetrics.php · docs/specs/v2/08-estimate-extraction.md (раздел формата папки) · tests/Feature/Ai/{DatasetImportTest,EvalMetricsTest}.php
**Required Reads:** 1) docs/specs/v2/04-llm-providers.md §5 2) app/Models/Procurement/Ai/{DatasetExample,EvalRun,EvalResult}.php 3) app/Dto/Procurement/Ai/Estimate/ (P2.2) 4) tests/Feature/Procurement/{AiAnalysisTest,EstimateTest}.php (существующие schema-тесты)
**Implementation Rules:** gold валидируется контрактом P2.2 при импорте (битый эталон → отказ с перечнем ошибок); eval пишет метрики и per-example результаты, сравнение детерминированное.
**Code Guidance:** метрики считать по полям code/name/unit/quantity/price + row_type; числовое сравнение через bcmath с допуском ±0.01; отчёт: сводная таблица + топ-10 худших примеров; import идемпотентен (updateOrCreate по document_version_id+task+version).
**Validation:** `docker compose exec app php artisan test --filter=DatasetImport --filter=EvalMetrics` зелёный; pint чистый.
