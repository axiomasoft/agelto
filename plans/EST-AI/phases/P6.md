# P6 — Полное извлечение смет

## Phase Context

Фаза 5 роадмапа, ТЗ 03 §3.5 + 04 §4 + спека 08 (P1.2). Многошаговый разбор (D3): (1) паспорт/границы — число строк, разделы, шапка, список смет в документе (в одном файле может быть НЕСКОЛЬКО смет, рвущихся на разных страницах — v1-поле `state`); (2) строки построчными диапазонами (row-range, calibrate 20–50 строк) по кэшированному документу, temperature=0, structured output, каждый ответ несёт буфер `incomplete_items`; (3) итоги/начисления отдельным шагом; (4) merge + stitcher + детерминированная арифметическая валидация в коде; (5) точечный re-run аномального диапазона. Персист: `prc_estimates` + sections/items/resources/totals, сырьё в `raw_result`/`raw_result_ref`, качество в `rows_expected/rows_extracted/validation_status`. Прогресс шагов — `analysis.progress` (jsonb), resume после падения не переизвлекает готовые диапазоны. Всё на контрактах P2 и LLM-слое P3, очередь ai_extraction из P4.1. Тесты — только FakeLlmProvider + JSON-фикстуры чанков.

**Inputs:** алгоритм склейки — спека 08 §алгоритм (транскрипция tmp/agelto2.md ЧАСТЬ 3: маркеры, буфер, правила слияния); допуск ±0.01; decimal-сравнение строками через bcmath.

### P6.4 — Fallback: постраничное окно для сверхбольших документов

**Status:** ⬜ Not started
**Intent:** `WindowedExtractionStrategy`: для документов > порога страниц (config, default 300) — резка PDF на окна по K страниц (default 3) с overlap 1 (PdfPageSlicer из P5.1), независимое извлечение окон тем же rows-контрактом (page-маркеры в user-части), сборка через тот же Stitcher (буфер разрывов уже в контракте).
**Why:** Row-range по целому документу требует, чтобы документ жил в кэше/контексте; гигантские сметы (сотни страниц) превышают пороги explicit-кэша и деградируют качество «lost in the middle» — нужен предохранитель.
**Scope Included:** стратегия + выбор пути в оркестраторе (по page_count из паспорта/метаданных PDF); тесты на FakeLlmProvider (окна с искусственным разрывом строки на стыке — склейка через существующий stitcher).
**Scope Excluded:** оптимизация порога (калибровка на реальных сметах — Pending Work до появления датасета P7.4).
**Inputs:** алгоритм окна — спека 08 (транскрипция tmp/agelto2.md: окно 3, сдвиг с overlap 1, [PAGE_START/END]-маркеры); D3.
