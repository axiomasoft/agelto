## Phase Context

Терминальная фаза после P11 (D21): по ФИНАЛЬНОМУ проекту прокачать AI-контекст, чтобы следующие модели «идеально вписывались в систему». **Routing (plan.md §3): только opus/Fable, effort high — sonnet'ом не исполнять**: нужна целостная картина всего реализованного кода. ### P12.1 — Локальные скилы и гайдлайны по финальному проекту

**Status:** ⬜ Not started
**Intent:** Проанализировать весь финальный проект и привести AI-контекст к факту. Гайдлайны (`.ai/guidelines/`): актуализировать architecture/glossary/navigation под реализованный код (домены, слои, канон имён с новыми сущностями: Correction, gold-петля, PromptStep). Скилы (`.ai/skills/`, зеркало `.claude/skills/`): (1) актуализировать `procurement-pipeline-dev` — стадии P4–P6, dependency map «что менять вместе» (DTO ↔ схема ↔ промт ↔ stitcher ↔ persister), test-gate; (2) НОВЫЙ `estimate-extraction-dev` — правки извлечения: контракты P2 как SSOT, чек-лист «поменял DTO → перегенерируй rules_hash → прогони eval», границы stitcher/validator, calibrate-параметры config/ai.php; (3) НОВЫЙ `llm-layer-dev` — контракт LlmProvider, добавление провайдера-адаптера, кэш-инварианты (prefix-stable, capability-based), учёт стоимости, запреты (реальные LLM-вызовы в тестах, Gemini-специфика в домене); (4) НОВЫЙ `prompt-engineering-agelto` — как писать/версионировать промты (файл→сид→is_protected), композиция и приоритеты, корректирующие hints, eval-цикл `ai:eval:run`, анти-паттерны из docs-private; (5) ревизия `testing-rules` (новые doubles: FakeLlmProvider) и review-осей в `.claude/rules/agelto-reviewer-overrides.md` (ось: LLM-слой/промты).
**Why:** Требование владельца: «прокачанные локальные скилы, чтобы нейросеть идеально вписалась»; без актуальных скилов каждая следующая сессия переоткрывает систему с нуля и нарушает инварианты (кэш, идемпотентность, protected-промты).
**Scope Included:** перечисленные гайдлайны и скилы (создание/актуализация в `.ai/**` + раскатка по канону skills-ssot/skiller); description-фронтматтер каждого скила с чёткими триггерами активации; перекрёстные ссылки на docs/03_Dev (не дублировать содержимое — скил учит ДЕЙСТВОВАТЬ, дока объясняет).
**Scope Excluded:** правка CLAUDE.md/AGENTS.md (P12.2); доработка swissknifeman-реестра (глобальные скилы — вне проекта); переписывание docs/ (P10 закрыта).
**Inputs:** весь код проекта (финальное состояние); plan.md §5 (19+ решений — источник инвариантов для скилов); docs/03_Dev/** (P10); skill `ai-context-workflow` (цикл правок), `skills-ssot` (раскатка).
**Files:** .ai/guidelines/** · .ai/skills/** · .claude/skills/ (раскатка) · .claude/rules/agelto-reviewer-overrides.md
**Required Reads:** 1) .ai/guidelines/ и .ai/skills/ (текущее состояние) 2) plans/EST-AI/plan.md §5 3) docs/03_Dev/ai-context/ (P10.3) 4) app/Services/{Llm,Procurement}/** (финальный код) 5) skill ai-context-workflow
**Implementation Rules:** только мощная модель (Routing §3); правки ТОЛЬКО в `.ai/**`-источниках и `.claude/rules/` — генерируемые файлы не трогать; каждый скил ≤ ~150 строк с эскалацией в docs/snippets, не энциклопедия; описания-триггеры на русском по образцу существующих.
**Code Guidance:** dependency map в скилах — таблицей «меняешь X → обязан проверить Y» (это главная ценность для дешёвых моделей); в llm-layer-dev зафиксировать запреты дословно (никаких прямых Prism-вызовов из домена, никакой Gemini-специфики в контрактах); в prompt-engineering-agelto включить правило «канон промта меняется только через файл+сид, админ-правка protected невозможна by design»; не создавать скилы сверх перечисленных без записи в Decision Log.
**Validation:** `skiller status` (или аналог) видит скилы без ⚠; каждый новый скил активируется на тестовой формулировке задачи (ручная проверка триггеров); grep: скилы не содержат устаревших путей/имён классов.
**Deliverables:** актуализированные гайдлайны, 3 новых + 2 обновлённых скила, обновлённые review-оси.
