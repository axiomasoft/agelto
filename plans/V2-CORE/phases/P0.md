**Scope Included:** `composer.json`/`composer.lock`, `artisan`, `app/`, `bootstrap/`, `config/`, `database/` (пустой), `public/`, `resources/`, `routes/`, `tests/` (стандартный Pest/PHPUnit скелет Laravel 12), `.env.example`.

### P0.2 — Docker-окружение полного стека

**Status:** 🟠 Done with deviations
**Intent:** Docker Compose (dev) со всеми контейнерами: `app` (PHP-FPM+Nginx или alpine-fpm, см. skill `docker-php`), `horizon` (queue worker), `scheduler`, `postgres` (17, с init-скриптом тестовой БД `<app>_test`, skill `docker-postgres`), `redis`, `minio` (S3-совместимое хранилище), `browser` (Node+Playwright, минимальный контейнер-задел без реализации сервиса — просто поднимается и слушает порт-заглушку). Плюс `Makefile` (делегирующий паттерн, skill `makefile`) и `docker-compose.override.example.yml`.
**Why:** Без поднятого стека нельзя гонять тесты (test-gate) и миграции с партиционированием (Фаза 1 нуждается в реальном Postgres 17).
**Scope Included:** `docker/` (Dockerfile'ы app/php, init-скрипты postgres), `docker-compose.yml` (dev: build + bind-mount), `docker-compose.prod.yml` (прод-скелет, не обязательно рабочий на этом шаге, но структурно присутствует по канону `docker-dev-prod`), `docker-compose.override.example.yml`, `Makefile` + `docker/Makefile`.
**Scope Excluded:** Vite dev-service и фронт-сборка (нет фронта на этом шаге — Laravel skeleton без Inertia/Vue); `reverb`/websocket-сервис (не в списке контейнеров ТЗ v2 §3); реальная реализация `browser`-сервиса (Playwright-сервис — Фаза 8, «задел», здесь только пустой healthcheck-контейнер).
**Inputs:** `docs/specs/v2/00-overview.md` §3 (список контейнеров: `app`, `horizon`, `scheduler`, `postgres`, `redis`, `minio`, `browser`, `admin`); skills `docker-php`, `docker-postgres`, `docker-dev-prod`, `docker-services`, `makefile`.
**Required Reads:** 1) `docs/specs/v2/00-overview.md` §3 2) skill `docker-php` (SKILL.md + снипеты Dockerfile) 3) skill `docker-postgres` (снипет `init-test-db.sh`, `pgsql-service.yml`) 4) skill `docker-dev-prod` (снипеты `docker-compose.dev.yml`, `docker-compose.prod.yml`, `.env.example`, `Makefile`) 5) skill `docker-services` (снипет `services.yml` для horizon/scheduler по паттерну queue/scheduler) 6) skill `makefile`.
**Implementation Rules:** Postgres — образ `postgres:17-alpine` (НЕ 16 — ТЗ фиксирует 17), healthcheck `pg_isready`, named volume, init-скрипт создаёт `<app>_test` (имя приложения — взять из `composer.json`/`.env` `APP_NAME`, привести к snake_case, например `agelto_test`). Redis — `redis:7-alpine`, healthcheck `redis-cli ping`. MinIO — официальный образ `minio/minio`, команда `server /data --console-address ":9001"`, healthcheck на `/minio/health/live`, named volume под данные, переменные `MINIO_ROOT_USER`/`MINIO_ROOT_PASSWORD` из `.env.docker`. `horizon` — тот же образ, что `app`, команда `php artisan horizon`, `depends_on: {app: service_healthy, redis: service_healthy, postgres: service_healthy}`. `scheduler` — тот же образ, команда `php artisan schedule:work`. `browser` — минимальный `node:22-alpine` контейнер с `CMD ["tail", "-f", "/dev/null"]` или простым health-эндпоинтом — явно закомментировать в compose, что это задел под будущий Playwright-сервис (Фаза 8), не полноценная реализация. Общий env-блок через YAML-анкор `&app_env` на `app`, переиспользовать в horizon/scheduler. Package manager фронта — **yarn**, не pnpm (расходится со снипетами `docker-vite`, которые используют pnpm — если нужен Node в образе, ставить yarn).
**Code Guidance:** следовать паттерну «одно PHP-изображение переиспользуется app/horizon/scheduler, различие только в `command`» (skill `docker-services`); не изобретать отдельные Dockerfile на каждый сервис. Healthcheck на `/up` для `app` обязателен (Laravel 12 из коробки отдаёт `/up`). Не открывать порты Postgres/Redis/MinIO наружу без необходимости — публиковать только на `127.0.0.1`. Секреты (MinIO root user/password, DB-пароль) — только через `.env`/`.env.docker`, не хардкодить в compose. Не тащить `reverb`/websocket — не требуется на этом шаге. `docker-compose.override.yml` — в `.gitignore`, коммитить только `.example`.
**Validation:** `docker compose config` без ошибок; `docker compose up -d` поднимает все сервисы, `docker compose ps` показывает всех `healthy`/`running`; `curl -fsS http://127.0.0.1:8080/up` (или актуальный порт `app`) отвечает 200.
**Deliverables:** `docker/`, `docker-compose.yml`, `docker-compose.prod.yml`, `docker-compose.override.example.yml`, `Makefile`, `docker/Makefile`.
**Completion Notes:** Все 7 сервисов healthy (`docker compose ps`), `/up` → 200, MinIO health → 200, `docker compose config` валиден для dev и prod. `make ps`/`make up` через делегирующий Makefile проверены. Добавлен `laravel/horizon` (composer require + `horizon:install`) — без пакета команда `php artisan horizon` не существует, контейнер `horizon` был бы бессмысленным; это расширяет заявленный в P0.1 «только дефолтный skeleton» скоуп, но необходимо для работоспособности P0.2.
**Pending Work:** —
**Known Deviations:** (1) top-level `name: agelto_v2` добавлен в оба compose-файла — не было в исходном Implementation Rules, обнаружено на живом хосте: старый v1-стек (та же машина, тот же каталог до переноса в Old/) занимал именованные volume'ы `agelto_pgsql_data`/`agelto_redis_data`/etc под тем же дефолтным именем проекта, новый стек тихо переиспользовал бы их. (2) `build.network: host` добавлен в Dockerfile-билды app/horizon/scheduler — DNS внутри build-контейнеров не резолвился из-за VPN на хосте (подтверждено: то же самое было и в уже запущенном чужом контейнере `sova_app`, не специфично для агелто), без этого `apt-get install` в Dockerfile зависал. (3) PUID/PGID из Implementation Rules убраны как нерабочие для `serversideup/php:8.4-fpm-nginx` (нет соответствующей логики в его `entrypoint.d`); фактический фикс прав на bind-mounted `storage/` — `docker compose exec -u root app chown -R www-data:www-data storage`, задокументирован в самом compose-файле и в `docker-compose.override.example.yml`. (4) Порт Postgres на хосте — `5433`→`5455` (5432 и 5433 заняты другими нативными сервисами на этой машине, не Docker); внутри `agelto_network` контейнеры обращаются к `postgres:5432` — конфликт не влияет на связность между контейнерами, только на хостовый доступ.

### P0.3 — Test-gate и healthcheck зелёные

**Status:** ⬜ Not started
**Intent:** Довести до зелёного `make test-preflight` (skill `db-test-preflight`) + `test-isolation-guard` (bootstrap.php/TestEnvironmentGuard) + пустая миграция ядра (`0000_00_00_000000_create_... ` — фактически дефолтные Laravel-миграции `users`/`cache`/`jobs`, без доменных таблиц v2 — те идут в Фазе 1) применяется в контейнере без ошибок.
**Why:** Формальный критерий приёмки Фазы 0 по `06-roadmap.md`: «`make test-preflight` зелёный, `/up` healthy, пустая миграция ядра применяется».
**Scope Included:** `phpunit.xml` (`DB_DATABASE=<app>_test`, `APP_ENV=testing`), `tests/bootstrap.php` (три источника env: `$_SERVER`/`$_ENV`/`putenv`), `tests/Support/TestEnvironmentGuard.php` (или аналог, namespace `Tests\Support`), `tests/TestCase.php` (`createApplication()` вызывает guard), `Makefile` target `test-preflight`/`test` (зависимость), запуск дефолтных Laravel-миграций (`users`, `cache`, `jobs` — из коробки Laravel 12) в контейнере `app` против `<app>_test`.
**Scope Excluded:** доменные миграции v2 (Фаза 1); реальные Pest-тесты домена (их ещё нет, только скелет из `laravel/laravel` + guard-тест).
**Inputs:** skills `db-test-preflight`, `test-isolation-guard`, `laravel-testing`.
**Required Reads:** 1) skill `test-isolation-guard` (снипеты `bootstrap.php`, `TestEnvironmentGuard.php`, `TestCase.php`) 2) skill `db-test-preflight` (снипет `preflight.sh`, `Makefile.test`) 3) `docker-compose.yml` из P0.2 (имя сервиса Postgres, имя тестовой БД из init-скрипта).
**Implementation Rules:** Тестовая БД должна оканчиваться на `_test` (жёсткий гейт в guard, regex `^[a-z0-9_]+_test$`). Guard читает `config()`, не `env()` напрямую. Все тестовые команды — только через `docker compose exec app ...`, никогда напрямую на хосте (в контейнере `/usr/bin/php` — версия образа, не путать с хостовым `/usr/bin/php8.4/8.5`, используемым только для локальных ad-hoc проверок вне Docker).
**Code Guidance:** `TestEnvironmentGuard::assertIsolatedTestDatabase()` бросает `RuntimeException` с русским сообщением и инструкцией, если БД не оканчивается на `_test` — это единственная линия защиты, недопустимо её ослаблять/обходить. Не используем `RefreshDatabase` до того, как guard подключён в `TestCase::createApplication()` — порядок важен (guard первым). Не коммитить `docker-compose.override.yml`. Один smoke-тест (`tests/Unit/ArchTest.php` или `tests/Feature/HealthCheckTest.php`) проверяющий, что `/up` отвечает 200 — как минимальный живой критерий приёмки, не заглушка.
**Validation:** `make test-preflight` завершается успехом (exit 0); `docker compose exec app php artisan test --compact` зелёный (хотя бы дефолтный скелетный тест + guard-тест); `docker compose exec app php artisan migrate --database=pgsql` (dev БД) и отдельно `--env=testing` (тестовая БД) без ошибок.
**Deliverables:** зелёный test-gate, healthcheck `/up`, применённые дефолтные миграции в dev и test БД.
