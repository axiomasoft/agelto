## Решение

**Маска («узел + все вложенные») — основной и единственный рабочий режим фильтра; выбор конкретных кодов через дерево остаётся как дополнительный сценарий поверх той же формы запроса.** В профиле хранится КОД ОКПД2, а не внутренний id ЕИС; id резолвится картой, пересобираемой обходом `GET /epz/api/nsi/okpd2/children.html?parentId=<id>`. Закрывает Q6. **Consequences:** появляется собственная сущность «карта код → id НСИ», её надо сидировать и уметь пересобирать; зато профиль переживает смену внутренних id на стороне ЕИС

## Почему

Требование владельца («маска вполне устроит, детальные коды — через модалку», `brief/01-refinements.md`) совпало с поведением площадки: без `okpd2IdsWithNested=on` выдача ПУСТА, т.к. закупки ссылаются на листовые коды, а не на группу.
