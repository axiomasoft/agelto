## Решение

**Контракт-блок и критерий завершения P2 пересобраны по факту детализации (reconcile `plan-protocol` §5).** Скелет заявлял завершением «профиль с `43` даёт выборку только строительных закупок, доказано тестом по фикстуре» — это физически недостижимо: отбор делает СЕРВЕР ЕИС, а фикстура есть уже отданный сервером ответ, и тест по ней доказывает лишь нашу же подложку. Новый офлайн-критерий: профиль невозможно сохранить без узла ОКПД2; уходящий запрос несёт `okpd2Ids` с резолвленными id и `okpd2IdsWithNested=on`; нерезолвящийся код даёт явный отказ. Проверка ДЕЙСТВИЯ фильтра — живая и живёт в P5. `supersedes` формулировку завершения из скелета P2. **Consequences:** внутри P2 не остаётся ни одного доказательства, что выборка действительно строительная — этот риск целиком лежит на P5, и до его закрытия «фильтр работает» держится на разведке 2026-08-06, а не на регрессионном гейте

## Почему

Усиливает уже записанное последствие D8 («страховки в виде отбора по колонке у нас нет; healthcheck обязан проверять именно действие фильтра»). `RAG:— (repo-grounded: research/03-p2-okpd2-design.md §6)`
