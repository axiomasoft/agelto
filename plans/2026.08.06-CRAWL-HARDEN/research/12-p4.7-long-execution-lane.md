# P4.7 — фактура длинного execution lane

Дата: 2026-08-08 · Скоуп: только `CrawlRunJob` архивного профиля с явным окном дат.

## 1. Что реально ограничено

`supervisor-crawl` читает `crawl` через connection `redis`, имеет `timeout=300`, `tries=1`,
`maxProcesses=1`; `queue.connections.redis.retry_after=360`. `CrawlRunJob` жёстко вызывает
`onQueue('crawl')`. Продолжение ставится только после возврата процессора со статусом `running`.
Fresh-процессор добровольно выходит по `crawler.run.checkpoint_seconds=240`, archive-процессор
этот таймер не читает. Поэтому 300 секунд — lease одной job, а не ограничение размера сайта и не
лимит числа запросов. `RAG:— (repo-grounded: config/horizon.php supervisor-crawl;
config/queue.php connections.redis; app/Jobs/Procurement/CrawlRunJob.php;
app/Services/Procurement/Modes/FreshRunProcessor.php;
app/Services/Procurement/Modes/ArchiveRunProcessor.php)`

## 2. Почему годовой CSV-обход не равен годовому детальному парсингу

Архивный сканер получает CSV-блоки листинга, сохраняет курсор после каждого блока и передаёт строки
в ingest. Детальная карточка и смета живут в других стадиях/job'ах. Сидовый архивный профиль имеет
явное окно `2025-01-01…2025-12-31`, source method `csv`; оно задаёт предмет обхода, но не включает
детальную обработку каждой закупки. `RAG:— (repo-grounded:
app/Services/Procurement/ArchiveWindowScanner.php;
app/Services/Procurement/Modes/ArchiveRunProcessor.php;
database/seeders/Procurement/CrawlerProfileSeeder.php)`

## 3. Калибровка начального long-lease

Сохранённый боевой замер в `config/crawler.php`: 194 блока, все HTTP 200, средняя длительность
4 577 мс, максимум 11 125 мс; throttle 1 000–4 000 мс. Грубая верхнеуровневая оценка средней
сетевой части с паузой: `194 × (4.577 + 2.5) ≈ 1 373 с ≈ 23 мин`, без точной цены DB ingest.
Отсюда начальный `long.timeout=3600` даёт более чем двукратный запас относительно измеренной
сетевой части; `retry_after=3900` сохраняет обязательный порядок `timeout < retry_after`.
Значение конфигурируемое через env, но профиль хранит только стабильный класс `standard|long`.
`RAG:— (repo-grounded: config/crawler.php throttle; config/horizon.php; config/queue.php)`

## 4. Выбранный шов

- `prc_crawlers.execution_lane`: enum `standard|long`, default `standard`.
- `standard` остаётся `connection=redis`, `queue=crawl`, `timeout=300`, `retry_after=360`.
- `long` получает отдельные logical connection `redis_crawl_long`, queue `crawl_long`, supervisor
  `supervisor-crawl-long`, `timeout=3600`, `retry_after=3900`, `maxProcesses=1`, `tries=1`.
- Оба connection используют тот же Redis server/database; отдельный Redis не нужен.
- `StartCrawlerRunAction` передаёт lane в job, а continuation сохраняет его. Прямой job-dispatch
  без lane безопасно остаётся `standard` для обратной совместимости тестов/внутренних вызовов.
- Compose grace становится больше long timeout (4200 секунд), иначе Docker способен оборвать
  job раньше Horizon timeout.

Один supervisor без отдельной connection отвергнут: единый `retry_after=360` меньше long timeout и
может повторно выдать ещё работающую job. Raw seconds в профиле отвергнуты: это смешивает
продуктовый профиль с инфраструктурным lease и создаёт неконтролируемые значения. `timeout=0`,
сутки и месяц отвергнуты: они скрывают зависания и делают crash/deploy-recovery слишком долгим.

## 5. Граница обещания

P4.7 не добавляет archive checkpoint по секундомеру и не обещает бесконечный автономный job.
Он устраняет практический конфликт временного годового CSV-профиля с пятиминутным стандартным
lane. Курсор уже обеспечивает возобновление после контролируемого/аварийного останова. Если
production-метрика покажет, что час недостаточен, корректируется значение long lane отдельным
решением; detailed jobs, request throttle и будущий общий budget площадки P4.4 не меняются.
