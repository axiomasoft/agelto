# P4.8 — фактура восстановления общих validation-гейтов P4.1 — 2026-08-08

## Метод

Проверены код сидера, миграция и модель реестра, текущий architecture-test и все вхождения
`zakupki.gov.ru` в `tests/`.

```bash
rg -n -C 3 'EisPlatformSeeder|uuid' database/seeders database/migrations app/Models tests
rg -n -C 3 'Estimate|estimate' app/Services/Procurement/{Screening,Extraction,Fixture} tests/Unit/Architecture
rg -l 'https?://zakupki\.gov\.ru' tests/ | sort
```

## Факты

1. `DatabaseSeeder` использует `WithoutModelEvents`. Поэтому `Registry::booted()` не генерирует
   обязательный `prc_registries.uuid` при `EisPlatformSeeder::run()`: его `updateOrCreate()` не
   передаёт `uuid`, хотя миграция требует `uuid()->unique()`.
2. `CoreKnowsNoDocumentTypeTest` реально видит 102 core-класса вместо зафиксированных 98. Четыре
   добавленных после последней сверки — `FinishReason`, `CrawlRunJob`, `OutboundProxy` и
   `ContractAttributeReader`; каждый лежит в динамическом периметре теста.
3. Два оставшихся нарушения type-boundary не являются ложными: `WorkingCopyProvisioner` знает
   `GoldImportCommand` только через импорт/докблок, а `PreflightDecision` импортирует
   `Estimate\\ExtractionRoute`, хотя решение preflight не зависит от типа документа.
4. URL ЕИС в тестах — это fixture values, входы моделей или `Http::assertSent()` после
   `Http::fake()`. Текстовый запрет URL не проверяет сетевой побочный эффект и потому ложно
   красный; Laravel HTTP factory умеет fail-closed режим `Http::preventStrayRequests()`.
