# P4.9 — фактура checkpoint при исчерпании request budget

**Дата:** 2026-08-08  
**Канал:** read-only recon рабочего дерева после закрытия P4.4 (`695b2524`)  
**Внешних запросов:** нет

## Наблюдения

1. `ArchiveWindowScanner::scan()` возвращает `void`. Операторский pause/cancel завершает метод
   обычным `return`, а успешный полный дренаж дня заканчивается тем же внешним контрактом.
   Вызывающий код не может различить «день дренирован» и «день прерван».
   `RAG:— (repo-grounded: app/Services/Procurement/ArchiveWindowScanner.php)`
2. `ArchiveRunProcessor`, `DeltaScanProcessor` и
   `BacklogRescanProcessor::drainWindow()` после каждого возврата из `scan()` безусловно
   увеличивают день и записывают курсор следующего дня. Проверка `RunStatus` стоит только в начале
   следующей итерации, то есть прерванный текущий день уже потерян из курсора.
   `RAG:— (repo-grounded: app/Services/Procurement/Modes/ArchiveRunProcessor.php; app/Services/Procurement/Modes/DeltaScanProcessor.php; app/Services/Procurement/Modes/BacklogRescanProcessor.php)`
3. `PlatformBudgetExhaustedException` из `collectListing()` сканер не перехватывает.
   `ArchiveRunProcessor` и `BacklogRescanProcessor` ловят её как обычный `Throwable` и переводят
   archive-run в `Failed`; delta-команда ловит исключение на внешнем уровне и возвращает failure.
   Это противоречит уже принятой семантике P4.4: исчерпание окна request budget — checkpoint,
   а не ошибка закупки или площадки.
   `RAG:— (repo-grounded: app/Exceptions/Procurement/Crawler/PlatformBudgetExhaustedException.php; app/Services/Procurement/Modes/ArchiveRunProcessor.php; app/Services/Procurement/Modes/BacklogRescanProcessor.php; app/Console/Commands/Procurement/RunDeltaScan.php)`
4. Продолжение уже имеет три носителя и не требует новой очереди: archive-job самодиспатчится,
   пока `RunStatus::Running`; delta запускается своим cron; backlog sweep запускается каждые
   15 минут и повторно берёт fresh-run, пока `backlog_rescanned_at` не записан.
   `RAG:— (repo-grounded: app/Jobs/Procurement/CrawlRunJob.php; routes/console.php; app/Services/Procurement/Modes/BacklogRescanProcessor.php)`
5. Ложный гейт P4.4 `grep zakupki.gov.ru tests/` проверяет наличие URL как текста, а не сетевой
   выход. После P4.8 базовый `Tests\TestCase` уже вызывает `Http::preventStrayRequests()`;
   URL легально остаются в фикстурах, model input и `assertSent()`.
   `RAG:— (repo-grounded: tests/TestCase.php; phases/P4.md P4.8 Completion Notes; research/13-p4.8-validation-gates.md)`

## Вывод для ТЗ

Нужен один типизированный результат `ArchiveWindowScanner`, который отделяет полный дренаж от
checkpoint и операторского стопа. День двигается только на результате «дренирован». Исключение
request budget перехватывается ровно в сканере, превращается в checkpoint с сохранением статуса
`Running`; все остальные исключения остаются failure-path. Сетевой acceptance доказывается
наличием `Http::preventStrayRequests()` и зелёным исполняемым тестовым набором, не URL-grep.
