### P1.5 — инвентарь вкладок и полей по шести видам процедур (item-коммит `06a5fb1a`)

Матрица — `artifacts/eis-card-inventory.json` (353 строки), разбор — `findings/P1-card-inventory.md`.
Шесть видов, у каждого исход `снят`; 42 запроса из 60 разрешённых.

1. **Вкладок СВЕРХ известных четырёх нет ни у одного из шести видов.** Перечень брался из
   навигации ЖИВОЙ страницы, не из сида — во всех шести случаях он оказался ПОДМНОЖЕСТВОМ наших
   четырёх. Требование владельца «понять максимальный объём того, что бывает в карточке» на уровне
   вкладок закрыто.
2. **Но перечень вкладок зависит от ЭТАПА, а не от вида процедуры.** Один и тот же `ea20`: на
   «Подаче заявок» — 3 пункта навигации, на завершённом — 4. При этом URL `supplier-results` в
   первом случае отвечает **200 с заглушкой**. Значит состояний у вкладки ТРИ (404 — нет по
   природе · 200-с-заглушкой — ещё не наступило · 200-с-данными), а различаем мы два.
3. **Сегмент типа в URL карточки — не ключ выборки.** Заведомо чужой `zk20` для конкурса даёт
   302 на канонический `ok20`. Отсюда: `okp20` (записан как «тип процедуры» в
   `findings/P1-card-anchors.md` §3) и `pop615` (из навигации 615-карточек) — **алиасы**, а не
   седьмой/восьмой тип; дыры в `card_url_templates` нет.
4. **`ea615`/`po615`: `supplier-results` — HTTP 404 у обоих.** Явный `null` сида (D121) подтверждён
   живой пробой.
5. **У `ea615`/`po615` ни одной `table.tableBlock`**: нет ИКЗ, валюты, финансового обеспечения,
   таблицы позиций. `CommonInfoParser` на них вернёт пустой DTO МОЛЧА — `prc_items`/`prc_financing`
   по этим видам не заполнятся ни при какой починке селекторов.
6. **Подпись имени закупки различается по видам, а у `ezt20` её нет вовсе** при `title NOT NULL` —
   значит у `ezt20` имя приходит только из CSV-листинга.
7. **Источник `prc_documents.kind` найден** — заголовок `h2` над блоком `div.blockFilesTabDocs`
   (снят с артефакта P1.4, живого запроса не делалось). Этим же снимается открытый риск «семь
   блоков `blockFilesTabDocs` вместо одного»: блок на категорию, а для протоколов — блок на
   протокол. Колонка `kind` в схеме есть и сегодня заполняется `null`.
8. **Вердикт Q16:** ни одно поле без носителя не прошло порог трёх признаков D83 — **новых колонок
   матрица не требует**, дефолт jsonb выдерживает всю фактуру.

   закупок, не сотня.
