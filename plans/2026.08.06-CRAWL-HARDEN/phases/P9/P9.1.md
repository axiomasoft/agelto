### P9.1 — Ревизия обоих деревьев и карта переноса

**Intent:** Прежде чем двигать хоть один файл — перечислить оба дерева НА МОМЕНТ ИСПОЛНЕНИЯ, снять
счётный замер (файлы, frontmatter, ссылки), и построить карту «файл → адрес или удаление → какой
живой факт забираем», покрывающую 100% переносимого.
**Why:** Фаза удаляет около 1900 строк текста (8 файлов `docs-private/` + 9 файлов `specs/v2/`), и
единственная реальная опасность операции — «факт исчез вместе с файлом». Спеки при этом известны
как разошедшиеся с кодом (план DOMLANG чинил в них 192 вхождения мёртвых префиксов таблиц —
`RAG:— (repo-grounded: plans/archive/DOMLANG/phases/P6/P6.md:10, findings/P1-audit-verification.md:11)`),
поэтому переносить их «как есть» нельзя, а решать «живой факт или мусор» на бегу, файл за файлом,
значит принимать это решение восемнадцать раз без общей картины. Карта стоит один проход и делает
следующие четыре items механическими.
**Scope Included:** (1) перечень обоих деревьев командой, а не по памяти, с разметкой «переносится
целиком / переносится частично / удаляется как дубль / удаляется как мёртвое»; (2) карта переноса
`findings/P9-docs-map.md`: строка на КАЖДЫЙ файл `docs-private/**`, `docs/specs/v2/**` и
`docs/dev/**` — адрес назначения (файл + раздел), перечень забираемых живых фактов, перечень
СОЗНАТЕЛЬНО не переносимого с причиной; (3) счётный замер `artifacts/P9-docs-baseline.json` —
число md-файлов, число файлов без frontmatter (поимённо), число относительных ссылок, число битых,
с шапкой «дата, `git rev-parse --short HEAD`, команда»; (4) перечень ЖИВЫХ (вне `plans/archive/**`)
ссылок на `docs-private` и `docs/specs/v2` с адресом item'а-правщика; (5) сверка карты с §3
`research/10-p9-docs-design.md` — расхождение фиксируется строкой «рекомендация research /
фактическое решение / почему», а не молча.
**Scope Excluded:** перемещение или удаление хоть одного файла (это P9.3–P9.5) · заведение теста
(P9.2) · написание диаграмм (P9.6/P9.7) · правка `plans/archive/**` в любом виде · дописывание
разделов `03_Dev` за фазы P3–P8 (Л-6 research'а).
**Inputs:** 1) целевая карта-рекомендация — `research/10-p9-docs-design.md` §3;
2) факты дерева — `research/10-p9-docs-design.md` §1;
3) решения владельца — `brief/01-refinements.md` блок P9;
4) замер — `findings/P9-rag-docs-2026-08-06.md` §3;
5) правило «живого факта» — `research/10-p9-docs-design.md` §3.2.

**Implementation Rules:** 1) **Перечни строятся КОМАНДОЙ**: `find docs docs-private -name '*.md'`,
`grep -rn "docs-private\|specs/v2" docs .ai .claude CLAUDE.md` — к моменту исполнения дерево
ОТЛИЧАЕТСЯ от снятого при авторинге (P3–P8 дописали свои разделы), и это норма, а не расхождение.
2) **Карта перечисляет разделы, а не «и т.д.»**: у файла-спеки называются номера разделов, которые
переносятся, и номера, которые нет. 3) **Правило отбора живого факта применяется письменно**: у
каждой строки «не переносим» — причина из закрытого списка (план работ · критерий приёмки фазы ·
открытый вопрос уже закрытого плана · имя таблицы/класса, не подтверждённое деревом · дубль
существующего раздела). 4) Замер снимается ОДНИМ скриптом-однодневкой и кладётся вместе с самим
скриптом в шапку JSON — иначе через неделю это просто числа. 5) Ни один файл вне `plans/**` этим
item'ом не меняется. 6) Спорная строка карты не решается в одиночку: помечается
`[решает P9.4/P9.5 при переносе]` с названными вариантами.
**Code Guidance:** Item производит ДОКУМЕНТЫ, не код: ни класса, ни команды, ни теста. Скрипт
замера — однодневка (python3/awk в одну строку), не повод завести `artisan docs:audit`
(потребителей ровно два — P9.1 и P9.8). Тексты — по-русски, как весь план. **Запрещённые
shortcuts:** карта «по памяти» без открытия файлов; строка «переносится целиком» у спеки, которую
не читали; замер, снятый на грязном рабочем дереве без указания HEAD; включение архивных планов в
перечень правок. **Анти-самообман:** карта, в которой хоть один файл обоих сносимых деревьев не
имеет ни адреса, ни причины удаления, — не карта, а черновик; счётная сверка (число строк карты =
число файлов `docs-private/**` + `docs/specs/v2/**` + `docs/dev/**`) обязана сойтись и быть
названа числом в Completion Notes. **Анти-подгонка:** если рекомендация research'а не подходит по
факту дерева — меняется карта и пишется причина, а не подгоняется факт под рекомендацию.
**Validation:** карта покрывает всё —
`ls docs-private/**/*.md docs/specs/v2/*.md docs/dev/*.md | wc -l` равно числу строк таблицы
переноса в `findings/P9-docs-map.md` (оба числа названы в Completion Notes с якорем на
bookkeeping-коммит) · замер воспроизводим — команда из шапки `artifacts/P9-docs-baseline.json`
на том же HEAD даёт те же числа · перечень живых ссылок полон —
`grep -rn "docs-private\|specs/v2" docs .ai .claude CLAUDE.md | wc -l` равно числу строк перечня ·
кода не тронуто — `git diff --name-only` содержит только `plans/**` ·
`python3 "$SWISSKNIFE/packages/task/scripts/plan-lint.py" plans/2026.08.06-CRAWL-HARDEN` — без
новых ERROR
**Deliverables:** `findings/P9-docs-map.md` (карта переноса с адресом у каждого файла) ·
`artifacts/P9-docs-baseline.json` (счётный замер с шапкой) · перечень живых ссылок с адресами
item'ов · один item-коммит по путям `Files` + bookkeeping-коммит
