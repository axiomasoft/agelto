### P10.6 — Не терять concurrent proxy outcomes в breaker и EWMA

**Intent:** Каждый завершившийся proxy request должен ровно один раз повлиять на global/target
breaker state и EWMA даже при одновременных channels.

**Why:** Detached models и ordinary update дают lost update; два failure могут записать счётчик 1,
а два latency samples — одну и ту же EWMA (`RAG:— (repo-grounded: F8 audit, D137)`).

**Scope Included:** (1) short DB transaction inside outcome persistence; (2) lock order proxy then
target; (3) fresh reread and breaker/EWMA calculation under lock; (4) global-only, target-only,
success and half-open semantics preserved; (5) transition log emitted once after commit; (6) real
two-session failure and latency regressions using P10.1 helper.

**Scope Excluded:** HTTP inside transaction · changing proxy selection/geo rules · changing breaker
threshold defaults · global queue serialization · retrying the network request from reportOutcome.

**Implementation Rules:** 1) HTTP response/exception is resolved before entering the transaction.
2) Lock proxy row first, then the exact target row, in every outcome branch. 3) Recompute from fresh
locked attributes; ignore counts/EWMA on the lease's detached models. 4) Persist both rows within
one transaction when outcome touches both. 5) Emit auto-disable/open transition only if this
transaction crossed the state boundary; log after commit and once. 6) Two simultaneous failures
from zero produce two; threshold transition count is one. 7) EWMA test names alpha and expected
value/order tolerance; both samples must be represented. 8) Existing target-vs-global failure
taxonomy tests remain unchanged in meaning.

**Code Guidance:** Repository may expose `lockProxyAndTarget()`/fresh update methods, but breaker
math stays in the service/policy, not Eloquent model hooks. Keep the lock critical section free of
logs that can perform I/O. Запрещённые shortcuts: atomic increment only (does not solve EWMA);
optimistic overwrite from the lease model; reverse lock order in target-only branch; wrapping the
network call. Анти-самообман: sequential `reportOutcome()` calls already pass today and are not
the regression. Анти-подгонка: do not raise breaker threshold or loosen exact transition count.

**Validation:** existing `ProxyResolverTest` remains green · real concurrent failures persist count
2 · at threshold breaker opens once and one transition log is emitted · concurrent successes/
latencies include both samples in final EWMA · no deadlock under mixed global/target outcomes ·
Pint/PHPStan · no new full-suite delta.

**Deliverables:** locked fresh-state proxy outcome transaction · once-only transition logging ·
real concurrency regressions for counts/breaker/EWMA · application/test item commit plus separate
bookkeeping commit.
