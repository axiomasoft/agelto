# P4 — Архив (перекачка истории)

## Phase Context

Archive-режим (`02-crawling.md` §4.2, roadmap Фаза 3b) — перекачка исторического потока
для обучающего датасета. Идём по дням возрастающей даты: `publishDateFrom = publishDateTo =
<день>`, `sortDirection=true`; если день переполняет серверный потолок (~10k, «тихий cap»
§3.3) — **рекурсивное бинарное ценовое дробление** (`priceFromGeneral`/`priceToGeneral`;
аналог v1 `priceSplitHook`, но качаем CSV). Переполнение детектируется БЕЗ счётчика записей
(CSV-экспорт его не отдаёт): повтор `dedupSignature` = достигли cap → окно велико → делим цену;
окно считается **дренированным**, когда блок вернул < `block_size` строк. Стоп рекурсии —
минимальный ценовой интервал (лог + допустимая потеря, назначение — датасет). Курсор
(`crw_runs.cursor`): текущий день + ценовой work-стек интервалов + номер блока; возобновление
с точки обрыва.

Фаза опирается ТОЛЬКО на инфраструктуру P2 (`SourceMethod`/`CsvSourceMethod`, `CrawlerRunManager`,
`CsvBlockIngestor`, `ListingCursor` с уже готовыми полями `day`/`priceStack`), НЕ на детальную
карточку P3. Ядро дренажа одного date-окна с ценовым дроблением — общий `ArchiveWindowScanner`:
P4.1 гоняет его по дням (publish-окно = один день), P4.2 переиспользует по update-окну.
Второй item — **fresh backlog-защита** (`02` §4.1): sweep-потребитель cap-флага (`cap_hit`/
`possible_skip_window`, уже поднятого в P2.6) запускает точечный archive-рескан окна простоя
по диапазону `source_updated_at` — так пропущенные fresh-обновления добираются гарантированно.

**Завершение фазы:** перекачка выбранного периода без слепых зон сверх допуска (roadmap
Фаза 3b приёмка); cap-флаг из fresh идемпотентно триггерит archive-рескан окна простоя.
После P4 план V2-CRAWL терминален целиком (roadmap Фазы 2/3/3b).

**Implementation Rules:** **Детект переполнения — без счётчика записей** (CSV-экспорт его не даёт): (a) окно **дренировано**, когда `batch->rowsTotal < block_size` (последний/частичный блок) → `scan` завершает окно; (b) **cap** — `batch->dedupSignature === $previousSignature && $previousSignature !== null` → окно превышает серверный потолок → **бинарное ценовое дробление**; (c) иначе `blockFrom += block_size`, следующий блок. Ценовой work-стек в `cursor->priceStack` (`list<string>`, элемент `"{from}:{to}"`): вершина = текущий обрабатываемый интервал. Старт окна: стек `["0:{price_ceiling}"]`, `blockFrom=1`. Cap на вершине `[lo,hi]`: если `hi-lo <= min_price_interval` → `Log::warning` (потолок дробления, допустимая потеря) и pop вершины; иначе заменить вершину на два полуинтервала (`mid = lo + intdiv(hi-lo,2)` → `[lo,mid]`, `[mid,hi]`; толкать в порядке «сначала обрабатывается нижний»), `blockFrom=1`. Окно дренировано → pop вершины, `blockFrom=1`, следующий интервал. Стек пуст → окно закрыто, вернуть управление процессору. `ArchiveRunProcessor`: `startOrResume`; если `cursor->day===null` → `day=from`; цикл `day<=to`: собрать `WindowFilter(publish, day, day)`, `scanner->scan(...)`, затем `day=day->addDay()`, сбросить `priceStack=null`/`blockFrom=1` в курсоре, `updateCursor`; по выходу — `complete`. ### P4.2 — Fresh backlog-защита: archive-рескан окна простоя по cap-флагу

**Status:** 🟢 Done
**Intent:** `App\Services\Crawler\Modes\BacklogRescanProcessor` + команда `crawler:rescan-backlog` — sweep-потребитель fresh-прогонов с флагом `cap_hit`: для каждого запустить `ArchiveWindowScanner` (P4.1) по update-окну `possible_skip_window` на archive-профиле того же реестра; идемпотентно пометить флаг обработанным.
