# P4 — Архив (перекачка истории)

## Phase Context

Archive-режим (`02-crawling.md` §4.2, roadmap Фаза 3b) — перекачка исторического потока
для обучающего датасета. Идём по дням: `publishDateFrom = publishDateTo = <день>`,
сортировка по возрастанию даты; если в дне > лимита выборки (≤ 5000) — **рекурсивное
ценовое дробление** (`priceFromGeneral`/`priceToGeneral`, бинарное деление интервала;
аналог v1 `priceSplitHook`, но качаем CSV, а не HTML). Стоп рекурсии — минимальный ценовой
интервал (лог, если всё ещё переполнено). Курсор (`crw_runs.cursor`): текущий день +
ценовой стек + номер блока; возобновление с точки обрыва. Небольшие потери на краях
допустимы (назначение — датасет, не оперативные данные).

Фаза опирается ТОЛЬКО на инфраструктуру P2 (`SourceMethod`/`CsvSourceMethod`, менеджер
прогонов, инжест-блок), НЕ на детальную карточку P3. Второй item — **fresh
backlog-защита** (`02` §4.1): при cap-стопе в fresh (флаг «возможен пропуск», поднятый в
P2.6) запустить точечный archive-рескан окна простоя по диапазону `source_updated_at` от
последнего успешного скана до now, с тем же дроблением. Так пропущенные обновления
добираются гарантированно.

**Завершение фазы:** перекачка выбранного периода без слепых зон сверх допуска (roadmap
Фаза 3b приёмка); cap-флаг из fresh триггерит archive-рескан окна простоя.
