# P2 — Сбор: CSV/HTTP, fresh-поток

## Phase Context

Фаза строит фундамент сбора: переключаемую **source-абстракцию** (`SourceMethod` —
`csv`/`html`/`api`, метод — параметр профиля `crw_crawlers.source_method`, не ветка кода),
менеджер прогонов (heartbeat, иерархический курсор, инвариант «один `running` на профиль»,
recovery оборванных), прокси-пул с вежливым темпом, основной `CsvSourceMethod` (HTTP-забор
блока ЕИС) и **fresh-режим** (скан по убыванию обновления до первого известного блока).

Опорные факты (`02-crawling.md` §3): endpoint
`GET /epz/order/orderCsvSettings/download.html?...&from=<n>&to=<n+500>` отдаёт **ровно 500
строк**, `windows-1251`, разделитель `;`, кавычки удваиваются (`""`), заголовок русский;
глубина ~10 000, за пределом сервер молча повторяет последний блок → детект по
`crw_fetches.dedup_signature` (первый `reg_number` блока совпал с предыдущим → cap, стоп).
Один endpoint обслуживает 44-ФЗ (`fz44=on`) и 223-ФЗ (`fz223=on`); различаются флаг реестра
и нормализация «способа закупки» (§3.4). Всё — обычный HTTP через прокси-пул, без сессии.

Инжест-ядро готово (V2-CORE P1) и **переиспользуется, не переписывается**: source-метод
парсит CSV → нормализует способ/статус → кормит `App\Services\Procurement\ProcurementIngestProcessor`
снапшотом `App\Dto\Procurement\ProcurementSnapshotData`; тот сам решает discover/no-op/новая
ревизия+события. Сырой CSV и метрики блока → `crw_fetches` + object storage (S3/MinIO).
Модели: `App\Models\Crawler\{Crawler,Run,Fetch,Proxy}`; enum'ы
`App\Enums\Crawler\{SourceMethod,CrawlerMode,RunStatus}`. Слой: агностик — `App\Services\Crawler\*`,
контракты — `App\Services\Crawler\Contracts\*`, DTO краулинга — `App\Dto\Crawler\*`,
ЕИС-специфика — `App\Services\Crawler\Eis\*` (в репо нет `Modules/`, D10).

**Завершение фазы:** реальный fresh-скан двух реестров наполняет `prc_procurements`/ревизии/
события; повтор идемпотентен (нет дублей); дедуп и cap-стоп-детект работают (`06-roadmap.md`
Фаза 2 приёмка). Мост в пайплайн документов — в P3 (D4). Archive-рескан окна простоя — P4.2 (D5).

### P2.2 — Менеджер прогонов (lifecycle, one-active, heartbeat, recovery, курсор)

**Status:** 🟢 Done
**Intent:** `App\Services\Crawler\CrawlerRunManager` — жизненный цикл прогона: `startOrResume` / `heartbeat` / `updateCursor` / `complete` / `fail` / `recoverStale`.
**Why:** Возобновляемость и «один running на профиль» — инвариант (`02` §6.1, `06` Фаза 2). Оборванный прогон должен продолжаться с курсора, а не начинаться заново и не плодить второй активный.
**Scope Included:** Сервис-менеджер с методами выше; резолв «есть running → resume его; есть resumable (paused) → resume; иначе новый»; обработка гонки на создании через `UniqueConstraintViolationException`; `heartbeat` → `last_heartbeat_at=now`; `recoverStale()` → прогоны `running` с протухшим heartbeat переводит в `paused` (resumable); запись курсора через `ListingCursor::toArray()`.
**Scope Excluded:** Сам цикл забора блоков (P2.6); ретраи HTTP (P2.4); прокси (P2.3); архивный курсор день/цена (P4).
**Inputs:** Модели `Crawler`, `Run`; enum `RunStatus` (running/paused/completed/failed/cancelled, `isTerminal()`); DTO `ListingCursor` (P2.1); частичный unique-индекс `crw_runs_crawler_id_running_unique` (уже в миграции `2026_07_04_100039`).
**Files:** `app/Services/Crawler/CrawlerRunManager.php` (new); `config/crawler.php` (add `heartbeat_timeout_seconds` default 300).
**Required Reads:** `docs/specs/v2/02-crawling.md` §6.1; `docs/specs/v2/01-database.md` §7 (`crw_runs`); `app/Models/Crawler/Run.php`; `app/Enums/Crawler/RunStatus.php`; `database/migrations/2026_07_04_100039_create_crw_runs_table.php`; skills `production-readiness-checklist`, `dependency-injection`, `named-arguments`.
**Implementation Rules:** Каждый переход статуса — в `DB::transaction`. `startOrResume(Crawler): Run`: внутри транзакции искать `running` → вернуть; иначе искать последний `paused` (не `isTerminal`) → перевести в `running`, вернуть; иначе `create(status=running, started_at=now, last_heartbeat_at=now, cursor=<initial>)`. При `UniqueConstraintViolationException` на create — перечитать running и вернуть его (гонку выиграл другой воркер). `recoverStale(): int` — `where status=running AND last_heartbeat_at < now()-heartbeat_timeout` → `paused`; вернуть число.
**Code Guidance:** Стиль — `final readonly` сервис, конструкторная инъекция. Владелец инварианта «один running» — **DB-индекс**, НЕ вторая PHP-проверка: ловим нарушение и резолвим, не делаем `SELECT ... FOR UPDATE`-лок вручную (`production-readiness-checklist`: атомарные переходы, single-owner). `recoverStale` возвращает в `paused` (транзиентный обрыв, resumable), НЕ в `failed` (иначе потеря курсора). Никаких очередей/джоб здесь — менеджер синхронный. Запрещено: менять `status` минуя enum; трогать курсор сырым массивом мимо `ListingCursor`. Обязательные тесты — см. Validation.
**Validation:** `docker compose exec app php artisan test --compact --filter=CrawlerRunManager` зелёный (тесты: первый `startOrResume` создаёт один running; повторный — резюмит тот же (id совпал), второго running нет; вставка второго running руками падает на unique; `recoverStale` переводит протухший running в paused и не трогает свежий; `complete`/`fail` ставят терминальный статус + `finished_at`). `./vendor/bin/pint --dirty` чисто.
**Deliverables:** `CrawlerRunManager`; Feature-тест `tests/Feature/Crawler/CrawlerRunManagerTest.php`; ключ `heartbeat_timeout_seconds` в `config/crawler.php`.
**Completion Notes:** Реализовано: `app/Services/Crawler/CrawlerRunManager.php` (`startOrResume`/`heartbeat`/`updateCursor`/`complete`/`fail`/`recoverStale`, `final readonly`, без зависимостей в конструкторе — только `DB`/`config`/`now()`). `startOrResume` — running→вернуть; paused→resume; иначе create в `DB::transaction`, гонка на unique-индексе (`UniqueConstraintViolationException`) резолвится перечитыванием running. `recoverStale` переводит протухшие `running` (heartbeat старше `heartbeat_timeout_seconds`, default 300) в `paused`. Курсор пишется только через `ListingCursor::toArray()`. `config/crawler.php` — добавлен ключ `heartbeat_timeout_seconds`. Ревью `agelto-reviewer` нашло major (тесты не покрывали `heartbeat`/`updateCursor`) и minor (`complete`/`fail` не в `DB::transaction`, хотя бриф требует транзакцию на каждый переход статуса) — оба исправлены: добавлены тесты на `heartbeat` и `updateCursor` (round-trip через `ListingCursor::fromArray`); `complete`/`fail` обёрнуты в `DB::transaction`.
