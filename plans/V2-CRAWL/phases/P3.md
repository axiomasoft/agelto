# P3 — Детальная карточка + документы

## Phase Context

Отдельная стадия после листинга (`02-crawling.md` §5): снять **полную карточку**
извещения ЕИС по вкладкам, а не только файлы. Всё — server-side HTML, **обычный HTTP**
без сессии (браузер — запасной путь, не в этой фазе). Структура снята живьём —
`research/eis-card-recon.md`. URL: `GET /epz/order/notice/<тип>/view/<вкладка>.html?regNumber=…`,
`<тип>` = способ закупки (`ea20`/`ok20`/`zk20`/`ezt20`…); шаблоны URL по типам — в
`plt_registries.settings` (`App\Models\Platform\Registry`).

Вкладки → таблицы: `common-info` → `prc_procurements`+`prc_eis_details`+`prc_financing`
(по годам)+`org_procurement_parties` (роли)+`prc_items` (ОКПД2/КТРУ); `documents` →
`doc_documents`+`doc_versions` (скачивание версий, дедуп по `content_hash`, сырьё в object
storage); `event-journal` → `prc_events` (даты/подтверждения, best-effort парсинг строк —
дополняющий источник); `supplier-results` (у завершённых) → `prc_awards`+`prc_bids`
(+ `prc_protocols`/`prc_clarifications`/`prc_cancellations`). Модели всех таблиц готовы
(V2-CORE P1): `App\Models\{Procurement\*,Document\*,Organization\*,Reference\*}`.

Ключевые правила (§5.2): каждая вкладка — идемпотентный upsert по естественным ключам
(`prc_items` по позиции, `org_procurement_parties` по `(procurement_id, organization_id, role)`,
`prc_protocols` по номеру); организации — entity resolution по ИНН/ОГРН в `org_organizations`
(одна орг. в нескольких ролях → один `org_organizations`); триггеры пересъёма — не только
`source_updated_at`, но и смена этапа + ре-скан завершающихся (`evaluation`/`awarded`).
Классификаторы `ref_*` — загрузчик справочников + резолв кодов позиций.

**Завершение фазы:** по закупке снят полный детальный слой; журнал ЕИС наполняет
`prc_events`; орг. в нескольких ролях → один `org_organizations`; итоги → `prc_awards`/`bids`;
замена файла → новая версия+событие; стадия ставит `prc_procurements.detail_fetched_at`;
мост в пайплайн документов (`02` §8) идемпотентно ставит закупки/документы в очередь.
