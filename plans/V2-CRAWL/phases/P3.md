# P3 — Детальная карточка + документы

## Phase Context

Отдельная стадия после листинга (`02-crawling.md` §5): снять **полную карточку**
извещения ЕИС по вкладкам, а не только файлы. Всё — server-side HTML, **обычный HTTP**
без сессии (браузер — запасной путь, не в этой фазе). URL:
`GET /epz/order/notice/<тип>/view/<вкладка>.html?regNumber=…`, `<тип>` = способ закупки
(`ea20`/`ok20`/`zk20`/`ezt20`…); шаблоны URL по типам — в `plt_registries.settings`
(`App\Models\Platform\Registry`, каст `settings => array`).

Вкладки → таблицы: `common-info` → `prc_procurements`+`prc_eis_details`+`prc_financing`
(по годам)+`prc_items` (ОКПД2/КТРУ) — роли/`customer_org_id` владеет P3.4 (D15);
`documents` → `doc_documents`+`doc_versions` (скачивание версий, дедуп по `content_hash`,
сырьё в object storage); `event-journal` → `prc_events` (best-effort, дополняющий источник);
`supplier-results` (у завершённых) → `prc_awards`+`prc_bids`
(+ `prc_protocols`/`prc_clarifications`/`prc_cancellations`). Модели всех таблиц готовы
(V2-CORE P1): `App\Models\{Procurement\*,Document\*,Organization\*,Reference\*}`.

Паттерн фазы (как P2.6 собрал куски P2): items P3.1 (забор вкладок) и P3.3–P3.7
(парсер+процессор одной вкладки, тестируемы от HTML-фикстуры к строкам БД) — независимые
кирпичи; **оркестратор `DetailAnalysisProcessor` собирается в P3.8** (забор → все
процессоры → `detail_fetched_at` → error-блок → триггеры пересъёма → мост в пайплайн).
Каждая вкладка — идемпотентный upsert по естественным ключам (§5.2): `prc_items` по позиции,
`org_procurement_parties` по `(procurement_id, organization_id, role)`, `prc_protocols` по
номеру; организации — entity resolution по ИНН/ОГРН (одна орг. в нескольких ролях → один
`org_organizations`). Детальный слой пишется НЕ через ingest-ядро (оно про листинг-ревизии),
а через новый `ProcurementDetailStoreRepository` + типизированные сущности §4 (D18).

**Scope фазы — только 44-ФЗ карточка** (вкладки по типу процедуры). 223-ФЗ ветка
`notice223`/`lot-list`/`lot-info` (лоты первичны, нужен `noticeGuid`/`lotGuid`) — вне P3
(D14). **Завершение фазы:** по 44-закупке снят полный детальный слой; журнал ЕИС наполняет
`prc_events`; орг. в нескольких ролях → один `org_organizations`; итоги → `prc_awards`/`bids`;
замена файла → новая версия+событие; стадия ставит `prc_procurements.detail_fetched_at`;
мост в пайплайн документов (`02` §8) идемпотентно ставит документы в очередь стадии подготовки.
