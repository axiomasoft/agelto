# P4 — Provenance: тонкий срез по конфликтным полям

## Phase Context

> СКЕЛЕТ — не детализирован, разворачивается /task:plan-design DOMLANG P4

Фаза с **легальным отрицательным исходом**. Сначала доказать, потом кодить.

ADR-0008 (D4): материализуем provenance только для полей, которые приходят из ≥2 слоёв
**и расходятся**. Правило взято из `RAG:✅ 2026-07-10 «W3C PROV vs прагматичные колонки»`:
fact-level provenance окупается, только если ответ должен пережить дедупликацию или согласование
источников; иначе достаточно coarse-колонок, которые в проекте уже есть
(`prc_revisions.crawler_run_id`, `prc_fetches.artifact_ref`,
`prc_ai_analyses.{provider,model,rules_hash}`, `prc_estimates.raw_result`, `prc_documents.source_url`).

Гипотеза кандидатов (**подлежит проверке в коде, не принимать на веру**): `status` (listing ⚔
карточка ⚔ протокол), НМЦК (listing ⚔ карточка), сроки подачи заявок (listing ⚔ карточка).

Если P4.1 не находит ни одного поля, которое пишется из ≥2 слоёв с расхождением — фаза
закрывается `⛔ Skipped by decision`, а ADR-0008 фиксирует триггер возврата. Это успешный исход,
а не провал.

**Scope Included:** research-доказательство конфликтов; материализация provenance строго для
найденных полей.
**Scope Excluded:** колонка `provenance` на каждой доменной таблице (прямо запрещено ADR-0008);
дублирование существующего coarse-lineage; пять уровней `*-derived` из аудита.
