# P7 — Глоссарий v2 + OCDS mapping

## Phase Context

Два глоссария уже существуют (`.ai/guidelines/glossary.md` — технический канон-SSOT;
`docs/02_Workflow/glossary.md` — бизнес-версия, ссылается на первый). Аудит ошибочно рекомендовал
их «завести» — фаза их **дополняет**, а не создаёт. Восемь отсутствующих терминов проверены
по коду/миграциям (2026-07-10) и анкорены на реальные артефакты — маппинг зафиксирован D33:
`revision` → `App\Models\Procurement\ProcurementRevision` (`prc_revisions`); `event` →
`App\Models\Procurement\ProcurementEvent` (`prc_events`, immutable, `ProcurementEventType`);
`projection` → отношение `prc_procurements` (текущее состояние) к `prc_revisions`/`prc_events`
(история) — концептуальный термин без своей таблицы, объясняет изоморф ADR-0007
(`prc_procurements`≈`compiledRelease`); `provenance` → coarse-lineage колонки ADR-0008
(`crawler_run_id`/`artifact_ref`/`provider,model,rules_hash,cache_id`/`source_url`), тонкий срез,
без fact-level схемы; `quality flag` → `App\Enums\Procurement\EstimateValidationStatus`
(`prc_estimates.validation_status`: `Valid`/`Suspicious`/`Invalid`) — **не путать** с
`ReviewStatus` (`prc_ai_analyses.review_status`: операторское ревью, уже в глоссарии); `notice` —
не новая сущность, регуляторный/OCDS-синоним `Procurement` (44-ФЗ «извещение о закупке»); `registry
number` / `номер ЭТП` → `prc_procurements.registry_number`/`etp_number` (D5: реестровый номер
извещения ЕИС vs второй номер по 223-ФЗ на площадке, `etp_number` — forward-provision без
продюсера, D13).

Второй Deliverable — `docs/03_Dev/ocds-mapping.md`. Per ADR-0007 (D3) OCDS — **экспортный
контракт, persistence на нём не строим**: `prc_procurements` ≈ `compiledRelease`, `prc_revisions`
≈ `versionedRelease`, `prc_events` ≈ `releases` (immutable). Файл документирует mapping
«внутреннее поле ↔ OCDS-путь» как справочник экспортной поверхности, активируется как боевой
контракт только по триггеру ADR-0007 (первый внешний потребитель/регуляторное требование).

Завершение фазы: оба глоссария покрывают 8 терминов; `docs/03_Dev/ocds-mapping.md` существует,
явно объявляет OCDS экспортным слоем и покрывает 3 замапленные таблицы.

**Scope Included:** дополнение двух глоссариев (8 терминов); новый `docs/03_Dev/ocds-mapping.md`
(mapping-таблица `prc_procurements`/`prc_revisions`/`prc_events` ↔ OCDS `release`/`record`/
`compiledRelease`/`versionedRelease` + секции `tender`/`award`/`parties`/`documents`, покрытые
текущей схемой).

**Scope Excluded:** реализация OCDS-экспортера (кода в фазе нет); переименование внутренних
сущностей под OCDS (запрещено ADR-0007); материализация OCDS-секций без источника данных
(`planning`/`contract`/`implementation` — фиксируются как «не покрыто, нет источника», не
выдумываются); правка любого `app/`/`database/`/`tests/` (фаза docs-only, как P6).
