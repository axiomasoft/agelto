# ТЗ v2: универсальная система сбора и AI-парсинга закупок (greenfield)

## Context

Текущий agelto — надёжный ЕИС-парсер с рядом зрелых решений, но: финальный маппинг смет в БД не реализован (`OrderParsingProcess` пуст), истории изменений закупок нет, схема БД заточена под ЕИС, браузер — chrome-php без нормального anti-detection, вложения качаются синхронно. Решено спроектировать **новую систему с нуля** (новый репозиторий), заимствуя лучшее из agelto. Результат этой задачи — **пакет ТЗ-документов** в `docs/specs/v2/` (кода не пишем).

Принцип синтеза: **опыт Claude + готовые решения agelto + внешний research (Perplexity Web)** — из всего выбирается лучшее.

## Зафиксированные решения (интервью с владельцем)

| Тема | Решение |
|---|---|
| Подход | Greenfield, новый git-репозиторий; ТЗ пишем в `agelto/docs/specs/v2/` |
| Стек | PHP 8.4+, Laravel 12, Postgres 17, Redis/Horizon, Filament (админка), Playwright — **отдельный Node-сервис** (HTTP API) в своём контейнере |
| История закупок | Полные снапшоты каждой редакции (jsonb) + нормализованный журнал событий (статус, цена, даты, документы); восстановление состояния на любую дату |
| Спец-поля площадок | Гибрид: общее ядро — фиксированные столбцы; редкое — jsonb attributes; богатые площадки — extension-таблицы 1:1 |
| Сметы | Нормализованные таблицы (estimates/sections/items/resources) + сырой ответ LLM в jsonb |
| Охват | 44-ФЗ + 223-ФЗ ЕИС в ядре сразу; коммерческие площадки — валидация дизайна на бумаге |
| Данные | Пустая БД, без миграции из plt_*; перекачка архива через CSV-метод; проектируем на десятки млн записей (партиционирование) |
| Сырые артефакты | Храним всё (CSV, документы, ответы LLM) в object storage с retention; HTML-снапшоты — сжато/опционально |
| Потребитель | Внутренний инструмент (операторы + датасет для обучения LLM), задел под публичный API без детальной проработки |
| LLM-роутинг | Матрица «тип документа × шаг пайплайна → провайдер+модель», настройка в админке (spatie-settings) |
| LLM-абстракция | Кандидат — официальный **laravel/ai** (указан владельцем); research сравнит с Prism и своей обёрткой: покрытие Gemini context caching, structured output, OpenAI-совместимых локальных серверов |
| Локальная LLM | В ТЗ: контракт провайдера (OpenAI-совместимый API), сбор обучающего датасета, eval-метрики + shadow-режим. Выбор модели/обучение — вне ТЗ |
| Типы документов | Полный обработчик только для смет; скрининг классифицирует и сохраняет типы остальных (обработчики подключаются позже) |
| Краулинг | Основной метод листинга — CSV-экспорт ЕИС; детали/документы — HTTP-first с fallback на Playwright; SOAP API — интерфейс на будущее. Свежие: сортировка по убыванию обновления каждые ~30 мин; архив: по дням + ценовое дробление |

## Что заимствуем из agelto (проверено разведкой)

- `CrawlerRunManager`: heartbeat, курсор возобновления, инвариант «1 running на профиль», recovery по heartbeat (`app/Process/Crawling/Run/CrawlerRunManager.php`)
- Рекурсивное ценовое дробление `priceSplitHook()` + архивный режим по дням (`Modules/Eis/app/Crawling/EisCrawlingService.php`)
- Gemini context-caching + rules_hash/fingerprint инвалидация, учёт токенов (`app/Services/GeminiService.php`)
- Промпты из БД (`plt_prompt_rules`, версии/приоритеты) + «схема как код» в system instruction (`PromptRuleRepository`)
- Двухступенчатый анализ: дешёвый скрининг → полный разбор; lease-защита job'ов; архивы→дочерние записи с parent_id
- Полезные столбцы: error-блок (attempts/last_error/next_retry_at/failed_permanently), analytics по стадиям, ignore-links, content_hash вложений
- Enum'ы статусов как основа для новой статусной модели

## Исполнение (после одобрения плана)

### Фаза 0 — фиксация плана в проекте

Скопировать этот план в `plans/` проекта agelto (просьба владельца; в plan mode запись в проект запрещена — делаем первым шагом исполнения).

### Фаза A — разведка ЕИС (Playwright MCP, main-поток)

Зайти через прокси на zakupki.gov.ru (расширенный поиск): снять реальные параметры формы CSV-экспорта (POST download.html), устройство модалки выбора файлов (лимит 5000 / отрезки по 500), структуру CSV (колонки, кодировка), различия реестров 44/223. Результат — `research/eis-csv-recon.md`.

### Фаза B — research workflow (Workflow tool, субагенты sonnet + perplexity-web)

Параллельные research-агенты (каждый пишет выжимку, main синтезирует):

1. **Универсальная схема закупок** — OCDS (Open Contracting Data Standard) как референс ядра: releases/versioning, статусные модели, маппинг 44/223-ФЗ на универсальную модель
2. **Темпоральность/версионирование в Postgres** — снапшоты + event log, SCD-паттерны, партиционирование больших таблиц закупок
3. **CSV-экспорт ЕИС** — подтверждение параметров запроса, лимитов, подводных камней (дополняет фазу A)
4. **Playwright Node-сервис** — архитектура browser-pool сервиса (API, очереди, прокси-ротация, anti-detection, crash-изоляция), готовые решения (browserless и аналоги) vs свой
5. **LLM document-extraction pipeline** — multi-provider абстракция: **laravel/ai** (приоритетный кандидат) vs Prism vs своя обёртка — покрытие Gemini context caching, structured output, file API, локальные OpenAI-совместимые серверы; multi-step extraction больших таблиц, eval/shadow-режим, датасет для fine-tune
