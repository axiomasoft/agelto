### P3.3 — Развести /up liveness и Doctor/service application readiness

**Intent:** Сохранить `/up` lightweight liveness и добавить единый active-readiness service/command, который Doctor переиспользует для DB, cache, storage, migrations/base/admin, assets, Horizon и scheduler. RAG:— (repo-grounded: D21/D23 and current health carriers).
**Why:** Текущий `/up` доказывает только boot, а превращение его в full dependency sweep создаст restart churn/cycles; отдельные shell и Doctor checks без shared service разойдутся. RAG:— (repo-grounded: `bootstrap/app.php`, `docker-compose*.yml`, `research/05-P3-execution-design.md`).
**Scope Included:** Typed readiness result/code registry · bounded active DB/cache/storage checks with cleanup · migration/base/admin and P3.2 asset checks · Horizon status · scheduler cache heartbeat · `app:readiness --format=agent|json` · Doctor delegation · Compose/Make aggregate gate · pass/fail/timeout/redaction tests · docs.
**Scope Excluded:** Heavy checks inside `/up` · monitoring vendor/notification system · generic procurement platform health · auto-fix · production secrets/output · CI wiring P11.
**Inputs:** `research/05-P3-execution-design.md` · `phases/P2/P2.6.state.md` · `phases/P3/P3.2.state.md` · D21 · D51 · D23 · `bootstrap/app.php` · `docker-compose.yml` · `docker-compose.prod.yml`
**Files:** `app/Services/Health/ApplicationReadiness.php` · `app/Dto/Health/ReadinessCheckResult.php` · `app/Console/Commands/ApplicationReadinessCommand.php` · `app/Doctor/Diagnostics/ApplicationReadinessIsGreen.php` · `config/doctor.php` · `routes/console.php` · `tests/Feature/Health/ApplicationReadinessTest.php` · `tests/Feature/Doctor/ApplicationReadinessDiagnosticTest.php` · `docker/tests/readiness-contract.sh` · `docker/Makefile` · `docker-compose.yml` · `docker-compose.prod.yml` · `docs/03_Dev/commands.md` · `docs/03_Dev/docker/development.md` · `docs/03_Dev/docker/production.md` · `docs/03_Dev/process/deploy.md`
**Required Reads:** 1) `plans/2026.08.09-RELEASE-READINESS/research/05-P3-execution-design.md` 2) `plans/2026.08.09-RELEASE-READINESS/phases/P2/P2.6.md` 3) `plans/2026.08.09-RELEASE-READINESS/phases/P2/P2.6.state.md` 4) `plans/2026.08.09-RELEASE-READINESS/phases/P3/P3.2.state.md` 5) `D21` 6) `D51` 7) `D23` 8) `bootstrap/app.php` 9) `routes/console.php` 10) `docker-compose.yml` 11) `docker-compose.prod.yml` 12) `docker/Makefile` 13) `app/Providers/AppServiceProvider.php`
**Implementation Rules:** P2.6/P3.2 terminal; preserve every P2 diagnostic code and D21 companion-image boundary using the layer-1/2 provenance linked by D51. `/up` performs no new dependency I/O. Readiness service returns typed ordered results and never throws past the aggregate; each risky check has configured timeout, stable code, short redacted message and cleanup in `finally`. DB executes `select 1`; cache and configured storage perform unique write/read/compare/delete; assets call P3.2 check without mutation; Horizon uses application-visible status; scheduler heartbeat is written by the scheduler and freshness-thresholded. Command/Doctor share service, and production warning/failure exits nonzero. RAG:— (repo-grounded: D21/D23/D51; active-check pattern verified by selected health-checks skill).
**Code Guidance:** Controllers are not needed; do not add an HTTP Doctor/readiness route or put logic in `routes/console.php` beyond scheduling the heartbeat. Use `final` typed classes and constructor injection; never catch and discard errors, expose exception class/secret-bearing DSN or leave temp keys/files. No `|| true`, score threshold or mocked-all-green test. Анти-самообман: config presence is not resource readiness; every external resource check must touch it, cleanup must be asserted, and `/up` tests must prove independence from forced DB/cache/storage failure.
**Validation:** `php artisan test --compact tests/Feature/Health/ApplicationReadinessTest.php tests/Feature/Doctor/ApplicationReadinessDiagnosticTest.php` covers pass/fail/timeout/cleanup/stale heartbeat/redaction and `/up` independence · `php artisan app:readiness --format=json` is schema-parseable and green on healthy isolated stack · each forced DB/cache/storage/assets/Horizon/scheduler failure yields its stable code and nonzero · `bash docker/tests/readiness-contract.sh` proves app `/up`, service healthchecks and aggregate semantics without dependency cycle · production Doctor `--fail-on=warn` remains no-fix and nonzero on degraded readiness.
**Deliverables:** Shared typed readiness service, agent/JSON command, Doctor wrapper, scheduler heartbeat, executable service/Compose gate and synchronized health/deploy docs; separate item commit.
