**Implementation Rules:** All input states terminal and workflows call existing local carriers; YAML does not reimplement their logic. Resolve every action tag to the vendor repository's current full SHA and record tag→SHA/date in P11 finding; unknown/unverified action is forbidden. Default `permissions: contents: read`, job-specific elevation only when required; no privileged untrusted checkout. Private credentials are individual secrets, masked, least-privilege and absent from caches/artifacts/args. Cache keys include runner OS/arch, runtime/image fingerprint and exact lock hash; trusted triggers write, PRs restore within GitHub scope. Ordinary tests use `--ci --no-tia`; only baseline workflow uses TIA and uploads the exact hidden path. Missing credential, red audit or absent required job blocks, never skips green. RAG:— (repo-grounded: D19/D20/D39/D40/D42 plus verified external contracts).
**Code Guidance:** Keep workflows declarative and thin; factor repeated shell into tested repo scripts/Make targets, not copied multiline YAML. Pin action SHAs with readable version comments and Dependabot maintenance. No `continue-on-error` on required quality/security/tests/build, no floating Docker/action versions, no cache restore key broad enough to cross incompatible locks. Anti-self-deception: YAML lint/local emulation is necessary but not sufficient; P11.6 requires a real candidate-SHA run. If private-package checkout cannot be made secret-safe for untrusted PRs, fail with an explicit blocked check and escalate D19—do not checkout with a write-capable token.
