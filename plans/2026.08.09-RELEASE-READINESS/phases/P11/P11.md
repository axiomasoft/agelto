# P11 — Pest 5 performance, test isolation и CI

## Phase Context

P11 начинается только на terminal committed P0/P1–P10 tree и сначала повторяет все authoring
counts/versions/timings. P11.1 запечатывает serial/TIA/parallel/shard/profile/coverage baseline;
P11.2 выбирает самый маленький полезный execution mode по D40, а P11.3 доказывает exact DB и
process-scoped filesystem isolation до признания parallel безопасным. P11.4 закрывает все
доказанные runtime/test critical/high gaps из общей risk matrix, переиспользует D24 Playwright и
передаёт единственный CI-only gap D42 его владельцу P11.5 без ложной отметки `Covered`. P11.5
закрывает D42 через terminal P1/P10 local carriers, hardened GitHub Actions и отдельный TIA baseline;
P11.6 фиксирует coverage/performance/flake budgets и реальный CI evidence для P12. TIA replay,
cache hit, focused suite или компактный PAO output никогда не подменяют свежую приёмку.

> **Контракт фазы (contract-first).** Потребляет: terminal P0.4/P0.6, P1–P10 committed products, `root/contracts/release-readiness-v1.md`, D24/D25/D39–D42, P10 local gates and all upstream risk tests · Производит: immutable benchmark, correct Pest 5 TIA/concurrency carrier, exact DB/filesystem/agent guards, closed risk matrix, hardened CI/shared baseline and committed coverage/performance/flake evidence · Границы: не ослабляет guards/thresholds, не принимает TIA replay как proof, не создаёт второй browser stack и не объявляет production-ready до P12

## Scope Included

1. Повторяемый serial/TIA/parallel/shard/profile/coverage baseline на terminal P0–P10 tree.
2. Evidence-based выбор Pest 5 execution mode и доказательство DB/filesystem/process isolation.
3. Закрытие critical/high risk-test gaps без удаления, skip или подгонки existing tests.
4. Hardened GitHub Actions, shared local/CI carrier и финальные coverage/performance/flake budgets.

## Scope Excluded

- Product-contract redesign из P1–P10 и второй browser stack.
- TIA replay, focused suite или cache hit как final proof.
- Production host/deploy/recovery P12 и объявление release readiness.
- Ослабление thresholds, test guards, exact DB suffix/media isolation или security regression checks.
