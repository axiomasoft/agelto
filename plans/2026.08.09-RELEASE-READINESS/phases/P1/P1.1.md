### P1.1 — Зафиксировать канон целей Make и проверяемый help/preflight

**Intent:** Реализовать один самодокументируемый Make command surface с отдельными dev/prod/agent/image namespaces, non-mutating preflight и shell contract harness, не сохраняя старые targets по инерции. RAG:— (repo-grounded: D10/D16 и `research/03-P1-execution-design.md`).
**Why:** Текущий `docker/Makefile` смешивает environment switch, image build и deploy, а `prod-pre-clean` делает destructive volume cleanup; без target contract следующие P1 items будут добавлять новые команды поверх неоднозначного интерфейса. RAG:— (repo-grounded: `docker/Makefile::prod-pre-clean`).
**Scope Included:** Root delegation · namespaced target taxonomy/help · version/config preflight без запуска stack · единый non-TTY/agent exec flag contract · fake-Docker shell harness для проверки argv/side effects · временные compatibility aliases только с явной таблицей судьбы.
**Scope Excluded:** Реализация final Compose/image/Vite behavior P1.2–P1.5 · запуск/остановка production stack · миграции/backup/secrets · CI workflow.
**Inputs:** `research/03-P1-execution-design.md` · `findings/P1-docker-make-vite-recon-2026-08-09.md` · `phases/P0/P0.6.state.md` · `root/contracts/release-readiness-v1.md` · D10 · D16
**Files:** `./Makefile` · `docker/Makefile` · `docker/scripts/compose-preflight.sh` · `docker/tests/make-contract.sh` · `docs/03_Dev/commands.md` · `docs/03_Dev/getting-started.md`
**Required Reads:** 1) `plans/2026.08.09-RELEASE-READINESS/research/03-P1-execution-design.md` 2) `plans/2026.08.09-RELEASE-READINESS/findings/P1-docker-make-vite-recon-2026-08-09.md` 3) `plans/2026.08.09-RELEASE-READINESS/phases/P0/P0.6.state.md` 4) `D10` 5) `D16` 6) `./Makefile` 7) `docker/Makefile` 8) `docs/03_Dev/commands.md` 9) `plans/2026.08.09-RELEASE-READINESS/root/contracts/release-readiness-v1.md`
**Implementation Rules:** До правок P0.6 state обязан быть terminal, а frozen contract — не противоречить D10/D16; иначе escalation `plan-design P1`. `help` остаётся default first target; root Makefile только делегирует. Preflight проверяет executable/version/config presence и rendered config, не делает `up`, build, pull, migrate или secret output. Complex branching живёт в `docker/scripts`, Make targets остаются thin aliases. Compatibility alias разрешён только с tested canonical target и removal note. RAG:— (repo-grounded: D10/D16 and plan Execution Rules).
**Code Guidance:** Никаких заглушек, targets «на будущее» без команды и silent `|| true` вокруг обязательных checks. Harness подменяет `docker` через temporary PATH и сравнивает exact argv, не вызывает реальный daemon. Анти-подгонка: расходится help, target и docs — исправить один канон и его consumers, не ослаблять grep/assertion. Если P0 freeze меняет taxonomy — не продолжать самовольно: это меняет D16, нужен D-record + plan-design.
**Validation:** `bash -n docker/scripts/compose-preflight.sh docker/tests/make-contract.sh` · `test "$(make -s help | wc -l)" -gt 5` · `make infra:preflight MODE=dev ENV_FILE=.env.example` зелён без созданных/изменённых containers (`docker ps --format '{{.ID}}'` before/after одинаков) · `bash docker/tests/make-contract.sh` зелён · `make -n dev:up agent:artisan prod:config image:build` возвращает 0 и не содержит `down --volumes` · `git diff --check` зелён.
**Deliverables:** Канонический namespaced Make surface, non-mutating preflight script, fake-Docker contract harness, документированная судьба legacy targets и синхронные command/getting-started docs; отдельный item commit.
