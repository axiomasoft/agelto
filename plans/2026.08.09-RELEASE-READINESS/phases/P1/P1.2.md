### P1.2 — Закрепить dev Compose для code-only изменений и agent execution

**Intent:** Сделать dev stack быстрым и доказуемым: source change виден без image rebuild, stateful/runtime paths имеют явное владение, service readiness проверяется health conditions, agent commands работают non-TTY. RAG:— (repo-grounded: owner trace and D16).
**Why:** Текущий root bind mount даёт code sync, но volume/UID/agent contracts разбросаны по comments и Make logic; изменение Dockerfile/Compose легко вернуть лишний rebuild или interactive-only path. RAG:— (repo-grounded: `./docker-compose.yml:3`, `docker/Makefile:1`).
**Scope Included:** Named `development` Docker target · dev Compose app/horizon/scheduler/postgres/redis/minio topology · project-scoped service/container/volume/network names without fixed `container_name` · source/vendor/runtime/Tia volume policy · health-based dependencies · local override example · code-sync/image-ID and non-TTY smoke scripts · dev docs.
**Scope Excluded:** Vite service/node_modules P1.4 · immutable production image P1.3 · private packages/secrets P2 · full browser stack/CI.
**Inputs:** `research/03-P1-execution-design.md` · `findings/P1-docker-make-vite-recon-2026-08-09.md` · `phases/P0/P0.6.state.md` · `phases/P1/P1.1.state.md` · D16 · D25
**Files:** `docker-compose.yml` · `docker-compose.override.example.yml` · `docker/php/Dockerfile` · `docker/Makefile` · `docker/tests/compose-contract.sh` · `docker/tests/dev-code-sync.sh` · `docs/03_Dev/docker/development.md` · `docs/03_Dev/docker/index.md` · `docs/03_Dev/docker/troubleshooting.md`

**Implementation Rules:** P0.6 и P1.1 обязаны быть terminal; frozen contract mismatch → escalation. Dev services build one `development` target and mount source, но dependency/runtime caches do not become anonymous volumes. Fixed `container_name` запрещён; all names derive from an explicit/default Compose project and commands address service names through Compose. `depends_on` uses `service_healthy`/completed semantics where readiness matters. Agent targets force `-T`, forward only named agent markers and never print secret values. Code-sync test creates/cleans an untracked sentinel, proves it inside `app`, and asserts image ID unchanged across a no-build recreate. RAG:✅ 2026-08-09 Docker Compose startup-order; repo boundaries D16/D25.
**Code Guidance:** Preserve Horizon stop-grace and test/Tia invariants; do not simplify services into generic queue worker. No `privileged`, Docker socket, blanket root user or `chmod -R 777`. Do not make `docker-compose.override.yml` tracked. Анти-самообман: `docker compose config` alone does not prove sync/readiness; dynamic sentinel + health/non-TTY checks are mandatory and cannot be replaced by prose.
**Validation:** validation env renders `docker compose --env-file .env.example -f docker-compose.yml config --quiet` with required dummy secrets supplied by the test script · `bash docker/tests/compose-contract.sh dev` rejects `container_name` and proves two distinct project-name renders have disjoint resource names · `docker compose ... up -d --build app horizon scheduler postgres redis minio` reaches healthy/running states · `bash docker/tests/dev-code-sync.sh` proves sentinel visibility and unchanged app image ID · `make agent:artisan ARGS='about --only=environment'` exits 0 with no TTY · fixed dynamic smoke: app `/up` curl green, `php artisan horizon:status` reports running, `pgrep -af 'artisan schedule:work'` finds scheduler · no sentinel/untracked runtime file remains.
**Deliverables:** Stable dev Compose/development target, explicit volume/readiness/UID contracts, non-TTY agent surface, executable dev compose/code-sync tests and synchronized dev Docker docs; separate item commit.
