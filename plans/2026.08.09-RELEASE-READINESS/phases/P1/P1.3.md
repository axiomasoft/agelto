### P1.3 — Собрать immutable production image topology и service contract

**Intent:** Создать multi-stage runtime/application topology и standalone prod Compose, где PHP services используют один обязательный immutable tag, code/vendor не приходят с host bind mount, а cache/rebuild boundaries проверяемы. RAG:✅ 2026-08-09 Docker production/multi-stage/cache official docs; D17.
**Why:** Текущий prod carrier bind-mount'ит checkout и vendor volume поверх prebuilt image, поэтому image tag не идентифицирует running code; Dockerfile не имеет application/dependency stages и `.dockerignore`. RAG:— (repo-grounded: `./docker-compose.prod.yml:3`, `docker/php/Dockerfile:1`).
**Scope Included:** `.dockerignore` secret/context exclusions · named runtime-base/application stages · non-root final user · app/horizon/scheduler same image tag · project-scoped names without fixed `container_name` · no code/vendor host mounts · persistent data/runtime mount allowlist · prod health/grace parity · static/image contract tests · production docs.
**Scope Excluded:** Private Composer package transport and complete vendor layer P2 · frontend build artifact P1.4 · framework asset readiness P3 · secret mechanism P2 · image registry/Ubuntu deployment P12.

**Implementation Rules:** P0.6/P1.2 terminal and D17/D25 reconcile are hard gates. Prod Compose requires `IMAGE_TAG` and uses the exact same repository:tag for app/horizon/scheduler; no `latest` deployment default or fixed `container_name`, and all operator commands address services through one explicit Compose project. `.dockerignore` excludes `.git`, plans/AI context, `.env*`, auth/secrets, vendor, node_modules, runtime/generated data while retaining required source/config. Runtime-base pins verified upstream tags, installs only runtime system/PHP assets, ends as `www-data`; application topology copies source but must label full vendor/readiness as gated on P2/P3. Persistent allowlist covers Postgres/Redis/MinIO/backups and required Laravel writable dirs only. RAG:✅ 2026-08-09 Docker/serversideup official docs; repo gates D17/D25.
**Code Guidance:** Never invent an image digest or claim final application health without P2/P3. If frozen P0 lacks a verified upstream pin, stop with escalation rather than use `latest`. No secrets in ARG/ENV/COPY/history; no source/vendor bind mount; no root final process; no destructive `down --volumes`. Анти-подгонка: image test inspects effective Compose JSON and Docker metadata, not comments or target names.
