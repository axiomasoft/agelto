Фаза сначала материализует общий исполняемый citation gate, затем снимает воспроизводимый baseline Agelto и трёх локальных reference projects и проверяет внешние практики по первичным источникам. ## Scope Included

1. Исполняемый stdlib citation verifier с embedded selftest и fail-closed strict mode до P0.1.
2. Инвентарь Agelto по восьми несущим поверхностям: Docker/Make, deploy/bootstrap, secrets, assets/readiness, protected docs, proxy, document/extension pipeline, tests/CI.
3. Сравнение Sova, Vintera/CMS и Dterema по одной матрице с полным snapshot provenance для dirty trees.
4. Три RAG-трека по инфраструктуре, Laravel-экосистеме и domain/security contracts с independent verification; infrastructure track закрывается только после зелёного MCP replay D56.
5. Синтез alternatives, acceptance matrix, consumer map, frozen contract и route-review matrix.
6. Отдельный fresh-context phase audit после закрытия P0; неудачная попытка workflow-авторинга сохранена как evidence D15.
7. Один адресный remediation-item P0.7 закрывает F1–F5 из `## Audit P0 — 2026-08-10` без повторного проектирования, RAG или изменения frozen product semantics.

## Scope Excluded

- Любые правки application code, Docker/Compose/Makefile, Composer, env, schema, tests и project docs.
- Копирование reference repositories в Agelto, их checkout/stash/commit или очистка dirty state.
- Выбор новых dependencies без официального source/compatibility verdict; implementation любого из выбранных contracts.
- Самовольное закрытие owner-policy развилки: необратимая или равносильная альтернатива остаётся proposed decision.

## Audit P0 — 2026-08-10

**Вердикт: RED** · заход 1 · phase-close нельзя считать подтверждённым до устранения F1–F3. F4–F5 — учётные дефекты, которые следует закрыть тем же повторным заходом.

### Findings

**F1 · Major · high confidence · issue — embedded selftest citation gate не доказывает запечатанную acceptance-матрицу.** `phases/P0/P0.0.md:11-12` требует positive/negative line/range/list/symbol/JSON, реальную two-base precedence, strict/non-strict exit и exception mismatch. Фактические три теста в `plans/verify-citations.py:156-190` проверяют только положительные формы, два отрицательных path-случая, прямой `scan()` с точным exception и archive opt-in; `main()`/CLI exit boundaries, конфликт одинакового пути в двух bases, negative range/list/symbol/JSON и exception mismatch не исполняются. Сценарий отказа: регрессия делает `--strict` fail-open либо выбирает неверную base, selftest остаётся зелёным, а 51 downstream acceptance gate принимает неверно разрешённые citations.

**F2 · Major · high confidence · issue · PROMOTE-CANDIDATE — terminal states теряют обязательные write-site compiler codes.** Независимое вычисление текущих bundles для P0.0–P0.6 вернуло `pre_mutation: allow` и `pre_final: allow`, но эти значения напечатаны только в `phases/P0/P0.3.state.md:15-17`; они отсутствуют в `P0.0.state.md:15`, `P0.1.state.md:15`, `P0.2.state.md:15`, `P0.4.state.md:15`, `P0.5.state.md:15` и `P0.6.state.md:15`. Для P0.6 коды были в `journal.jsonl:52`, но последующий `plan-close` в `journal.jsonl:54` вытеснил их из byte-fresh state, а lint остался зелёным. Сценарий отказа: cold-start auditor видит `🟢`, но не может доказать обе write-boundaries; повторная reconciliation бесшумно стирает обязательное evidence. Нужен общий Task-инвариант, запрещающий terminal green без обоих кодов в текущем state.

**F3 · Major · high confidence · issue — Validation P0.6 не воспроизводится на заявленном item commit.** На чистом дереве `52fb69c6` команда `plan-views.py decisions --plan-dir ... --check` из обязательной цепочки `phases/P0/P0.6.md:12` завершается с exit 1: `decisions/_current.md` устарел. При этом `phases/P0/P0.6.state.md:15` утверждает, что `52fb69c6 and declared validation are green`. Остальные P0.6 checks на этом дереве зелёные, а current HEAD уже содержит свежий view, но это не исправляет ложный якорь закрытия. Сценарий отказа: чистый checkout заявленного accepted artifact не проходит собственную acceptance-команду и не содержит актуальную проекцию D57–D61.

**F4 · Minor · high confidence · issue — route deviation P0.4 записан без факта отклонения.** Routing требует `implementation/high` (`plan.md:68`), тогда как terminal event выполнен `frontier/high` (`journal.jsonl:45`). У события есть friction `deviation`, но `phases/P0/P0.4.state.md:17` и Phase Handoff повторяют только «findings committed; checks green», не называя overshoot. Сценарий отказа: cold-start route audit зависит от ручной дедукции из append-only journal и не может отличить осознанное превышение route от повреждённой метки.

**F5 · Minor · high confidence · issue — D60 использует неканонический RAG marker.** `decisions/D60-recovery-policy-owner-gate.md:14-15` смешивает канонический `RAG:✅` с `RAG:[UNVERIFIED]`, хотя frozen enum допускает `[UNVERIFIED]` как самостоятельный marker. Сценарий отказа: машинная агрегация принимает решение как полностью verified по первому валидному token и не распознаёт ownership-dependent operational values как непроверенные.
