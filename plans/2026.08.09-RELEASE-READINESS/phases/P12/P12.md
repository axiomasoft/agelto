# P12 — Ubuntu deployment guide и финальный clean-room rehearsal

## Phase Context

P12 начинается только на terminal committed P0–P11 tree и превращает уже работающие carriers в
один literal zero-to-production путь для Ubuntu 24.04 LTS. P12.1–P12.3 подготавливают host,
раздельные read-only Git identities, loopback Nginx/TLS ingress и owner-approved recovery/alert
profile с deterministic config/fixture gates; application-dependent proof до deploy запрещён D53.
P12.4 выполняет первый immutable deploy без host build и доказывает live HTTPS/application paths.
P12.5 включает recurring backup/watchdog units после deploy и доказывает scheduled off-host set,
retention/alert delivery, обычный release, Horizon drain, D20 staged secret rotation
apply/verify/rollback, previous-digest rollback и полный isolated restore. P12.6 сверяет каждую
dev/prod/agent/Vite command с executable source, а P12.7 повторяет guide на свежей VM и выдаёт
только `READY|NOT_READY`. Никакой warmed state, local emulation или prose promise не заменяет
реальный host/DNS/registry/CI/backup proof.

> **Owner reframe input — D89.** Текущий Phase Context и item acceptance требуют re-design:
> P12 становится локально проверяемым preparation package в одном adjacent batch P12.2–P12.7.
> Реальные host/DNS/registry/CI/deploy/backup/restore/rehearsal действия переходят в отдельный
> следующий test plan, а не остаются gate, block или deviation этой фазы. Design root обязан
> заменить противоречащие поля items/Routing/DoR и сохранить R&D findings before execution.

> **Контракт фазы (contract-first).** Потребляет: terminal committed P0–P11 products, `root/contracts/release-readiness-v1.md`, D9/D17/D19–D27/D39/D42–D45/D49–D50/D53 и owner-filled production profile; каждая команда документации обязана ссылаться на реально проверенный carrier · Производит: Ubuntu host/repository/ingress guides, pre-deploy recovery config/fixture gates, first deploy with live application proof, post-deploy recurring backup/retention/watchdog/alert/restore evidence, subsequent deploy, D20 rotation and recovery runbooks, command matrix, rehearsal evidence и final readiness report · Границы: не строит image на production host, не требует application evidence до P12.4, не изобретает отсутствующий шаг в prose, не ослабляет security/quality gates и не объявляет READY при residual blocker

## Scope Included

1. Idempotent Ubuntu 24.04 host provisioning and security preflight with real disposable-VM proof.
2. Раздельные read-only Git identities, pinned private vendor access and immutable image retrieval.
3. Loopback app topology, Nginx/TLS ingress and owner-approved recurring off-host backup/retention/watchdog/alert profile.
4. First deploy, subsequent release, D20 staged secret rotation, previous-digest rollback, isolated restore and source-derived command matrix.
5. Fresh-VM clean-room replay with final binary `READY|NOT_READY` report.

## Scope Excluded

- Cloud/VPS/DNS/registry account procurement and invented production secrets or policy values.
- Image build on production host, floating tags, prose-only commands or warmed-state acceptance.
- Automatic choice of RPO/RTO/retention/backup destination; these stay owner gates D44.
- READY verdict with residual blocker, missing live CI evidence or untested restore/rollback path.

## Sequence and orchestration

| Шаг | Зависимость | Результат |
|:--|:--|:--|
| P12.1 | terminal P0–P11 | hardened Ubuntu host and profile carrier |
| P12.2 | P12.1 | repository/private-vendor/image identity proof |
| P12.3 | P12.2 + owner D44/D50 values | ingress/recovery config and deterministic fixture gates; no application-dependent proof |
| P12.4 | P12.3 | first immutable production deploy plus live HTTPS/readiness/Doctor/Livewire proof |
| P12.5 | P12.4 + staged P2.2 `.next` set | real scheduled backup/retention/watchdog/alert/restore proof, release and D20 rotation apply/verify/rollback |
| P12.6 | P12.5 | executable command/troubleshooting matrix |
| P12.7 | P12.6 | fresh-VM rehearsal and final verdict |

Цепь strict sequential и содержит external-state owner gates: следующий step использует реальный
evidence carrier предыдущего. Параллельный autonomous workflow небезопасен и не заявлен.

## External fact classes
