**Implementation Rules:** P12.4 terminal and current deployment healthy. Before any release/rotation mutation, enable the P12.3 backup/watchdog units, wait for and identify one real scheduled run, verify independent off-host read/hash, apply retention only after verified copy, observe service-failure plus overdue/disk alert delivery and restore the resulting DB/object/secret/config set into a unique isolated application project. Rotation refuses incomplete/stale/symlinked `.next`, wrong permissions, concurrent release/backup/rotation, red baseline or missing fresh verified backup; before-state files and provider identities are hashed/redacted, not printed. Each APP/DB/Redis/MinIO row names prepare→switch-authority→switch-consumers→restart/drain→verify→retire-old order and exact reverse rollback. New DB connection/migration read, Redis queue/cache, MinIO object round-trip, APP encryption/session/readiness and authenticated browser checks must pass before old active-auth is retired; prior APP key may remain only in an explicitly verified bounded decrypt-only compatibility list. Any apply failure automatically stops and offers owner-confirmed rollback; rollback restores authoritative services and file mounts in reverse, restarts bounded workers and must regain the same full checks. Image rollback is allowed only when schema compatibility says previous app can read current DB; otherwise stop for owner restore/remediation decision. Restore always targets unique isolated DB/bucket/secret root first. RAG:— (repo-grounded: D17/D20/D23/D44/D49/D50/D53 and P1/P2 carriers).
