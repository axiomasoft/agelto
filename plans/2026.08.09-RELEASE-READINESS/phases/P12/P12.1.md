### P12.1 — Подготовить пустой Ubuntu: deploy user, SSH hardening, firewall и Docker

**Intent:** На terminal P0–P11 tree создать и буквально прогнать idempotent Ubuntu 24.04 LTS host carrier: dedicated key-only deploy identity, validated SSH hardening, effective firewall/Docker socket boundary, official Docker Engine/Compose install, log rotation и machine-readable production profile. RAG:✅ 2026-08-09 official Ubuntu/Docker evidence in `findings/P12-ubuntu-deployment-rag-2026-08-09.md`; D43.
**Why:** Пустой сервер не воспроизводим через список prose-команд: Docker ports могут обходить UFW, `docker` group равна root-level privilege, а неверный sshd fragment может отрезать доступ. RAG:✅ 2026-08-09 official Docker/Ubuntu security docs captured in P12 finding.
**Scope Included:** Terminal P0–P11 gate · Ubuntu 24.04 architecture/package baseline · explicit `check|apply` host provisioner · `deploy` user/home/SSH key permissions · root/password SSH denial with safe two-session cutover · restricted sudo/provisioning boundary · Docker official apt repo/Engine/Compose plugin · no Docker TCP API · loopback/public port inventory · effective UFW/iptables/DOCKER-USER assertions · unattended security updates/reboot reporting · Docker log rotation/disk/capacity/time-sync checks · ignored owner-filled production profile with schema/redacted agent output · disposable-VM evidence.
**Scope Excluded:** Ubuntu 26.04 support · cloud account/VPS creation · DNS/Nginx/TLS P12.3 · Git deploy keys/repos P12.2 · application/image deploy · host-wide monitoring vendor · arbitrary CIS hardening · automatic reboot during an active deployment · secret values in tracked profile.

**Implementation Rules:** P11.6 and every earlier phase state must be terminal with no release blocker. Provisioner supports read-only `check` and explicit `apply`, rejects other distro/release/architecture and re-verifies current official Docker apt instructions before mutation. SSH changes live in a fragment, pass `sshd -t`, preserve the current session and require a second successful key-only login before password/root denial. `deploy` is the sole runtime owner; Docker group privilege is printed as root-equivalent, socket stays Unix-only, no `2375/2376`. Effective network proof enumerates listening/published ports and rejects any non-loopback application/data port beyond 22/80/443. Production profile parser accepts a closed key set, rejects missing/duplicate/placeholder/control/symlink/weak-permission values and redacts all secrets. RAG:✅ 2026-08-09 official sources in P12 finding; repo policy D43.
**Code Guidance:** Use small quoted Bash functions with explicit check IDs and temp fixtures; Make remains a thin carrier. Never `curl | sh`, `eval`, broad recursive chmod/chown, delete an existing user/key/rule, enable UFW before SSH allow, restart sshd before `sshd -t`, expose the Docker API, print environment values or assume UFW alone controls Docker. Анти-самообман: a package-installed or `ufw active` check is insufficient; disposable-VM validation must prove reboot persistence, second SSH login, effective socket/port rules and rerun byte/state stability. If terminal P1 requires another host/image boundary, stop and escalate D43.
