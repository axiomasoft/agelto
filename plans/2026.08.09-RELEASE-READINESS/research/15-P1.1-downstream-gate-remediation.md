## Диагноз

P1.1 product commit реализовал Make surface и прошёл собственный harness, после чего
`downstream-gate-v1` механически нашёл 20 consumers общих Make/docs carriers. Их Validation была
записана как смесь будущих команд, prose и нескольких inline-code fragments. Gate исполняет каждый
разделённый ` · ` фрагмент, если адресованные repository paths уже существуют; команда без
адресованного path также применима. Поэтому до реализации consumers были запущены будущие цели
`make infra:check`, Doctor/Pest/pnpm/Composer checks и случайные пояснительные tokens вроде `/up`,
`--ci`, `locally()`. Итог RED описывал незрелость будущих consumers, а не регрессию producer.
RAG:— (repo-grounded: records и Task source выше).

## Целевой contract

1. Validation будущего consumer имеет ровно один machine entrypoint — item-owned executable
   carrier, явно объявленный в Files. Полная acceptance-матрица остаётся в описании Validation,
   но исполняется самим carrier и имеет один итоговый exit code.
2. До появления carrier в producer tree downstream outcome честно `unknown`; это не pass и не
   блокировка producer. После реализации consumer carrier обязан выполнить все перечисленные
   static/dynamic/negative checks, без soft points.
3. Нельзя получать `unknown` удалением честных dependency paths, fabricated missing sentinel или
   advisory bypass. Carrier должен быть реальным deliverable item и оставаться его основным
   verification entrypoint.
4. Coupling-batch охватывает P1.1–P1.5 и полный union механических consumers P1.1–P1.4. После
   правки admission симулируется на commit `ddb446a4`: applicable command count должен быть 0 для
   каждого незапущенного consumer, затем state/bundle/decision/status views пересобираются.

## Альтернативы

- Игнорировать RED вручную: запрещено fail-closed contract и оставляет лживую terminal state.
- Скрыть общие Files/Required Reads: ломает dependency discovery и холодный старт.
- Ослабить Task runtime глобально: внешний cross-repo scope, не нужен для корректного plan-side
  declaration.
- Выбран item-owned carrier: сохраняет fail-closed gate, делает applicability машинной и оставляет
  полную Validation в собственности consumer.
