## 1. Почему прежний гейт P4.3 (Validation 3) не измерял ничего

`git grep -n "discoverWidgets" 80cec5f -- app/Providers/Filament/AdminPanelProvider.php`:

```
app/Providers/Filament/AdminPanelProvider.php:46:            ->discoverWidgets(in: app_path('Filament/Widgets'), for: 'App\Filament\Widgets')
```

Строка живёт в файле с коммита `db724a1` («feat(admin): Filament 5 admin panel on Azguard (phase 1)»,
проверено `git log --oneline -1 -S "discoverWidgets" -- <файл>`) — задолго до этого плана. Греп по
слову `Widgets` в этом файле непуст на `<base>` по построению; более того, `import`-строки
`Filament\Widgets\AccountWidget`/`FilamentInfoWidget` (`:15-16`) дают совпадение сами по себе.

**Следствие для формы гейта:** регистрация нового виджета в этом проекте НЕ является правкой
`AdminPanelProvider.php` — она является появлением класса в каталоге `app/Filament/Widgets/`.
Значит, доказывать её надо составом панели, а не грепом по провайдеру.

есть проверка красна «до» и зелена «после» — исход «а» D89.

## 3. Право доступа к виджету (AzGuard) — и ловушка вакуумно-зелёного теста

- `vendor/axioma-studio/azguard-filament/src/Concerns/HasAzGuardWidget.php` — трейт даёт
  `static canView()`, делегирующий `PageWidgetAccessEvaluator::authorize(subjectClass, ability)`;
  ability — `config('az-guard-filament.widgets.ability')` = `view`
  (`config/az-guard-filament.php:93-95`).
- Ключ права: `PermissionSchema::key()` (`…/Permissions/PermissionSchema.php:37-44`) по шаблону
  `config/az-guard-filament.php:106-107` = `{panel}.{resource}.{ability}`, `case: snake`, где
  `{resource}` = `class_basename($subjectClass)`. Для `LlmSpendChartWidget` → **`admin.llm_spend_chart_widget.view`**.
- Каталогизация права идёт из состава панели:
  `vendor/axioma-studio/azguard-filament/src/Permissions/FilamentDiscovery.php:67-73` —
  `foreach ($panel->getWidgets() as $widgetClass)`. Отдельной регистрации права руками не нужно.
- **Ловушка (ключевая для формы теста):** `PageWidgetAccessEvaluator` намеренно ДЕГРАДИРУЕТ в
  «разрешено» на трёх ветках — `:43` (нет текущей панели), `:49` (панель без плагина AzGuard либо
  `enforce=false`), `:55` (нет пользователя или он без `hasPermission()`). В тесте, где не выставлен
  текущий панель-контекст и нет `actingAs`, `canView()` вернёт `true` ВСЕГДА, и тест «право
  проверяется» будет зелёным, ничего не проверяя. Поэтому тест обязан показать РАЗНЫЕ исходы для
  двух пользователей.
- Суперадмин проходит по wildcard: `app/Guards/Admin/Roles/SuperAdminRole.php` →
  `[PermissionKey::WILDCARD]`; образец подготовки ролей в тесте —
  `tests/Feature/Filament/AdminPanelAccessTest.php:19` (`beforeEach(fn () => artisan('guard:sync-roles'))`).
- Выдача права виджета конкретным ролям (`app/Guards/Admin/Roles/{Operator,Analyst}Role.php`) —
  НЕ предмет P4.3: пока право не выдано роли, виджет виден только суперадмину. Названо в Pending
  Work item'а, носитель — P5 (права панели).

## 7. RAG — схема ручной выгрузки биллинга Google (внешний факт)

**RAG:✅ 2026-07-30, Perplexity Web.** Вопрос: «какие колонки содержит CSV, скачиваемый со страницы
Cloud Billing → Reports (Download CSV), и какие — экспорт usage из AI Studio».

**Вердикт:** единой фиксированной схемы НЕТ.

- CSV со страницы Reports формируется ПО ТЕКУЩЕЙ ГРУППИРОВКЕ отчёта: колонки следуют выбранному
  `Group by` (Service · SKU · Date > Service · Date > SKU), то есть дата присутствует только при
  дата-группировке; отдельной гарантированной колонки валюты движок в документации не нашёл.
  **Граница доверия названа честно:** движок сослался на биллинг-доки Google
  (`cloud.google.com/billing/docs/how-to/reports`) пересказом, отдельным URL в списке источников
  ответа это утверждение не подтверждено — единственная выданная ссылка относится к AI Studio (ниже).
  Для проектного вывода этого достаточно: вывод состоит в ОТСУТСТВИИ фиксированной схемы, а
  отсутствие подтверждается и пересказом, и тем, что схему не удалось процитировать.
- Экспорт из AI Studio — это выгрузка ДАТАСЕТА логов (CSV/JSONL/Sheets), а не отчёта о стоимости;
  состав колонок зависит от того, что попало в датасет.
  Источник (единственная выданная ссылка): `ai.google.dev/gemini-api/docs/logs-datasets`.
- Ранее (RAG:✅ 2026-07-28, `rag-provider-billing-2026-07-28.md`) уже зафиксировано: REST
  фактического расхода у Google нет, стабильная программная схема — только экспорт Cloud Billing в
  BigQuery, отложенный владельцем (D34).

**Следствие для проектирования P4.4 (D130):** привязывать парсер к колонкам Google нельзя — они не
контракт, а функция того, как оператор сгруппировал отчёт. Команда принимает НОРМАЛИЗОВАННЫЙ CSV
нашего формата (обязательные `date`, `cost`; опциональные `currency`, `service`, `sku`), опознаёт
колонки по заголовку со списком алиасов и отказывает явным сообщением при незнакомом заголовке;
click-path «как получить такой файл из Cloud Billing» несёт runbook, а не код.
