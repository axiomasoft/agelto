**Status:** 🟠 Done with deviations
**Intent:** Довести до системной части промта транзитивное замыкание контрактов шага (вложенные Data-типы и enum'ы с их докблоками и `#[Alias]`) по ТОМУ ЖЕ правилу обхода, что строит JSON-схему, плюс словари, недостижимые обходом, которые объявляет сам ТИП; заменить зелёный-по-построению тест словарей проверкой по боевому пути.

**Implementation Rules:**
1. **Правило обхода — ОДИН владелец.** Вторая реализация «что считается вложенным типом» рядом с `JsonSchemaGenerator` ЗАПРЕЩЕНА: расхождение двух носителей — ровно тот дефект, который item чинит (класс, попавший в схему, но не в контекст, невидим глазами). Форма выделения (отдельный класс-обходчик, публичный метод существующего генератора) остаётся за исполнителем, инвариант проверяется тестом когерентности (Validation п.5).
2. **Выход `JsonSchemaGenerator` обязан остаться БАЙТ-В-БАЙТ прежним.** До рефакторинга снять golden-фикстуру схемы для Response-классов всех шагов извлечения и скрининга, закоммитить её, после рефакторинга сверять тестом. Схема — контракт structured output провайдера: её молчаливое изменение ломает разбор ответа, а не тест.
3. **Словари шага объявляются ОДИН раз в каталоге типа.** Захардкоженный список словарей в call-site'е — дефект: у шага `extract_rows` потребителей несколько (`RowRangeChunkSource`, `WindowedChunkSource`, экспорт датасета), и разъезд между ними даёт датасет, обученный на промте, отличном от боевого. Если носитель шага (контракт P2.1) уже несёт место для такого объявления — использовать его; если НЕ несёт — объявить внутри каталога анализатора, НЕ трогая замороженный контракт; если окажется, что без правки контракта не обойтись — остановиться и эскалировать (§10).
4. **Детерминированность выхода не ослабляется.** Порядок классов обязан оставаться стабильным между прогонами и между машинами (сортировка по короткому имени, Response-обёртки последними): системная часть — префикс implicit-кэша всех провайдеров, недетерминированный порядок обнуляет кэш молча. Множество классов, приходящих из обхода, сортируется тем же правилом, а не порядком обнаружения.
5. **`rules_hash` меняется — это ожидаемое последствие, а не побочный эффект.** Item обязан назвать его числом (старый/новый sha1 системной части по каждому шагу) и явно записать в Completion Notes, что живые explicit-кэши анализов инвалидируются штатным механизмом `LlmCacheManager::validHandle()`. Ручная правка `rules_hash` в БД или обход инвалидации ЗАПРЕЩЕНЫ.
6. **Тест словарей идёт по БОЕВОМУ пути.** Существующая проверка (`PromptCompositionTest.php:49`) передаёт классы словарей в генератор руками и зелена по построению — она заменяется (не дополняется) проверкой системной части, собранной `PromptComposer` для РЕАЛЬНОГО шага. Фальсифицируемость проверяется руками: снять регистрацию словаря → тест обязан покраснеть; результат цитируется в Completion Notes.
