**Scope Included:** РЕШЕНИЕ по составу интерфейса `DocumentAnalyzer` — строго по правилу «в контракте ровно то, что вызывает ЯДРО», с перечислением call-site'ов ядра, из которых каждый метод выведен; РЕШЕНИЕ по замене флага `has_extractor` (D16) — как тип отвечает «есть ли у меня извлечение» и что именно диспатчится; РЕШЕНИЕ по сводке результата (D27): форма DTO-сводки, которую витрина P5 показывает, не зная про `prc_estimate_*`; РЕШЕНИЕ по носителю шага извлечения и назначения вызова — как общий enum и enum анализатора сосуществуют в сигнатурах `PromptComposer::compose()`, `PromptReadRepository::activeForSteps()` и маршрутизации, и кто задаёт цепочку композиции (`global → step-global → step`) вместо сегодняшней match-лесенки; РЕШЕНИЕ по механизму регистрации (что физически есть «одна строка регистрации» D14) и по поведению реестра на типе без анализатора и на `AiDocumentType::Unknown`; РЕШЕНИЕ по конвенции каталога типа — точный неймспейс каталога анализатора и ТОЧНЫЙ список неймспейсов ЯДРА, на который встанет arch-тест P2.6; РЕШЕНИЕ по месту валидации `step`/`purpose` по реестру типа (сейм назван контрактом P1.2, реализация — P2.5); по КАЖДОМУ решению — отвергнутая альтернатива одной строкой; запись `root/document-analyzer-contract.md`; предъявление владельцу и фиксация его «утверждаю».

**Implementation Rules:**
1. **Правило состава интерфейса: в контракт входит РОВНО то, что вызывает ядро.** Каждый метод обязан нести в контракте call-site ядра, из которого он выведен (`файл:строка`). Метод без call-site'а — спекуляция: персистер, валидатор, ститчер, метрика анализатора сметы вызываются ЕГО ЖЕ кодом внутри его каталога и в интерфейс не выносятся. Контракт, перечисляющий «шаги, промты, DTO ответа, job, персистер, валидатор, метрику» без такой привязки, считается невыполненным.
2. **Кросс-документное назначение — не анализатор.** Носитель, заменяющий строку `'any'`, задан контрактом P1.2; реестр анализаторов его НЕ обслуживает (у кросс-документных вызовов нет типа документа). Контракт обязан показать, как обе оси сосуществуют в сигнатуре маршрутизации.
3. **`AiDocumentType::Unknown` анализатора не имеет.** Сегодня `unknown`/`null` уводит документ в `ignored` (RAG:— repo-grounded: `ScreeningOutcomeHandler.php:119`) — контракт обязан сохранить это поведение и назвать, где оно живёт после развязки: в ядре или в реестре. Заводить «анализатор неизвестного типа» ради единообразия ЗАПРЕЩЕНО — это вернуло бы ветвление по типу в ядро через чёрный ход.
4. **Сейм носителя шага.** Контракт обязан ответить проверяемо: какой тип стоит в сигнатуре `PromptComposer::compose()` после расщепления, как `PromptReadRepository::activeForSteps()` получает список значений, и КТО задаёт цепочку композиции вместо `stepsForComposition()`-лесенки. Ответ «шаг остаётся строкой» допустим только с явным разбором цены (потеря compile-time-проверки уже принята для БД D7 — но не автоматически для PHP-сигнатур).
5. **Регистрация анализатора обязана переживать `config:cache`.** Если носителем выбран config-массив, значения — имена классов, а не замыкания; если сервис-провайдер — регистрация детерминированная и не зависит от порядка загрузки. Механизм, ломающийся под `config:cache`, отвергается (скилл `config-driven-abstraction`).
6. **Конвенция каталога типа задаётся ЯВНЫМ неймспейсом**, а не описанием «где-то рядом»: приёмка D14 и arch-тест P2.6 считаются по нему буквально. Список неймспейсов ЯДРА для arch-теста перечисляется поимённо и обязан покрывать `App\Services\Procurement\Screening`, машинерию `App\Services\Procurement\Extraction` и `App\Services\Llm`.
7. **Каталоги DTO не перепланируются** (D19 отдал раскладку `app/Dto/Procurement/Ai/**` фазе P3): контракт называет, что DTO сметы остаются на месте до P3, и что arch-тест P2.6 обязан считать `App\Dto\Procurement\Ai\Estimate\**` частью поверхности ТИПА, а не ядра. Иначе P2.6 покраснеет на состоянии, которое фаза сознательно не чинит.
8. **Сводка результата (D27) — DTO, а не разметка.** Контракт называет поля сводки и запрещает возврат HTML/Blade из анализатора: презентация остаётся в P5, анализатор отдаёт данные.
9. Контракт — замороженный документ: после утверждения владельцем правится только новой D-записью со ссылкой `supersedes`.
