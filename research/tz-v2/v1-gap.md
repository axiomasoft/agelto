## 2. Решения/идеи v1, не учтённые в v2

- **Дневная посуточная witness-таблица метрик пайплайна** (`plt_crawler_analytics`: `s1_found/s1_errors … s4_parsed_items/s4_errors`, unique `(date, crawler_id)`) — в v2-схеме **нет вообще никакого аналога**. Ни `crw_fetches`, ни `prc_events`, ни `sys_operation_logs` не дают готового посуточного среза «сколько нашли/сколько ошибок» по стадиям на конкретный `crawler`. Для дашборда/observability понадобится либо материализованная витрина поверх партиционированных `crw_fetches`/`prc_events`/`ai_llm_calls`, либо отдельная `crw_daily_stats`-таблица — сейчас это открытый пробел, а не осознанное решение (в тексте v2 не упомянуто и не отвергнуто явно).
- **Дедуп LLM-цепочки через `rules_hash` на связке "документ+кэш+версия промпта"** — в v2 есть `ai_llm_calls.prompt_version_set jsonb` (неплохая замена), но нет явного механизма «если `rules_hash` не совпал с текущим — кэш невалиден» на уровне схемы/чек-листа §11 — стоит явно прописать инвалидацию кэша по смене промпт-версии как сценарий (её сейчас нет в таблице чек-листов §11).
- **Явный recovery/heartbeat для детального слоя карточки** — в v1 весь retry/attempts/heartbeat жил на уровне `plt_crawler_links` (детальный парсинг = тот же линк). В v2 детальный слой карточки (`prc_procurements.detail_fetched_at`) не имеет собственного error-блока (`attempts/next_retry_at/failed_permanently`) — если снятие детальной карточки упало, непонятно, как её ретраить: приходится реконструировать через `crw_fetches` (лог попыток), но явного механизма приоритизации ретраев по `detail_fetched_at IS NULL` не описано.

## 3. Что из v1 осознанно НЕ переносим (v2 уже подтверждает решение верно)

- **`geo_locations`/`geo_countries`** (ФИАС/КЛАДР с geometry) — в v2 корректно заменены плоским денормализованным `region_code text` на `org_organizations`/`prc_procurements`, тяжёлый геосправочник не тянется (§12 явно откладывает «адресный слой (ГАР)» на будущее).
- **`sys_proxity_services`** (опечатка "proxity") — не воспроизведена; v2 просто ссылается на `crw_proxies`/`crw_proxy_checks` по образцу `sys_proxies`.
- **`ord_lot_infos`** со строковыми `quantity`/`unit_price`/`total_price`** — в v2 `est_items` типизирован нормально (`numeric(18,6)`/`numeric(18,2)`), техдолг не унаследован.
- **`plt_document_analysis_logs`** (отдельный построчный лог сессии анализа) — в v2 не выделен отдельной таблицей; функцию частично закрывает связка `ai_llm_calls` (детальный технический след вызова) + `sys_operation_logs` (общий операционный журнал) — осознанная консолидация, а не пробел.
- **`plt_platform_proxies`** (pivot платформа↔прокси) — не нужен: v2 (как и v1 `sys_proxies.targets jsonb`) уже решает привязку прокси к цели через `targets jsonb`, отдельный pivot избыточен.
- **`app/Dto/Estimates/*` + `ItemType` enum + `SmetaParserService`** (legacy/дублирующая версия схемы сметы) — не имеет отражения в v2 и не должна: `est_*` таблицы строятся по более продуманной `Schema/*`-модели, а не по этому мёртвому коду.
