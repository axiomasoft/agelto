# CSV-экспорт результатов поиска ЕИС zakupki.gov.ru — исследование

## 1. Механизм кнопки «Выгрузить результаты поиска»

На странице `/epz/order/extendedsearch/results.html` (и аналогичных: `/epz/contract/search/results.html` для реестра контрактов) над таблицей результатов расположена пиктограмма «Выгрузить результаты поиска». По клику:

1. Открывается модальное окно **«Выгрузка данных»**, где сначала предлагается выбрать набор полей/колонок будущего файла (можно оставить дефолтный набор или отметить нужные).
2. Далее — второй шаг модалки с указанием **диапазона записей** для выгрузки (пример: «1–500», «501–1000» и т.д.) с верхним лимитом **до 5000 записей** за одну операцию выгрузки.
3. Сервер формирует и отдаёт **CSV-файл**, физически ограниченный примерно **500 записями на один файл**; если диапазон больше — портал сам разбивает выгрузку на несколько файлов.

Пример имени файла из практики: `ContractSearch(1-146)_07.04.2024.csv` — префикс типа реестра, диапазон строк в скобках, дата выгрузки.

**Важная оговорка (не удалось подтвердить документально):** точный URL внутреннего эндпоинта (`download.html` или его аналог), полный список HTTP-параметров и метод (GET/POST) **нигде официально не задокументированы**. Информация восстанавливается сообществом только через DevTools → Network при ручном клике по кнопке — то есть это undocumented/internal route, который менялся при редизайнах портала и не гарантирует обратной совместимости. Помимо самой выгрузки, у портала есть исторически известные «полуслужебные» пути (`downloadDocument.html?id=...`, `pgz/printForm?type=NOTIFICATION&id=...`) для скачивания отдельных документов/печатных форм — это другие эндпоинты, не массовый CSV-реестр.

Источники: [ppt.ru — пошаговая инструкция](https://ppt.ru/art/zakupki/kak-sokhranit-naydennye-v-yeis-zakupki-poshagovaya-instruktsiya), [habr.com/ru/articles/806877](https://habr.com/ru/articles/806877/), [qna.habr.com/q/49006](https://qna.habr.com/q/49006)

Запрос выгрузки жёстко привязан к текущей поисковой сессии/фильтрам, заданным на `extendedsearch/search.html` — то есть параметры фильтра (закон, даты, этап закупки, ключевые слова, ОКПД2, регион) должны быть применены до вызова выгрузки.

## 2. Формат CSV

| Параметр | Значение |
|---|---|
| Кодировка | Windows-1251 (де-факто стандарт рос. госпорталов под Excel/1С) |
| Разделитель | `;` (точка с запятой) |
| Формат имени файла | `<ТипРеестра>(<from>-<to>)_<дата>.csv`, напр. `ContractSearch(1-146)_07.04.2024.csv` |
| Колонки — 44-ФЗ | Номер извещения/реестровый номер, заказчик (наименование, ИНН/КПП/ОГРН), НМЦК, способ определения поставщика (закрытый нормированный справочник: конкурс/аукцион/запрос котировок/ЕП), этап закупки (статус), даты (размещение, окончание подачи заявок), регион и региональный код, ссылки на карточку |
| Колонки — 223-ФЗ | Тот же базовый набор полей, **но** значение «способ закупки» вариативно — заказчик описывает процедуры в своём Положении о закупке, поэтому помимо стандартных (конкурс/аукцион/запрос котировок/запрос предложений/ЕП) встречаются нестандартные названия («электронный магазин», закупка «с полки» и т.п.) |

**Вывод по совпадению колонок 44-ФЗ vs 223-ФЗ**: базовая структура похожа (номер, заказчик, цена, способ, этап, даты, регион), но:
- у 44-ФЗ «способ закупки» — закрытый нормированный справочник (можно смело кодировать как ENUM);
- у 223-ФЗ «способ закупки» — свободный текст по Положению заказчика, требует слоя маппинга/нормализации на своей стороне, плюс желательно хранить оригинальную строку отдельно.

Источники: [habr.com/ru/articles/806877](https://habr.com/ru/articles/806877/), [habr.com — Win-1251 в госсистемах](https://habr.com/ru/companies/vk/articles/129476/), [ofdata.ru/databases/44_223](https://ofdata.ru/databases/44_223), [fz44.org — про ЕИС](https://fz44.org/blog/2026/01/20/%D0%B5%D0%B8%D1%81/)

## 3. Лимиты, блокировки, требования к сессии

Часть цифр ниже получена из практических/сообщественных источников и **не подтверждена официальной документацией ЕИС** — помечаю явно.

- **Cookies/сессия обязательны**: портал использует `JSESSIONID` и сопутствующие cookie, выставляемые при первом заходе (например, на `/epz/main/public/home.html`). Без переиспользования единой сессии (persistent HTTP-client с cookie jar) запросы выглядят как «новые устройства» каждый раз — повышает риск детекта бота.
- **Anti-bot эвристики** (по опыту сообщества, не документировано официально): трекинг частоты запросов с IP, анализ равномерности интервалов (строго через N секунд — подозрительно), проверка User-Agent/Referer, иногда JS-активности.
- **Rate limit** — конкретные цифры (например, «~8 req/s комфортно», «~100 запросов/час на IP → блок на 24–72ч») встречаются в неофициальных гайдах по мониторингу ЕИС, но не в официальных источниках — **достоверность не подтверждена**, к цифрам стоит относиться как к ориентиру, не факту.
- **Прямой HTTP без браузера в принципе работает**: HTML/CSV на портале рендерятся на сервере (SSR), JS для получения данных не обязателен — обычный HTTP-клиент с сессией/cookie/заголовками достаточен для публичных страниц поиска и CSV-выгрузки.
- Рекомендации сообщества по устойчивости: случайные паузы (порядка единиц секунд) между запросами вместо фиксированного интервала, ограниченный параллелизм (единицы одновременных соединений), экспоненциальный backoff на 429/5xx/пустой body (встречается артефакт: HTTP 200 с 0-byte телом — списывают на Varnish-кэш, лечится ретраем).

Источники: практический синтез (без единого точного первоисточника по числам rate-limit — трактовать как неподтверждённое).

## 4. Опыт open-source парсеров

**github.com/VadimSpb/goszakupki** — исследовательский проект (парсинг закупок 44-ФЗ/223-ФЗ по Мурманской области, 2017–2018):
- Базовая выборка получена **вручную** через кнопку «выгрузить результаты поиска» → CSV → объединение и дофильтровка в Excel.
- Дальнейшее автоматическое обогащение (победитель, итоговая цена аукциона) частично получилось через сайт, а вот «предмет закупки» (перечень позиций/объёмов/цен) **не удалось полностью автоматизировать** — потребовался ручной проход по документации.
- Автор прямо фиксирует незавершённость: не поднялся VPN, поточный парсинг не был доведён до прод-режима.
- **Вывод**: это не production-ready ETL, а подтверждение, что (а) кнопка CSV реально работает и используется на практике, (б) извлечение позиций сметы/спецификации из вложений — отдельная, гораздо более сложная задача, не решаемая CSV-выгрузкой.

Источник: [github.com/VadimSpb/goszakupki](https://github.com/VadimSpb/goszakupki)

**habr.com/ru/articles/806877** — практическая инструкция: раздел «Контракты и договоры» → «Все параметры» → фильтр по ИНН поставщика → «Применить» → «Выгрузить результаты поиска» → окно «Выгрузка данных» → выбор полей → «Выгрузить». Подтверждает:
- лимит **не более 500 строк на один CSV-файл**, при большем количестве результатов — автоматическое разбиение на несколько файлов;
- имя файла с диапазоном строк в скобках;
- рекомендацию заранее сужать фильтры (дата, регион, сумма), чтобы не собирать вручную много «нарезанных» файлов.

Источник: [habr.com/ru/articles/806877](https://habr.com/ru/articles/806877/) (также смежная статья [habr.com/ru/articles/1041566](https://habr.com/ru/articles/1041566/) — про парсинг без официального API, с отдельными URL/режимами для 44-ФЗ и 223-ФЗ).

**excelvba.ru** — коммерческий VBA-парсер под заказ (не готовый open-source):
- Демо-версия собирает 50 закупок по 223-ФЗ по ключевому слову с базовым набором полей (способ, регион, объект, заказчик, НМЦК, дата окончания подачи заявок, ссылки).
- Полная (платная) версия — постраничный обход всех результатов, смена сортировки, произвольные поля, вывод в Excel (**не CSV напрямую** — конвертация в CSV была бы доработкой).
- В комментариях к странице зафиксирован **реальный кейс поломки** парсера после изменений вёрстки портала — прямое подтверждение риска: UI-парсинг ЕИС хрупок к редизайнам, нужна модель поддержки/мониторинга парсера.

Источник: [excelvba.ru/programmes/Parser/samples/zakupki](https://excelvba.ru/programmes/Parser/samples/zakupki)

## 5. Ограничение выдачи поиска и обход

- **Лимит выдачи расширенного поиска: 1000 записей** на один набор параметров (`/epz/order/extendedsearch/search.html` и `/results.html`) — записи после 1000-й недоступны в рамках одного запроса, независимо от постраничной навигации.
- Это **другой лимит**, чем «до 5000 за операцию выгрузки CSV» — 1000 ограничивает саму выдачу поиска (то, что вообще можно увидеть/выгрузить по текущему фильтру), 5000 (с нарезкой по 500) — верхняя граница диапазона в мастере CSV-экспорта одного поискового результата.

**Стратегия обхода лимита 1000** — дробление фильтра по дополнительным осям, пока в каждом поддиапазоне не окажется ≤1000 записей:
1. **Дата** (размещение/обновление, окончание подачи заявок) — основная ось, часто достаточно недели/месяца.
2. **Цена НМЦК** — диапазоны (0–100 тыс, 100 тыс–500 тыс, 500 тыс–2 млн, 2–10 млн, 10 млн+), можно рекурсивным бинарным делением.
3. **Регион** (местоположение поставки/заказчика) — третья ось при необходимости.
4. Практический алгоритм: рекурсивное бинарное деление диапазона по дате → если count > 1000, делить пополам → если ≤ 1000, принимать поддиапазон как атомарный; при пересекающихся границах — дедупликация по реестровому номеру закупки (уникальный ключ из URL `regNumber`).

Источники: [zakupki.gov.ru/epz/order/extendedsearch/results.html](https://zakupki.gov.ru/epz/order/extendedsearch/results.html), [research.spbstu.ru — руководство по поиску закупок в ЕИС](https://research.spbstu.ru/news/rukovodstvo_po_poisku_konkurentnyh_zakupok_v_eis/)

## 6. Альтернативы: FTP и SOAP-сервисы

**FTP (`ftp.zakupki.gov.ru`) — подтверждено закрыт с 01.01.2024.** Старые логины (`free/free`, `fz223free/fz223free`) и каталоги (`/fcs_nsi`, `/out/published`) актуальны только для исторических архивов. Официальная точка входа для машиночитаемых открытых данных сейчас — раздел **«Открытые данные»**: [zakupki.gov.ru/epz/opendata/search/results.html](https://zakupki.gov.ru/epz/opendata/search/results.html) (наборы по реестру контрактов 44-ФЗ, реестру договоров 223-ФЗ и др., с описанием структуры XSD).

**SOAP int44/int223 — подтверждён вывод из эксплуатации.** Ключевые факты по срокам:
- С 6 июля 2025 введены новые интеграционные домены, старые и новые какое-то время работали параллельно.
- **С 4 октября 2025** `int44.zakupki.gov.ru` и `int223.zakupki.gov.ru` полностью отключены — интеграция через них невозможна.
- Актуальные домены: `int.zakupki.gov.ru` (основной, ГОСТ с односторонней аутентификацией) и `int44-ttls-cert.zakupki.gov.ru` (44-ФЗ, ГОСТ + двусторонняя аутентификация по сертификату).
- Дополнительно: до **04.07.2026** всем пользователям/интеграционным системам нужно установить корневой сертификат Минцифры России — иначе HTTPS-доступ (включая интеграционные каналы) перестанет устанавливаться.
- Важная смысловая оговорка: SOAP int44/int223/int.zakupki.gov.ru — это сервисы **интеграции поставщика/заказчика с ЕИС** (подача заявок, обмен документами, публикация через внешние системы/ЭТП), а не публичный API для **массового чтения** реестра закупок/контрактов сторонним агрегатором. Для чтения массива данных официальный канал — раздел «Открытые данные» (XML/ZIP-наборы), а не SOAP int-сервисы.

Источники: [kbfit.ru — интеграция МедЕРП с ЕИС](https://kbfit.ru/articles/pod-kapotom-integracii-mederp-s-eis-ot-diagnostiki-do-vosstanovleniya/), [pro-ability.ru — новые домены ГИС ЕИС 2025](https://www.pro-ability.ru/tpost/n7un45opk1-novie-domeni-gis-eis-zakupki-2025-pereho), [budev.ru — выгрузка тендеров через FTP/XML (историческая)](https://budev.ru/gos-zakupki/167-vyigruzka-tenderov-s-goszakupok-cherez-ftp-i-xml.html)

## Рекомендации для ТЗ

**1. Первичный источник массовых данных — «Открытые данные» ЕИС, а не CSV-кнопка и не SOAP.**
Раздел `zakupki.gov.ru/epz/opendata/search/results.html` даёт официальные XML/ZIP-наборы по реестру контрактов 44-ФЗ и реестру договоров 223-ФЗ с задокументированной структурой (XSD) — это единственный канал без риска слома при редизайне UI. Строить основной ETL-пайплайн стадии 1 (Collector) на нём, а не на скрейпинге результатов поиска.

**2. CSV-экспорт через `extendedsearch/results.html` — вспомогательный/резервный метод, не основной.**
Использовать для:
- точечной довыгрузки полей, которых нет в наборах открытых данных;
- узких фильтрованных срезов (например, по ключевым словам/ОКПД2, которых нет в открытых XML-наборах в удобном виде);
- ручной/полуавтоматической верификации данных пайплайна.

Технически: **HTTP-клиент, не полноценный браузер** — портал рендерит HTML/CSV на сервере, JS для чтения не требуется. Но обязательно:
- persistent session (cookie jar с `JSESSIONID`), стартовый заход на `home.html` перед запросами;
- реалистичные заголовки (User-Agent, Referer, Accept-Language);
- случайные паузы между запросами (секунды, не миллисекунды), низкий параллелизм (единицы воркеров);
- explicit backoff/retry на 429/5xx/пустой body;
- поскольку точный endpoint/параметры выгрузки не задокументированы официально — перед реализацией **обязателен ручной сниффинг через DevTools Network** на актуальной версии портала (не полагаться на устаревшие описания из статей 2024 года — верстка ЕИС меняется).

**3. Дробление обязательно закладывать на двух уровнях:**
- на уровне поиска — лимит 1000 записей на фильтр → рекурсивное деление по дате (основная ось) + цена/регион (вторичные оси при необходимости);
- на уровне экспорта — лимит 500 записей на CSV-файл (до 5000 за операцию) → цикл выгрузок по диапазонам с последующей склейкой и дедупликацией по реестровому номеру.

**4. Парсинг CSV**: явно задавать `cp1251` при чтении (в PHP — `mb_convert_encoding`/`iconv` при импорте), разделитель `;`. Конвертировать в UTF-8 сразу на границе импорта, во внутренней модели хранить UTF-8.

**5. Раздельная нормализация «способа закупки» для 44-ФЗ и 223-ФЗ.**
44-ФЗ — фиксированный enum (закрытый нормативный список). 223-ФЗ — свободный текст по Положению заказчика: нужен маппинг-слой (справочник + fallback на «прочее») плюс хранение оригинальной строки для аудита/юридической точности.

**6. SOAP int.zakupki.gov.ru/int44-ttls-cert рассматривать только если понадобится интеграция как участника закупки** (подача заявок, электронный документооборот) — не как канал для сбора реестра. Если такая потребность появится в будущем — закладывать поддержку отечественных ГОСТ-криптоалгоритмов (stunnel+msspi или аналог) и корневого сертификата Минцифры (обязателен с 04.07.2026), а также миграцию на новые домены (старые `int44`/`int223` отключены с 4.10.2025).

**7. Устойчивость к изменениям вёрстки** — раз CSV-кнопка и параметры поиска undocumented и менялись исторически (подтверждено кейсом excelvba.ru), для стадии 1/2 пайплайна закладывать:
- health-check/smoke-тест на актуальность связки «поиск → выгрузка» (например, еженедельный контрольный прогон с известным ожидаемым числом записей);
- алертинг при резком падении/росте объёма выгружаемых данных или ошибках парсинга CSV-структуры (изменение набора колонок — частый признак редизайна).

**Что не удалось подтвердить документально** (явно отмечаю для ТЗ как риск):
- точный HTTP-метод, endpoint и полный список параметров выгрузки CSV — только сниффинг вручную;
- конкретные цифры rate-limit (req/s, запросов/час до бана) — только неофициальные оценки сообщества, требуют собственной калибровки в тестовом режиме перед продакшн-нагрузкой;
- стабильность CSV-эндпоинта во времени — исторически ломался при редизайнах портала.
