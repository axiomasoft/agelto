# Структура карточки извещения ЕИС (44-ФЗ / 223-ФЗ): исследование для проектирования детального слоя БД

## 1. Общая архитектура доступа к данным ЕИС

Прежде чем описывать поля — принципиальная развилка источника данных, критичная для архитектуры парсера.

**Два разных источника с разной надёжностью:**
- **HTML-страницы** (`https://zakupki.gov.ru/epz/order/notice/{тип}/view/common-info.html?regNumber=...`) — серверно рендерятся, не требуют JS/SPA-эмуляции для базового извлечения, но вёрстка/классы/id меняются без предупреждения (нестабильный контракт) [habr.com/ru/articles/869934](https://habr.com/ru/articles/869934/).
- **XML/SOAP-выгрузки** — машиночитаемый источник по XSD-схемам (узел `ns2:fcsNotificationEF` для извещения). С 01.01.2025 старый FTP-сервер выгрузок закрыт, актуальный канал — SOAP-сервисы `int44.zakupki.gov.ru` (`getDocsByReestrNumberRequest`, `getDocsByOrgRegionRequest`), ответ содержит `archiveUrl` со ссылкой на архив документов [habr.com/ru/articles/869934](https://habr.com/ru/articles/869934/), [ru.stackoverflow.com/questions/852237](https://ru.stackoverflow.com/questions/852237/).

**Рекомендация**: HTML — для мониторинга/ленты и fallback, XML/SOAP — для нормативно устойчивого импорта детального слоя.

### URL-схема карточки извещения

Единый шаблон: `https://zakupki.gov.ru/epz/order/notice/{код_типа}/view/common-info.html?regNumber={reestrNumber}`

| Код типа | Процедура |
|---|---|
| `ea20` | Электронный аукцион (44-ФЗ) |
| `ok20` | Открытый конкурс в электронной форме (44-ФЗ) |
| `zk20` | Запрос котировок (классический/в эл. форме) |
| `ezt20` | Электронный запрос котировок |

Примеры живых URL: `.../ea20/view/common-info.html?regNumber=0373200580423000005`, `.../ok20/view/common-info.html?regNumber=0172200002526000293` [zakupki.gov.ru](https://zakupki.gov.ru/epz/order/notice/ok20/view/common-info.html?regNumber=0172200002526000293), [roseltorg.ru](https://www.roseltorg.ru/procedure/0373200580423000005/1).

Для карточки контракта (после заключения) — отдельный путь: `/epz/contract/contractCard/common-info.html?reestrNumber=...` и `/epz/contract/contractCard/document-info.html?reestrNumber=...`.

Для 223-ФЗ отдельного стабильного `{код_типа}` не зафиксировано в открытых источниках — карточка открывается по ссылке «Перейти к извещению» из результатов поиска (`epz/order/extendedsearch/results.html`), точная view-схема параметров **не подтверждена достоверно**, требует эмпирической проверки на живых карточках.

## 2. Разделы карточки извещения 44-ФЗ

Публичная карточка логически делится на разделы (часть — вкладки, часть — блоки страницы):

| Раздел | Назначение |
|---|---|
| Общая информация / Извещение о закупке | Идентификаторы, способ закупки, заказчик, площадка, НМЦК, сроки |
| Объект закупки | Предмет закупки, категорийное описание (ОКПД2/КТРУ) |
| Требования к участникам / преимущества / нацрежим | Условия допуска |
| Обеспечение заявки и контракта | Финансовые гарантии |
| Документы | Прикреплённые файлы + структурированные блоки (критерии оценки, проект контракта) |
| Результаты определения поставщика | Победитель, цена, статус закупки |
| Протоколы | Все протоколы процедуры по этапам |
| Журнал событий | Хронология действий (публикация, изменения, разъяснения) |

Источники: [fz44.org](https://fz44.org/articles/еис/), [v1a.ru](https://www.v1a.ru/sovety/analiticheskie-stati/vse-chto-nuzhno-znat-ob-izveshchenii-v-goszakupkakh-po-44-fz-/).

### 2.1. Общая информация — перечень полей

- ИКЗ (идентификационный код закупки, 36 разрядов — расшифровка ниже)
- Реестровый номер извещения (= `regNumber`)
- Способ определения поставщика (аукцион/конкурс/запрос котировок/предложений/у единственного поставщика)
- Заказчик: наименование, ИНН/КПП, адрес, ОКТМО
- Организация, осуществляющая закупку (если отличается от заказчика), специализированная организация
- Электронная площадка (наименование ЭТП, ссылка)
- Контактное лицо: ФИО, должность, телефон, email
- НМЦК, валюта, размер аванса
- Источник финансирования, КБК
- Даты этапов: публикация извещения, начало/окончание подачи заявок, рассмотрение заявок, подведение итогов
- Флаг «закупка только для СМП/СОНО»
- Ссылка на критерии оценки заявок

### 2.2. ИКЗ — структура 36 разрядов

Критически важное поле для связки закупка↔план-график↔бюджет:

| Разряды | Смысл |
|---|---|
| 1–2 | Год закупки (последние 2 цифры) |
| 3–22 | Код заказчика (20-значный, по приказу Минфина №127н, отражает ГРБС/тип учреждения/уровень бюджета) |
| 23–26 | Номер закупки в плане закупок |
| 27–29 | Номер закупки в плане-графике |
| 30–33 | Код объекта закупки: класс (30–31) / подкласс (32) / группа (33), по ОКПД2/КТРУ; может быть `0000` для многопредметных закупок или отдельных случаев по ст. 93/83 |
| 34–36 | Код вида расходов (КВР, напр. 242, 244); `000` для БУ/АУ/унитарных предприятий или многовидового финансирования |

Источники: [new.oskolzakaz.ru](https://new.oskolzakaz.ru/2017/10/02/икз/), [garant.ru/news/1285495](https://www.garant.ru/news/1285495/).

**Для БД**: ИКЗ стоит хранить не только как строку, но и распарсенным на составные поля (год, код заказчика, номер в плане, номер в плане-графике, класс/подкласс/группа объекта, КВР) — это готовый естественный ключ для связи с планом-графиком и бюджетной классификацией.

### 2.3. Обеспечение заявки и контракта

| Параметр | Правило |
|---|---|
| Обеспечение заявки, НМЦК ≤ 20 млн ₽ | 0,5–1% от НМЦК |
| Обеспечение заявки, НМЦК > 20 млн ₽ | 0,5–5% от НМЦК |
| Обеспечение заявки, УИС/организации инвалидов (ч.2 ст.29) | 0,5% от НМЦК |
| Обеспечение заявки, гос./муниципальные учреждения | 0% (не устанавливается) |
| Обеспечение исполнения контракта, общий случай | 0,5–30% от НМЦК (для СМП/СОНКО — от цены контракта) |
| Правило по авансу | обеспечение ≥ размера аванса, если аванс > 30% НМЦК — обеспечение = размеру аванса |
| Антидемпинг (снижение цены ≥25% от НМЦК) | обеспечение ×1,5, но не менее 10% от НМЦК (альтернатива — подтверждение добросовестности при НМЦК ≤15 млн, коэффициент и добросовестность не совмещаются) |

Способы: денежные средства (спецсчёт) или независимая (банковская) гарантия — включается в реестр банковских гарантий (РБГ) ЕИС, без чего заказчик вправе её не принять. Отдельно фиксируется признак казначейского сопровождения (влияет на требования к обеспечению аванса).

Источники: ст. 44, 45, 96 44-ФЗ, ПП РФ №439; [intmag24.ru](https://intmag24.ru/kalkulyatory/kalkulyator-obespecheniya-44-fz/), [censovet.ru](https://censovet.ru/vs-rf-pozvolil-ukazyivat-razmer-obespecheniya-zayavok-i-kontrakta-v-protsentah-ot-nachalnoy-tsenyi/).

**Для БД, поля-кандидаты**: `bid_security_required`, `bid_security_percent` (или min/max), `performance_security_required`, `performance_security_percent`, `is_smp_only`, `anti_dumping_applied`, `has_advance`, `advance_percent`, `treasury_support`.

### 2.4. Преимущества участникам (ст. 28–29)

Важное уточнение — модель преимуществ для разных категорий участников принципиально разная, это не единая шкала:

| Категория | Механизм | Размер |
|---|---|---|
| Организации инвалидов, учреждения/предприятия УИС (ст. 28, 29) | Ценовое преимущество к предлагаемой цене | до 15%, но контракт не выше НМЦК; применяется только к объектам из перечня распоряжения Правительства РФ №3500-р |
| СМП / СОНКО | Не надбавка к цене, а спецрежим: обязательные закупки у СМП/СОНКО, лимиты НМЦК, льготное обеспечение | — |

Условие применения — декларация участника через оператора ЭТП; отсутствие указания преимущества в извещении = преимущество не применяется, даже если объект в перечне. Источники: [dzen.ru/a/YigIUn2iSWkbUvze](https://dzen.ru/a/YigIUn2iSWkbUvze), [garant.ru/products/ipo/prime/doc/71677592](https://www.garant.ru/products/ipo/prime/doc/71677592/).

### 2.5. Национальный режим (ст. 14 44-ФЗ)

С 01.01.2025 действует единое ПП РФ №1875 (заменило разрозненные №617, 878, 791 и др.). Три независимых механизма:

| Механизм | Приложение | Суть |
|---|---|---|
| Запрет | Приложение №1 | заявки с иностранным товаром из перечня отклоняются полностью |
| Ограничение («второй лишний») | Приложение №2 | при наличии хотя бы одной заявки с подтверждённым российским товаром — заявки с иностранным/неподтверждённым отклоняются |
| Преимущество | вне перечней 1/2 | понижающий коэффициент 0,85 к цене российского товара при оценке (контракт — по фактической цене); действует «правило 100% российского происхождения» по всему лоту |

Подтверждение происхождения — через реестры РРПП/ЕРПТ. **Для БД**: поле «национальный режим» должно быть не булевым флагом, а перечислением (`none` / `prohibition` / `restriction` / `preference`) плюс ссылка на конкретные позиции приложений ПП №1875 по коду ОКПД2. Источники: [tender-rus.ru](https://tender-rus.ru/baza_znaniy/nacionalnyj-rezhim-v-44-fz-i-223-fz), [litender.ru/nazrezhim](https://litender.ru/nazrezhim/).

## 3. Объект закупки, лоты, позиции: два разных уровня модели

Ключевой методологический вывод — **это не один уровень данных, а два связанных**:

1. **«Объект закупки»** — категорийное описание предмета (что покупают): наименование объекта, код каталога (класс/подкласс/группа ОКПД2, входит в ИКЗ 30–33 разряды), описание, ссылка на КТРУ либо свободное описание по ст. 33 (если позиции в каталоге нет).
2. **Структура лота / спецификация** — построчная детализация для расчёта НМЦК и заявок участников.

### 3.1. Строка спецификации (позиция)

| Поле | Источник |
|---|---|
| Код ОКПД2 | обязателен всегда |
| Код КТРУ | обязателен, если позиция есть в каталоге и наступила дата обязательности |
| Наименование ТРУ | из КТРУ, либо свободно по ст. 33 |
| Характеристики | из КТРУ (дословно) либо свободные |
| Количество / объём | число |
| Единица измерения | из КТРУ либо классификатора |
| Цена за единицу | расчётная |
| Сумма по позиции | количество × цена |

### 3.2. Характеристики КТРУ — типизация значений

Это тонкий момент, который стоит явно заложить в схему БД:

- **Тип характеристики**: качественная (текст/перечисление/булево) vs количественная (число + обязательная единица измерения).
- **Тип значения** количественной характеристики: минимальная граница / максимальная граница / диапазон (несколько вариантов интервалов) / конкретное значение.
- Заказчик обязан выбрать **ровно один** допустимый вариант из предложенных каталогом (нельзя оставить «диапазон значений» неконкретизированным — прямое требование из разъяснений Минфина).
- Единицу измерения количественной характеристики заказчик менять не может — она жёстко задана позицией КТРУ.

Источники: [bicotender.ru](https://www.bicotender.ru/article/ktru-v-edinoy-informacionnoy-sisteme-po-44-fz-v-2025-godu.html), [zakupki44fz.ru](https://zakupki44fz.ru/dokumentatsiya/6-1-1-opisanie-obekta-zakupki-v-strukturirovannom-vide/), [edu.lot-online.ru](https://edu.lot-online.ru/media/material/news/kazanie-kharakteristik-obekta-zakupki-pri-osushchestvlenii-zakupki-s-polki-pismo-minfina-rossii-ot-2/).

**Модель данных-кандидат для характеристики**: `name`, `type` (qualitative/quantitative), `unit` (nullable), `value_type` (min/max/range/exact/enum), `allowed_values` (JSON-массив), `selected_value` (что выбрал заказчик).

### 3.3. Лот vs аукцион/котировки

По действующей редакции 44-ФЗ лоты в открытых конкурсах/аукционах практически не используются (ограничены закрытыми/специальными процедурами), но само понятие «лот» как контейнер спецификации в модели ЕИС сохраняется и для запроса котировок (обычно один лот с набором позиций, итоговая цена заявки — по всей совокупности позиций). Источник: [fado-dpo.ru](https://fado-dpo.ru/articles/goszakupki-stati/chto-takoe-lot-i-po-kakim-pravilam-ego-formirovat-skolko-lotov-mozhet-byt-v-odnoy-zakupke/).

## 4. Протоколы (электронный аукцион, 44-ФЗ)

| Протокол | Кто формирует | Срок | Ключевые данные |
|---|---|---|---|
| Рассмотрения первых частей заявок | комиссия заказчика | ≤3 раб. дня (иногда 1 день) после окончания подачи заявок | id заявки → допущена/отклонена + основание со ссылкой на нормы |
| Проведения электронного аукциона | оператор ЭТП автоматически | ≤30 мин после окончания торгов | все ценовые предложения участников с timestamp |
| Рассмотрения вторых частей заявок | комиссия заказчика | ≤3 дня после получения от ЭТП | соответствие/несоответствие по топ-участникам |
| Подведения итогов | комиссия заказчика | ≤3 раб. дня после протокола аукциона, публикация не позднее следующего раб. дня | ранжирование, победитель, цена контракта |
| О признании несостоявшимся | комиссия заказчика | по факту (0/1 заявка или все отклонены) | основание, дальнейшие действия (единственный поставщик) |
| Согласования заключения контракта с единственным поставщиком (в т.ч. решения ФАС по жалобам) | ФАС / уполномоченный орган | — | обоснование выбора единственного поставщика |

Источники: [ppt.ru/art/zakupki/protokoly-elektronnogo-auktsiona](https://ppt.ru/art/zakupki/protokoly-elektronnogo-auktsiona), [cpp-group.ru](https://cpp-group.ru/baza-znaniy-smp/obrazcy-dokumentov/protokoly-elektronnogo-auktsiona-po-44-fz-obrazets/), [zakupki-kontur.ru](https://zakupki-kontur.ru/news/protokoly-aukciona-po-zakonu-44-fz/).

**Модель данных**: `Protocol` (тип, дата, статус) → `ProtocolBidDecision` (заявка → решение → основание) — хорошая событийная схема для дальнейшей аналитики отклонений и рисков жалоб.

## 5. Различия 44-ФЗ vs 223-ФЗ

| Аспект | 44-ФЗ | 223-ФЗ |
|---|---|---|
| Планирование | план закупок + план-график (жёсткая форма, публикация извещения возможна не ранее 10 дней после плана-графика) | план закупок (без плана-графика); отдельные планы для инновационной/высокотех. продукции и ЛС |
| Способы закупки | закрытый перечень, зафиксированный законом | определяются заказчиком в положении о закупке; ЕИС хранит справочники «способы закупки»/«шаблоны извещений»/«шаблоны протоколов» по каждой записи положения |
| НМЦК/обоснование | обязательные регламентированные поля обоснования (метод расчёта, источники цен) | обоснование определяется положением о закупке, форма произвольнее |
| Структура извещения | жёсткие типовые формы под способ закупки | шаблон извещения заказчика, но ЕИС требует базовые блоки (предмет, цена/диапазон, требования, критерии, условия договора) |
| Реестр договоров | реестр контрактов | реестр договоров (регистрация, доп. соглашения, исполнение, расторжение, субподрядчики) |
| Дополнительная сущность | — | Реестр положений о закупках (реестровый номер, статус, даты утверждения/вступления в силу, вкладки «Способы закупки», «Документы положения», «Изменения», «Журнал событий») |

Источники: [zakupki.mpei.ru/help/Pages/Planirovanie.aspx](https://zakupki.mpei.ru/help/Pages/Planirovanie.aspx), [zakupki-portal.ru](https://zakupki-portal.ru/poleznye-materialy/trenazher-raboty-s-eis/), [tenderguru.ru](https://www.tenderguru.ru/zakupki-gov-ru-eis/rukovodstvo-polzovatelya-oficialnyy-sayt/razdel-reestr-polozheniy-o-zakupkah-223-fz).

Точная URL/DOM-структура карточки 223-ФЗ **не подтверждена достоверно** в открытых источниках (в отличие от чёткой схемы 44-ФЗ) — рекомендуется отдельная эмпирическая разведка (несколько живых карточек через Playwright) перед проектированием таблиц.

## Рекомендации для ТЗ

1. **Разделить детальный слой на два связанных уровня сущностей**: `PurchaseObject` (категорийный уровень — ОКПД2/КТРУ/описание) и `LotSpecificationLine` (построчный уровень — количество/цена/характеристики). Не сливать их в одну таблицу.

2. **ИКЗ хранить и как строку, и распарсенным** на компоненты (год, код заказчика, номер плана, номер плана-графика, код объекта класс/подкласс/группа, КВР) — естественный ключ для связи с планом-графиком и бюджетом.
