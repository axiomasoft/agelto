# Аудит v1 → что переносить в v2

Проект: Laravel-парсер госзакупок ЕИС. Прочитан реальный код (Services, Process/*, Modules/Eis, Repositories, Models, Enums).

## ТОП-10 «классных идей» проекта

1. **`CrawlerRunManager`** (`app/Process/Crawling/Run/CrawlerRunManager.php`) — управление жизненным циклом прогона краулера через `plt_crawler_runs`: инвариант «один активный (running) прогон на профиль» (упирается в БД-исключение при гонке, не в приложение), heartbeat-детект зависшего прогона (`HEARTBEAT_STALE_MINUTES=15`), `recoverOrphan()`, экспоненциальный backoff `2^attempts` (капом 60 мин). Модель crash-safe возобновления обхода — переносить как есть.
2. **`CrawlCursor`** (`app/Process/Crawling/Cursor/CrawlCursor.php`) — явный сериализуемый курсор обхода (стек ценовых интервалов + день + страница) вместо рекурсии PHP-стека. Ключевая идея: state, который переживает краш процесса/воркера. Переносить как есть.
3. **Lease-паттерн против дублей в очереди** — `DocumentAnalysis::acquireLease()/releaseLease()` (атомарный `UPDATE ... WHERE locked_until IS NULL OR locked_until < now()`, `app/Models/DocumentAnalysis/DocumentAnalysis.php:180-208`) + идемпотентные guard'ы в начале `handle()` каждого Job'а (`PrepareDocumentJob`, `PrimaryAnalysisJob`, `EstimateAnalysisJob`) по терминальным статусам. Защита от дублирующих дорогих вызовов (Gemini) при ретраях/крашах воркера. Переносить как есть — это общий паттерн, не завязан на ЕИС.
4. **Chain статусов с логом + агрегация вверх по иерархии** — `transitionStatus()` пишет в `plt_document_analysis_log` и вызывает `Link::recomputeStatusFromAnalyses()` (агрегирует статус вложений в статус ссылки: PROCESSING/COMPLETED/FAILED). Даёт аудит-трейл «где именно упало» и живой статус верхнего уровня без отдельного джоба-синхронизатора. Переносить как есть.
5. **`recordFailure()` + granular failed-статусы + dead-letter** (`DocumentAnalysis.php:158-174`) — инкремент `attempts`, экспоненциальный backoff (`2^attempts`, потолок 240 мин), `failed_permanently` при исчерпании попыток. Тот же паттерн продублирован в `CrawlingRepository::markFailed()` для `Link`. Идея хороша, но код задублирован (модель дублирует репозиторий) — **переработать**: вынести общий trait/concern `HasFailureTracking` на оба места.
6. **Кэш контекста Gemini (`getContextCache`/`isCacheValid`)** (`GeminiService.php:106-155`, `DocumentAnalysis::isCacheValid()`) — файл грузится в Google File API один раз (`ensureFileInCloud`, по fingerprint `md5(name+size+mtime)`), детальный анализ переиспользует `cachedContent` по TTL с проверкой `rules_hash` (если поменялись промпт-правила — кэш инвалидируется). Реальная экономия токенов/денег на многошаговом анализе одного документа. Переносить как есть (это специфика Gemini File API/context caching, но сам паттерн kэш-инвалидации по fingerprint+rules_hash — универсален).
7. **`PromptRuleRepository::systemInstructionsFor()`** (`app/Repositories/Prompt/PromptRuleRepository.php`) — системная инструкция для LLM собирается из двух слоёв: правила из БД (`PromptRule`, редактируются оператором без деплоя) + статические файлы `Schema/*.php` конкретного `Process/*` (сначала обычные DTO-схемы, `Responses/*` — в конце). PHP-схема очищается от `<?php/namespace/use` через `PromptService::getCleanSchema()` и прямо скармливается модели как спецификация JSON-формата — не нужно дублировать схему в промпт руками. Не самое чистое решение (regex-парсинг PHP-файлов, hardcoded маппинг Step→папка через `ucfirst`), но идея «PHP DTO = единственный источник правды и для кода, и для промпта» ценная. **Переработать**: типизировать сборку (явный registry Step→SchemaClass вместо угадывания по имени папки), но паттерн оставить.
8. **Ценовое дробление интервалов при лимите выдачи** — `EisCrawlingService::priceSplitHook()` рекурсивно бинарно делит диапазон цены пополам, если результатов > `MAX_RESULTS=1000`, со страховкой от бесконечной рекурсии (`$diff < 10000` → забираем что дают). Универсальный приём для площадок с ограничением на глубину пагинации/выдачи. Переносить как идею (сам метод специфичен для ЕИС-разметки, но паттерн «дробить проблемное измерение бинарным поиском» переиспользуем).
9. **Двухуровневый резюм обхода: день (архивный режим) + курсор пагинации внутри дня** — `EisCrawlingService::archiveCrawl()/resumeDay()/rememberDay()`, фиксация `day_from/day_to` и в `plt_crawler_runs`, и (legacy) в `Crawler.state`. Прошедшие дни стабильны → возобновление с несомкнутого дня дёшево и корректно, в отличие от «оперативного» режима (без даты), где курсор всегда сбрасывается (`resetCursor`), т.к. сортировка по updated_at «съезжает». Явное разделение стратегий возобновления по природе данных — ценная архитектурная идея, переносить как есть.
10. **`storeOrUpdateLink()` с guard «изменились ли данные»** (`CrawlingRepository.php:23-66`) — статус/`attempts`/backoff сбрасываются в PENDING только если `platform_updated_at` реально изменился; иначе повторный обход площадки не затирает накопленный прогресс ретраев уже обрабатываемой ссылки. Плюс `syncAttachments()` удаляет только вложения без начатого `DocumentAnalysis` (не осиротить запущенный анализ). Тонкий, но важный инвариант для идемпотентности конвейера. Переносить как есть.

### `app/Process/*`

- **`AbstractCrawlingService`** — темплейт-метод для стадии 1: `start()` оборачивает весь прогон в try/finally с гарантированным `browser->close()` и очисткой logger-контекста, делегирует конкретной площадке только `getNodes/crawlingItem/getPageMeta/getCrawlerUrl/parseAttachments`. `pageProcessing()` содержит важный инвариант: вложения парсятся заново только если `platform_updated_at` реально изменился (иначе используются уже сохранённые) — экономия дорогих запросов к площадке. **Переносить как есть**, это чистый Template Method, специфика площадки полностью инкапсулирована в наследнике.
- **`DocumentProcessor`** (`DocumentPrepare/DocumentProcessor.php`) — стратегии подготовки документа (`ArchiveStrategy` — распаковка zip с идемпотентным `firstOrCreate` дочерних `DocumentAnalysis` по `(parent_id, name)`, `ExcelStrategy`) через `PreparationStrategy` интерфейс, конфигурируемый список в `config('platform.document_prepare.strategies')`. Есть мёртвые/неиспользуемые приватные методы `findExistingByUrl/findExistingByMedia/findExistingByFileSignature` (нигде не вызываются в `run()`) — при переносе почистить. **Переносить архитектуру Strategy как есть**, вычистить dead code.
- **`PipelineDispatcher`** — явный класс-мост между стадией 1 (Crawling) и стадией 2 (DocumentPrepare): опрашивает PENDING-ссылки, диспатчит `PrimaryAnalysisProcessor::run()` на каждое непроанализированное вложение, переводит ссылку в PROCESSING. Комментарий в коде явно называет это «C1» фиксом отсутствовавшего моста — то есть решение выстрадано на реальном инциденте рассинхрона стадий. **Переносить как есть**, важный архитектурный шов.
- **Jobs (`PrepareDocumentJob`/`PrimaryAnalysisJob`/`EstimateAnalysisJob`)** — единообразный шаблон: guard по терминальному статусу → `acquireLease()` → `try/finally releaseLease()` → в `failed()` — `recordFailure()` + `PipelineAlert::failure()` (уведомление оператору с указанием стадии/джобы/попытки). Согласованный `tries/timeout/backoff` per-очередь (`platform_primary_analysis`, `platform_estimate_analysis`, `platform_document_prepare`), `tags()` для видимости в Horizon. **Переносить как есть** — образцовый шаблон idempotent-джобы для queued LLM-пайплайна.
- **EstimateAnalysis Schema/*** (много DTO: `EstimateHeader`, `EstimateItem`, `EstimateSection`, `EstimatePassport`, `EstimateResourceType` и т.д.) — структурированная типизация домена сметы под structured-output LLM. Ценно как словарь предметной области стройсметы. **Переносить, но пересмотреть** — `EstimateAnalysisProcessor.run()` сейчас явно недоделан (`// ... твой код запросов ...`, комментарий-заглушка, нет реального цикла пагинации по чанкам) — это скелет, не рабочая реализация; в v2 писать логику заново, схемы Data-классов забрать.

### `Modules/Eis/app/*`

- `EisCrawlingService` описан нейтрально в п.6/8/9 выше — ценность в **паттернах возобновления и дробления**, а не в CSS-селекторах/DOM-структуре площадки (это специфика конкретного сайта и будет меняться). При переносе в v2 — переносить архитектуру (курсор, price-split, archive-vs-realtime режимы), верстку-парсинг переписывать под текущую разметку целевой площадки.
- Флаг `isSplitProcess` для предотвращения рекурсивного повторного входа в `startHook()` при вызове `crawlingPage()` изнутри `processAllIntervalPages()` — простое, но грязноватое решение через mutable-флаг на инстансе сервиса. **Переработать**: сервис создаётся per-run, но флаг-стейт на shared-объекте — источник трудноуловимых багов, если сервис когда-нибудь станет reused/pooled. Явный параметр или отдельный внутренний Runner-объект был бы чище.

### `Repositories`, `Models`, `Enums`

- **`AnalysisStatus`** — модельный enum с `stage()` (маппинг статуса на `PipelineStage` для retry-с-нужной-точки), `isTerminal()/isFailed()/isInProgress()/isAwaiting()` — классификация статусов вместо разбросанных `in_array` по коду. **Переносить как есть**, канон для доменных статус-enum'ов.
- **`CrawlerRunStatus`** — аналогично, `isActive()/isTerminal()` + Filament `HasColor/HasLabel`. **Переносить как есть.**
- **`Link::recomputeStatusFromAnalyses()`** — агрегация «снизу вверх» описана в п.4. Единственное сомнение: делает отдельный SQL-запрос на каждый вызов `transitionStatus()` дочернего `DocumentAnalysis` (N+1 при массовой обработке пачки вложений одной ссылки) — **переработать**: батчить/дебounced-пересчёт, если объёмы вырастут.
- **`CrawlingRepository`** — методы именованы по канону (`findLink`, `findCrawler`, `getPendingLinks`, `storeOrUpdateLink`), чёткое разделение read/store. **Переносить как есть**, хороший образец репозитория по гайдлайнам проекта.
- **`PromptRuleRepository`** — см. п.7, ценная идея, требует переработки сборки схем (сейчас завязана на угадывание пути папки по имени Step через `ucfirst(explode('_', ...))`, хрупко при рефакторинге неймингов).

## Что явно НЕ переносить

- **`SmetaParserService`** целиком — dead code, дублирует функциональность `EstimateAnalysisProcessor`+Gemini File API более грубым способом (голый Guzzle, hardcoded API key в query string, `verify: false` в HTTP-клиенте).
- Закомментированный блок кода в `AbstractCrawlingService::pageProcessing()` (строки 235-243, альтернативная реализация через `$link->attachments`) — мёртвый закомментированный код, убрать.
- Неиспользуемые приватные методы `DocumentProcessor::findExistingByUrl/findExistingByMedia/findExistingByFileSignature` — не вызываются, вычистить.
- Заглушка-скелет `EstimateAnalysisProcessor::run()` (комментарии `// твой код запросов`) — не рабочая логика пагинации извлечения позиций сметы, писать с нуля в v2.
- Хардкод `--single-process` и полное отключение изображений/шрифтов в `BrowserService` флагах Chromium — специфично для текущего окружения, пересмотреть при переносе под ресурсы v2-инфраструктуры.
