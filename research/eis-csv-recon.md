# Разведка CSV-экспорта ЕИС (живая, 2026-07-03)

Снято вживую через Playwright (прокси) на `zakupki.gov.ru`, реестр закупок (`/epz/order/extendedsearch/results.html`). Все факты ниже — проверены запросами, не из статей.

## Механика выгрузки

1. Кнопка «Выгрузить результаты поиска» на листинге: `onclick="downloadCsv('<query-строка текущего поиска>', '<totalCount>')"`.
2. `downloadCsv()` кладёт критерии в `localStorage['criteria_csv_url' + reestr]` и открывает модалку `GET /epz/order/orderCsvSettings/loadSettings.html?totalCount=N`.
3. Модалка «Выгрузка данных», два шага:
   - **Шаг 1 — выбор параметров**: дерево групп колонок (Закупки, ИКЗ, Лот, Цена, Справочники, Заказчик, Дата, Особенности размещения/Преимущества 44-ФЗ). Пресеты параметров можно сохранять (до 10, серверные).
   - **Шаг 2 — выбор записей**: «Для выгрузки доступно не более 5000 записей», диапазоны по 500 («с 1 по 500» … «с 4501 по 5000»), у каждого кнопка «Выгрузить».
4. Сама выгрузка — **GET** (не POST):

```
GET /epz/order/orderCsvSettings/download.html
  ?<все параметры поиска как у results.html>   // morphology, fz44/fz223, sortBy, sortDirection, publishDateFrom/To, priceFromGeneral/To, ...
  &from=1&to=500                                // диапазон записей
  &<флаг колонки>Csv=true ...                   // какие колонки включить
```

## Проверенное поведение сервера

| Проверка | Результат |
|---|---|
| Без cookies/сессии (`credentials: omit`) | **200, работает** — сессия не нужна, чистый HTTP-GET достаточен (через RU-прокси; напрямую с хоста ЕИС не отвечает) |
| `from=1&to=50` и `from=1&to=1000` / `to=3000` | Всегда ровно **500 строк**: `from` округляется к границе блока 500, `to` фактически игнорируется |
| `from=5001&to=5500` | 200, отдаёт реальный блок глубже UI-лимита 5000 |
| `from=9501` / `from=10001` / `from=14501` / `from=20001` / `from=100001` | Все отдают **один и тот же блок** → жёсткий cap глубины ≈ **10 000 строк**; за пределом сервер **тихо** возвращает последний блок (без ошибки!) |
| `fz223=on`, те же флаги колонок | 200, работает тем же endpoint'ом, реестровые номера 223-ФЗ (№326…) |
| Сдвиг данных | При `sortBy=UPDATE_DATE` содержимое блоков «съезжает» между запросами (живой поток обновлений) — блоки одного скана надо снимать быстро и дедупить по `reg_number` |

Итог по лимитам: UI говорит 5000, фактический потолок ~10 000, но **полагаться на глубину > 5000 нельзя** (недокументировано), а выход за cap не детектируется по статусу — только по совпадению содержимого с предыдущим блоком.

## Формат CSV

- Имя: `OrderSearch(1-500)_03.07.2026.csv` (реестр закупок; для контрактов — ContractSearch).
- `Content-Type: application/download;charset=windows-1251`, `Content-Disposition: attachment`.
- Кодировка **Windows-1251**, разделитель `;`, значения с кавычками, внутренние кавычки удваиваются (`""`), заголовок на русском.
- Колонки присутствуют только те, чьи флаги переданы; порядок фиксированный.

## Этапы закупки (фильтр листинга, основа статусной модели)

Фильтр «Этап закупки»: Подача заявок → Работа комиссии → Закупка завершена / Закупка отменена. В выдаче встречались также «Определение поставщика завершено», «Определение поставщика отменено» (детальные статусы карточки богаче фильтра).

## Следствия для дизайна краулера (в ТЗ)

1. **CSV-метод реализуем чистым HTTP-клиентом** (Guzzle/Laravel Http) через RU-прокси, браузер не нужен вообще. UA/Referer — желательны, сессия — нет.
2. Один скан = серия GET по блокам `from=1,501,1001…` до 5000 (консервативно), дедуп по `reg_number`, детект «повторного блока» (сравнение первого reg_number с предыдущим блоком) как стоп-сигнал cap'а.
3. **Свежий поток** (каждые ~30 мин): `sortBy=UPDATE_DATE, sortDirection=false`, читать блоки до первого полностью «уже виденного» блока. За 30 минут обновлений заведомо меньше 5000 — слепых зон нет.
4. **Архив**: `publishDateFrom=publishDateTo=<день>` + при >5000 в дне — дробление по ценовым диапазонам (`priceFromGeneral/priceToGeneral`), как текущий `priceSplitHook`, но целимся в ≤5000 на выборку и качаем CSV вместо HTML-страниц.
5. Сортировка живая → внутри одного скана блоки снимать подряд без пауз в минуты; дедуп обязателен.
6. Rate limits агрессивно не проверялись (≈15 запросов подряд прошли без блока); в ТЗ — консервативный лимитер + мониторинг.
7. Один и тот же endpoint обслуживает 44-ФЗ и 223-ФЗ (`fz44=on` / `fz223=on`), набор колонок общий.

## Бонус: страница вложений — SSR, браузер не нужен

`GET /epz/order/notice/ea20/view/documents.html?regNumber=…` без cookies → 200, 135KB HTML, ссылки на файлы (`filestore/public/1.0/download/priz/file.html?uid=…`) присутствуют в сыром HTML. **HTTP-first для деталей/вложений подтверждён живьём**; Playwright — только fallback (и для площадок с JS-рендером).

## Не проверено (отнести к рискам)

- Реальные пороги rate-limit / бан по IP при массовой перекачке архива.
- Стабильность списка флагов колонок между релизами ЕИС (версия на момент разведки: hotfix/16.2.1.25 от 02.07.2026).
- Точное значение cap (9,5–10 тыс.); может меняться.
